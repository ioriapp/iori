# Files View

読むのは、Workspaceのファイル一覧、本文・画像の表示、検索、読み位置、Agentへの参照を変える時である。
製品全体の価値は[製品仕様](../product.md)、Gitの変更と履歴は[Git View](git-view.md)、会話の入力は[CLIの画面](cli-screen.md)、安全境界は[技術設計](../architecture.md)が持つ。

## ユーザーの目的

Workspaceの構成を把握し、Agentが触ったファイル、仕様書と実装、ログやPlaywright等の画像証跡を読む。見つけたファイルや行を、同じWorkspaceのAgentへ次の質問・指示の参照として渡す。

Files Viewはファイルの中身を編集しない。直接編集、未保存状態、undo、補完は持たない。変更はAgentへ依頼し、結果をFilesまたはGit Viewで確認する。外からファイルをアップロードすることと、Hostのファイルを手元へダウンロードすることだけはできる（[アップロード・ダウンロード](#アップロードダウンロード)）。

## 画面の構成

ファイルのタブと同じ行の一覧上端にworktreeの切替を置く。候補は、そのリポジトリの元の作業ツリーと、表示中の親とその子のworktreeとし、ブランチ名で選べる。元の作業ツリーは先頭に置き、ほかの候補と区切り線で分ける。別のリポジトリの子のworktreeは「〈リポジトリ名〉 › 〈ブランチ名〉」と表示する。切替はそのタブの表示対象だけを替え、サイドバーで選択中のワークスペース、ほかのタブ、本体の配置は変えない。表示対象もタブの配置とともに保存・復元する。全幅の帯は使わず、切替と一覧の間に罫線を引かず余白で分ける。対象を替えたら一覧と本文を同じworktreeに揃え、別の対象の読み位置や参照を混ぜない。

### Desktop

十分な幅では、左に一覧、右に選択した内容を並べる。一覧は初期値としてViewのおよそ4分の1を使い、仕切りをドラッグまたはキーボードで動かせる。ユーザーが決めた比率と一覧の開閉は、そのViewの配置として保存する。固定pixel値を製品仕様にせず、ファイル名と本文の双方を読める最小幅を下回る時は狭い表示へ切り替える。

### 狭いViewとMobile

一覧と内容を無理に横へ並べず、一方を全体に表示する。最初は一覧を表示し、ファイルを選ぶと内容へ進む。画面内の戻る操作とAndroidの戻る操作は、どちらも同じ一覧と同じ選択位置へ戻す。

現在のpath、一覧へ戻る操作は内容側でも失わない。幅変更や回転で選択、展開、検索、読み位置を初期化しない。横scrollを画面全体の移動手段にせず、長いコード行の内部だけに限定する。

## ファイルを探す

一覧はRootを起点にし、Root外へ表示範囲を広げない。directoryは開閉でき、開いた場所だけを読み込む。項目数が多くても内部の件数上限でdirectory全体を拒否せず、scrollに合わせて続きが自動で届く。転送単位の都合で「さらに読み込む」を押させない。

ファイル名の入力で、現在のWorkspace内のpathを絞り込める。Gitリポジトリでは`.gitignore`で除外したものを候補に出さない（VS Codeと同じ）。絞り込み結果はpathを見分けられる形で表示し、Root外や未取得対象を候補として作らない。

一覧の通常操作は次の通りとする。

- ファイルを選ぶと内容のタブで開く。タブの右クリック（スマホは長押し）のメニューは「閉じる」「その他を閉じる」「右側を閉じる」「左側を閉じる」「すべて閉じる」、区切って「パスをコピー」「ダウンロード…」（VS Codeのタブのメニューと同じ言葉と順序。「左側を閉じる」はVS Codeではコマンドだけにある）。閉じる相手のタブが無い項目は押せない。選んでいたタブが閉じたら右クリックしたタブを選び、すべて閉じたら一覧へ戻る。本体のタブ（CLI・Terminal）は閉じた結果がタブごとに違うので、まとめて閉じる操作を持たない。
- 一覧はフォルダーを先に、名前の順に並べる（VS Codeと同じ）。
- directoryの開閉とfileの選択を別の操作として扱い、開閉用のアイコンを固定した位置に置く。
- Desktopの矢印キーで前後移動、directoryの開閉、親子移動ができる。文字入力はファイル名の絞り込みへ使える。
- touchでは行全体を選択対象にし、開閉、scroll、文字選択を衝突させない。
- symlinkはsymlinkと分かり、許可されたRoot内の対象だけを開ける。Root外、参照不能、種類不明を同じ失敗へまとめない。

## 内容を読む

### Text

textは行番号と本文を表示し、見える行とその周辺だけを描画する。行の折返しは切り替えられ、codeは折返しなし、文章中心の形式は折返しありが初期状態でもよい。折返しにより長いfileのscrollが著しく悪化する場合は、理由を内部上限の文言で説明せず、安全な表示へ縮退する。

本文内検索はCtrl+F（とメニュー）で本文の右上に重ねて開き、前後の一致へ移動できる。行への移動はCtrl+G（とメニュー）で開く。本文の上に操作の行を常に並べない（VS Codeと同じ）。検索、行への移動、copy、文字選択を利用できる。

本文はUTF-8として読み込む。UTF-8として正しくないbyteは「�」に置き換えて表示し、そのbyteのためにfile全体を表示できないfileにしない。先頭付近にNULがあるfileだけをbinaryとする（VS Codeと同じ）。UTF-8のBOMは本文の文字として表示せず、CRLFを余分な空行にしない。改行を含まない巨大な一行を内部で分割して取得しても、別の行や途中までの全文として見せず、同じ論理行として検索・copy・参照できる。

本文はドラッグとダブルクリックで文字を選び、Ctrl+Cと右クリックのメニューの「コピー」でコピーする（VS Codeと同じ）。選んだまま見えている範囲の外へスクロールしても選択を失わず、選んだ始まりから終わりまでの本文を、描画していない行も含めて正しくコピーする。行範囲は行番号のクリックとShift+クリック、矢印とShiftで選び、Ctrl+Cと右クリックの「選択行をコピー」でコピーする。文字を選び始めたら行範囲の選択を解除し、行番号で選んだら文字の選択を解除する。スマホでは本文の長押しでOSの文字選択（つまみとOSの「コピー」）を使い、行番号のタップで行を選ぶ。本文の長押しではioriのメニューを開かず、行番号の長押しで本文の右クリックと同じメニュー（行へ移動・選択行をコピー・パスをコピー・行番号付きのパスをコピーなど）を開く。コピーに失敗した時は、その操作の近くで知らせる。

syntax highlightは内容を読む補助であり、全文到達、scroll、選択、copy、検索より優先しない。本文は色を待たずに表示し、色分けが届いた行から色を付ける。

- 言語は拡張子、ファイル名（`Dockerfile`など）、先頭の`#!`の行で決める。決まらない時は中身から推測せずplain textで表示する（VS Codeと同じ）。言語を手で選ぶ操作は持たない。
- 色分けはHostがファイル全体を先頭から読み込んで行う（VS Codeと同じTextMateの文法。Shiki）。Clientは見える範囲しか持たず、複数行のコメントや文字列の途中から正しく色分けできないため。外部変更では新しい内容で色分けし直す。
- 2万字を超える行はその行だけ、20MBか30万行を超えるfileは全体を色分けしない（VS Codeの`editor.maxTokenizationLineLength`と大きいfileの扱いと同じ値）。改行を含まない巨大な一行として分けて読む行も色分けしない。
- 色はライト・ダークのテーマのトークンで決め、テーマを替えても取り直さない。
- 対象はFilesの本文（「ファイル」のタブ、Markdownの原文を含む）。Markdownの描画した表示のコードブロックとGitの差分は含めない。

### Markdown

Markdownは描画した表示で開き、原文へ切り替えられる。仕様書を読みながら実装と行き来できるよう、切替でpath、検索語、原文側の読み位置を失わない。描画したMarkdownからscriptを実行せず、外部リンクは明示操作でデバイスの標準アプリへ開く。HTMLのコメント（`<!-- -->`）は、GitHub・Forgejoと同じく表示しない。`<details>`と`<summary>`はタグを出さずに中身の文字を残し、summaryの文字は普通の段落にする。相対リンクと相対画像は、表示中のファイルの場所を基準にWorkspace内の対象へ開ける。外部画像は自動取得しない。同じ文書内の目次リンクは見出しへ移動し、画面外の見出しも必要な範囲を読み込む。描画した表示はペインの横幅いっぱいを使い、最大化すれば最大化した幅で描く。それでも入らない広い表とコードの長い行は切らずに、その表・コードの中で横にスクロールして読め、本文全体は横にスクロールさせない。入りきらない表・コードは、続きがある側の端に影を出す。コードは1段の面で表示する。

### 画像

対応する画像は画面内へ収めて表示し、拡大・縮小、等倍、画像全体へ戻る操作を提供する。拡大時のpanとView全体のscrollを混同しない。file名、種類、pixel寸法、byte数を必要な範囲で確認できる。SVGを含め、Workspace内の画像をcodeとして実行しない。

画像以外のbinaryや未対応形式は、空のfileや読取失敗に見せず、種類・大きさと「この形式は表示できない」ことを表示する。hex editorや外部app起動は初期範囲に含めない。

## 大きい対象と資源

file本文、directory項目、行数にiori独自の製品上の総量上限を設けない。ユーザーは先頭だけで打ち切られず、scroll、検索、行移動により取得可能な末尾へ到達できる。

必要な範囲を読み進めるたびに自動で取得し、一度に取得する量の都合を本文の上限として画面へ出さない。選択変更、View close、Workspace切替では不要になった取得を止める。

取得中は内容を閲覧できる状態を保ち、必要な場所に控えめな進行表示を置く。正常な継続取得に操作を要求しない。通信・file変更・権限等で読取が失敗し、回復操作がある時は、対象のそば一か所に失敗と再取得または現在内容への更新を表示する。読み込めない範囲を未取得の表示で埋めない。

## Agentへの参照

CLI自身の画面とTerminalへは、ファイルをその画面かタブへドラッグしてパスを入力する（Enterは送らない）。パスは、シェルが知らせた作業ディレクトリの中なら相対、それ以外はHostの絶対パスで書き、シェルに合わせて引用する。スマホではドラッグしない。一覧と本文の右クリック（スマホは一覧・タブ・行番号の長押し）で「パスをコピー」「行番号付きのパスをコピー」を使える。

## アップロード・ダウンロード

AgentへHostにないファイル（仕様書、画像、ログ）を渡すため、また結果のファイルを手元で使うため、PC・スマホとHostの間でファイルを受け渡す。VS Code RemoteのExplorer・JetBrains Gateway・Termius・MobaXtermのSFTPと同じ操作にする。

- PCでは、エクスプローラーなどから一覧のフォルダーの行へファイルをドロップすると、そのフォルダーに置く。ファイルの行へ落とすとそのファイルのフォルダー、一覧の空いた所へ落とすとRootに置く。ドラッグ中は置き先のフォルダーの行を目立たせる。フォルダーごとのドロップは初期範囲に含めず、ファイルだけを置けることを表示する。
- 一覧のフォルダーの右クリック（スマホは長押し）のメニューの「ファイルをアップロード…」（アップロードのアイコン付き）で、OSのファイル選択から選んでも置ける。スマホ（AndroidのClient）はこの操作で置く。
- 同じ名前のファイルがある時は、置く前に名前を並べて「置き換える」か「キャンセル」かを聞く。フォルダー・symlinkと同じ名前の時は置かず、理由を表示する。置き先はRootの中だけにし、Root外へ逃げるパスは拒む。
- アップロードの間は、ファイルの名前・大きさ・進み具合と「キャンセル」を一覧の下に表示する。途中で止めた・失敗した時は、作りかけのファイルを残さず、前からあったファイルも壊さない。大きさに製品の上限は設けない。Relayを通る時も同じに扱う（公式のRelayを出す時に、Relayを通る転送の扱いを決め直す）。
- アップロード・ダウンロードの間に別のworktreeやViewへ移っても転送を続け、戻ると進み具合が見える。止めるのは「キャンセル」を押した時だけにする。
- ダウンロードの間も、アップロードと同じく名前・大きさ・進み具合と「キャンセル」を一覧の下（一覧の無い「ファイル」のタブでは本文の下）に表示する。
- 一覧のファイルの右クリック（スマホは長押し）のメニューと、ファイルのタブのメニューの「ダウンロード…」（ダウンロードのアイコン付き）で、OSの保存先の選択を開いて手元に保存する。Filesから外へのドラッグは初期範囲に含めない（ドラッグを始める前に全体を手元へ取る必要があり、大きいファイルに向かないため）。

## パスから開く

CLIの画面とTerminalの出力のパスのリンク（[Terminal](terminal.md#読む続ける)）を押すと、そのファイルを開く。

- そのタブが属する親とその子のworktreeの中のファイルは、同じ配置のFilesのタブで開く。Filesのタブが無ければ足し、worktreeの切替をそのファイルのworktreeへ合わせ、一覧でそのファイルを選び、行があればその行へ移って選ぶ。
- それ以外のファイル（別のリポジトリ、`~/.codex/config.toml` など）は、Filesの一覧に載せず「ファイル」のタブで開く。同じ配置に同じファイルのタブがあればそこへ移る。

### ファイルのタブ

1つのファイルだけを読むタブ。タブの名前はファイル名で、ツールチップで全体のパスを読める。本文の上に1行だけ、全体のパス（ホームの下は `~/…`）を小さく薄く表示する。本文の表示・検索・行への移動・コピー・行の選択・Agentへの参照・外部変更への追従はFilesの内容と同じで、一覧とworktreeの切替は持たない。中身は編集しない。Markdownの相対リンクと相対画像はそのファイルの場所を基準に開き、開いたリンク先も「ファイル」のタブで開く。タブは配置とともに保存・復元する。ファイルが消えた時は、本文の所に「ファイルが見つかりません」と「再読み込み」を表示する。

## 状態、更新、復帰

表示中のファイルは外部変更へ自動追従する。ユーザーが更新操作や開き直しをしなくても現在内容を確認できる。

空file、未選択、directory、読取中、取得済み、file変更、削除、binary、未対応形式、認可外を区別する。開いているfileが消えた時は、一覧のあるFilesでも「ファイル」のタブと同じく、本文の所に「ファイルが見つかりません」と「再読み込み」を表示し、古い本文を今の内容として見せない。最後に確認した本文がある時は一時失敗で削除せず、回復操作がある失敗だけを対象のそばへ表示する。別Host、別Workspace、同じpathに作り直された別fileの内容を混ぜない。

fileごとに選択、scroll位置、検索語と一致位置を保持し、View切替、tab移動、再接続、Client再起動から戻れるようにする。会話やfileを多く開いても、古い読み位置を件数だけで削除しない。全file本文の永続offline cacheを作ることとは区別し、最後に表示した内容を現在内容と誤認させない。

## キーボードとタッチ

focusは一覧、内容を順に移動できる。状態を色だけで表さない。touch targetを文字の大きさだけにせず、OSの文字倍率でも操作を重ねない。

## 受け入れ条件

- 項目の多いdirectoryでも、拒否や手動ページ送りなしに末尾の項目を選べる。
- 大きいUTF-8 fileでも、内部byte値や「さらに読み込む」を見ずに末尾を読み、検索・copy・行選択できる。
- 長いfileでDOM node数が総行数に比例せず、WindowsとAndroidでscroll中に通常操作を妨げる停止がない。
- Markdownの原文と描画結果、Playwright等のPNG画像、空file、binary、失敗を取り違えない。
- Root外symlinkを開かず、許可されたsymlink、通常file、参照不能を区別する。
