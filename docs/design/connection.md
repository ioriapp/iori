# 接続

ユーザーが登録済みHostを選ぶと、その登録情報で接続する。デバイス名や導入先の一致から同一Hostだと推測しない。複数のHostを同時に開き、Hostを意識せず切り替えられる。接続済み、再接続中、未接続（手動で接続）を区別し、表示の言葉は[画面の言葉](visual-style.md#画面の言葉)に従う。

PCではウィンドウが隠れていても、Androidでは前面または「バックグラウンドで接続を維持」がオンの間、切断直後は短い間隔で自動再接続を試し、間隔を延ばしながら約10秒を上限に、回数の上限なく続ける。PCのwindowがfocusを得た時とAndroidで前面へ戻った時は、選択中かどうかに関わらず全ての登録済みHostへ待たずに試す。切断時の表示は[Hostとの接続が切れた時の表示](host-recovery.md)に従う。接続が戻っても画面を取り直さない。手動の「再接続」は残す。

設定のHostの「接続」から、接続中・切断中・撤去に失敗したHostも「一覧から削除」で削除できる。確認は1回で、このClientの一覧と接続の情報だけを削除すること、Host側のデバイスの登録・データ・プログラムは変えないこと、また使う時は招待から再接続することを表示する。DesktopとMobileで同じ操作を使う。

接続はLANまたはVPN経由で行い、Relayを設定したHostへは届かない時だけRelayを通す（[Relay](relay.md)）。

「バックグラウンドで接続を維持」は既定オフ。通知を初めてオンにする時に、アプリを閉じていても受け取るにはこの設定が必要なことを表示し、一緒にオンにするかを聞く。オンにするとAndroidの背面でもLAN/VPN越しの接続を保ち、判断待ちを知らせる。常駐通知を1本表示し、電池を使う。オフの場合や通知を拒否した場合は、前面へ戻って未回答の判断を確認する。未接続中は新しい判断通知を出さない。

登録済みデバイスから「新しいデバイスを招待する」を選ぶと、招待をQRまたは文字列で表示する。期限切れと別の発行による無効を表示し、「新しい招待を発行する」で発行し直せる。招待は10分間、一回だけ使える。新しく発行すると、それまでの招待は使えなくなる。追加するデバイスは招待を読み取り、接続先とデバイス名を確認して「登録する」を押す。カメラを拒否した時や読み取れない時は文字列を貼り付ける。失敗時は入力と結果を保持して再試行できる。期限切れや使用済みの招待は再発行する。招待を出した画面は、登録されたデバイス名と「解除」を表示する。他のデバイスでは、デバイス一覧で新しく登録されたデバイスに印を付ける。印は一覧を表示し始めた時の既読集合で決め、表示時点の一覧を既読として保存する。このデバイスが登録された時点の一覧も既読にする。

CLIの承認・質問待ちは、1秒続いた時だけAttention・サイドバー・Board・タブの状態の印とOS通知へ出す。1秒より前に作業中・完了などへ変わった待ちは出さない。待ちの内容が変わっても待ち始めからの1秒は延ばさず、表示する時の最新の内容を使う。

判断待ちと完了は、Hostと接続中にAndroidのOS通知、Windowsのトーストで知らせる。判断待ちも完了も、その画面を前面のClientで見ている間は知らせない。設定の「通知」でそれぞれ切れる（既定はどちらもオン）。同じCLIの通知は最新の状態で置き換え、別のCLIの通知は残す。ただし、同じ会話（CLIの画面・チームの子）が承認・質問待ちのまま内容だけ次の承認・質問へ変わっても、音・振動・新しいOS通知を出さず、最初の通知を残す。Attention・Board・サイドバーは最新の内容を表示する。待ちが解けて作業中・完了などになった後、再び待ちになった時は通知する。

既読の記録が無いデバイスで最初に受け取る一覧は、新しい通知を出さずに既読とする。通知を押すとClientを前面へ戻し、対象の判断・画面へ移って入力できる。使える候補が無い委譲も判断待ちの通知設定に従い、その委譲ごとに一度だけ知らせ、押すと対象のチームの編集画面へ移る。そのチームの編集画面を前面で見ている間は知らせない。Windowsでは通知センターの履歴から後で押した場合も、Clientが終了していた場合も対象CLIへ戻る。まずウィンドウを表示し、対象が見つかればその画面へ移る。対象が無い時は今の画面を保つ。Hostへ届かない時もウィンドウは表示し、接続後に対象へ移る。URLの値の形を確かめ、登録済みHostの既存Terminal、または候補なし通知が指す既存チームの編集画面だけを開く。中継は使わない。WindowsのClientはウィンドウを×で閉じても通知領域に残って通知を受け続け、終了は通知領域のメニューから行う。設定の「一般」で「ウィンドウを閉じたら終了する」に変えられる。

招待はHost名と接続先を確認してから使い、QRの読取だけでは登録しない。招待の取消や期限切れ、読取・接続の失敗で既存の登録・下書き・配置を失わせない。

HostをClientから導入しない場合は、Hostのマシンで、Hostを動かすユーザーが`iori-host invite`を実行する。QRと文字列をTerminalへ表示し、登録されるまで待って、登録されたデバイス名を表示する。Ctrl+Cで待つのをやめても、招待は期限まで使える。登録済みデバイスまたはHostからデバイスを追加でき、招待した側の再承認は求めない。

Hostのアドレスが変わった時は、接続中にHostが今のアドレスを知らせ、Clientが接続先へ追加する。ユーザーが入力した接続先と現在接続している接続先は保持する。届かない時は、設定の「接続」で接続先（IPアドレスか名前）を直せる。

Androidのカメラ許可は読取を選んだ時に求める。カメラ画像は保存・送信しない。招待を出した画面とデバイス一覧から登録を取り消せる。Hostの鍵が変わった時は、設定の「iori Hostを追加する」から「招待で接続する」で新Hostとして明示的に登録し直す。確定したら新しいHostを選び、開き直しても選んだHostへ接続する。名前やIPの一致を信頼の根拠にしない。

通知の題は「リポジトリ / worktree - CLI 状態」。片方の名前だけがある時はその名前だけを出す。状態は承認待ち・入力待ち・完了・失敗。本文は承認・入力待ちなら対象の要約、完了・失敗ならCLIのhookから取った最後の応答の先頭を表示する。応答が取れないCLIは題名を使う。Orcaと同じく本文は180文字までのプレビューとし、空白と改行を整える。
