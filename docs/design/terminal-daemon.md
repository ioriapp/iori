# Hostの再起動・更新をまたいでTerminalを続ける

> Status: 採用済みの製品仕様。

読むのは、TerminalとCLIの画面（PTY）を持つプロセス、Hostの再起動・更新でのTerminalの扱い、CLIのhooks・`iori` コマンドの受け口を変える時である。

## ユーザーの目的

Hostを再起動・更新しても、作業中のエージェントとTerminalで動いているbuild・テストを止めない。応答の途中でも続け、再接続した画面はそのまま同じTerminalに戻る。

## 作り

- PTYとその画面の保持（headlessのemulator）を、Host本体と別の長く動くプロセス（以下、デーモン）が持つ。Host本体はデーモンへ同じマシン内の接続（LinuxはUnix socket、Windowsはnamed pipe。同じユーザーだけが開ける）で接続し、Clientとの通信・保存・Files・Git・チームなどを受け持つ。手本はOrcaのterminal daemon（[stablyai/orca](https://github.com/stablyai/orca) の `src/main/daemon/`）。
- Host本体が起動した時、動いているデーモンがあれば再接続、無ければ起動する。デーモンはHost本体の終了・再起動・入れ替えで止まらない場所で動かす（Linuxはsystemdのuserの別unit、Windowsはバージョンごとの場所へコピーした実行ファイルを、Host本体と親子にせず起動する）。
- PTYの中のCLIが使う接続先（hooksの知らせ、チームの `iori` コマンド）はデーモンが受ける。Host本体が止まっている間に届いたものはデーモンが保持し、Host本体が再接続した時に渡す。Host本体の再起動で接続先の場所が変わり、生きているCLIから届かなくなる作りにしない。
- デーモンと本体の間のやり取りにはバージョンを付ける。本体の更新でデーモンのバージョンが変わらない時はデーモンを続ける。デーモンのバージョンが変わる更新は、デーモンを入れ替えるのでTerminalとエージェントを止める（Orcaのように古いデーモンを残して複数のバージョンへ接続する作りは採らない。保守が大きく、Orcaでも再接続できなくなる不具合が出ているため）。デーモンのバージョンはなるべく変えない。

## ユーザーから見えること

- 再起動・更新の確認画面は、デーモンを続けられる時、「実行中のTerminalとエージェントは止まりません。全デバイスの接続が一度切れ、iori Hostが起動し直すと自動で戻ります。」を表示し、止める作業の一覧と危険色の文言を出さない。
- デーモンのバージョンが変わる更新と、デーモンが動いていない時（マシンの再起動の後など）は、[Hostの再起動](host-restart.md)・[更新](host-install-update.md#更新)のとおり、止める作業を表示して止める。止まったTerminalとCLIの画面の履歴を残し、CLIは会話の再開で起動し直す。
- マシンそのものの再起動、デーモンの異常終了では、Terminalは止まる。扱いは上と同じ。

## 確かめること

- 自動の受け入れに、Linux Host・Windows Hostそれぞれで、PTYで動くCLIとTerminalの処理を続けたままHostを再起動し、Clientが同じTerminalに再接続して出力の続きを受け、hooksの知らせと `iori` コマンドが届くことを通すシナリオを入れる。
