# Pi

読むのは、Pi（`pi` CLI）の検出・モデル候補・Linked Agentの親と子を変える時である。画面と操作は[CLIの画面](cli-screen.md)、子としての使い方は[Linked Agent](linked-agents.md)に従い、ここにはPiで異なる点だけを書く。

## 実行前の確認

Piはツール（ファイルの編集やコマンドの実行）を実行前に確認しない。チームの実行設定には「確認なしで実行」と示し、Piが提供しない承認モードは選べない。Piの拡張が出す質問・確認は、拡張からの通知でAttentionへ届け、CLIの画面で答える。

## 始める

- Piの検出と未導入時の扱いは、他のCLIと同じ「＋」の一覧に従う（[AI Agents/Teams](agents-and-teams.md)）。ログインと会話の開始・再開はPi自身の画面で行う。
- チームの候補で使うモデルは、Hostが`pi --list-models`から取得し、Piと同じ`プロバイダー/モデル`で示す。思考レベルは`pi --help`から取得し、思考に対応するモデルの候補にする。候補を取得するためにモデルは呼ばない。

## Linked Agentの子

- チーム内の子の役割の実行設定で、Piのモデル・思考レベルを選べる。
- 候補ごとに、Piの`--tools`で使えるツール（read・bash・edit・write・grep・find・ls）を選べる。既定はPiの既定で、`--tools`を渡さない。読み取り系だけを選ぶと、Pi自身の仕組みで変更できない。ユーザー・プロジェクトの拡張はPiの通常どおり読み込む。
- 子へ渡す指示文は、その会話でPiを起動するたびに追加のシステムプロンプトとして渡す。ユーザーのPiの設定は書き換えない。

## Linked Agentの親

Piはチームの親としても選べる。親も役割内でモデル・思考レベル・使えるツールを子と同じ規則で選べる。委譲・報告・質問には[Linked Agent](linked-agents.md)の共通コマンドを使う。

## 受入条件

Windows / Android Client × Windows / Linux Host の4組合せで、実際のPiを使って確かめる。

- 「＋」からPiの画面を開き、Pi自身の操作で会話を始め、続けられる。
- Piの拡張の質問がAttentionに届き、CLIの画面から答えるとPiが続きを進める。
- チームの候補でPiのモデル・思考レベル・ツールを選べる。
- Linked Agentで、Piの子へ委譲し、報告を受け取れる。Piを親にしたチームで、子へ委譲し、報告を受けてreviewし、差し戻しを1回行って受け入れられる。読み取り系のツールだけを選んだPiの子がファイルを変えられない。
