# Forgeとの連携

GitHub・Forgejo・GiteaのCIとIssueをioriの中で読む画面、Hostの設定の「連携」、Issueから作業を始める操作、AIエージェント向けのForgeを読み込むコマンドを作る・変える時に読む。サイドバーのPR・CIの印は[Git View](git-view.md#画面の構成)、worktreeの作成画面は[worktreeとフォルダー](worktrees.md#worktreeを作る)、Forgeとの通信と認証情報の保管は[技術設計](../architecture.md#filesとgit)が持つ。

## 範囲

ioriはForgeの情報を読み込むことを基本にする。読み込むのは、CIの実行・ジョブ・ログと、Issueの一覧・本文・コメントである。書き込みは、AIエージェントがPull requestを作るコマンド（`iori pr create`）だけを持つ。通知、Pull requestの本文とレビューのコメント、Release、それ以外の書き込み（コメント、Issueを閉じる、CIのやり直し）は持たない。画面とコマンドでは、Forgeが定義する名前（Issue、CI、workflow、ジョブ、step、ラベル）をそのまま使う。

手元のGitとForgeは別に扱う。Forgeが未設定の時や、Forgeを読み込めない時も、Files・Git・Terminal・CLIは普段どおり使える。

## 対象のリポジトリ

CIの対象は、[PR・CIの印](git-view.md#画面の構成)と同じく、表示中のworktreeのブランチのpush先（`@{push}`）のリポジトリとブランチの、最新のcommitである。Issueの対象は、main worktreeで引数なしの `git push` が使うリモート（Gitの規則で決まり、pushしていなくても決まる）のリポジトリとし、どのworktreeから開いても同じ一覧にする。Forgeの判定と開くURLは、印と同じく[ワークスペースの設定の「Git」](settings.md#ワークスペースのgit)のリモートとWebサイトに従う。

## 連携の設定

設定の「Host」の下の「連携」（英語の表示はIntegrations）で、そのHostがForgeを読み込むための認証を扱う。Forgeごとに設定の項目を増やさず、この1つの項目の中に節を並べる。GitLabなどを足す時も、この項目に節を足す。

### GitHub

そのHostの `gh` のログインの状態を表示する。ログインしているアカウントを並べ、アクティブなアカウント（`gh auth switch` で切り替えるもの）を表示する。`gh` が無い時は「`gh` が見つかりません」、ログインしていない時は「このHostのTerminalで `gh auth login` を実行してください」と表示する。ioriはここでログインやアカウントの切替をせず、トークンを表示しない。リポジトリごとに使うアカウントは[ワークスペースの「Git」](settings.md#ワークスペースのgit)の「GitHubのアカウント」に従う。

### Forgejo・Gitea

サイト（WebのURLのorigin）ごとにトークンを1つ登録する。一覧には、登録したサイトと、このHostで開いたワークスペースのリモートからForgejo・Giteaと分かったサイトを、ホスト名の順に並べる。各行にはサイトのURL、状態、操作を置く。

| 状態           | 表示すること                                             | 操作                       |
| -------------- | -------------------------------------------------------- | -------------------------- |
| 未登録         | 公開のリポジトリだけを読み込んでいること                 | 「トークンを登録」         |
| 登録済み       | トークンの持ち主のアカウント名（読み込めた時だけ）       | 「トークンを変更」「削除」 |
| 権限不足       | 足りない権限（例: `read:issue`）                         | 「トークンを変更」「削除」 |
| トークンが無効 | サイトがトークンを受け付けないこと（期限切れ・取り消し） | 「トークンを変更」「削除」 |
| 接続できない   | サイトに接続できないことと、最後に試した時刻             | 「再試行」「削除」         |

権限不足・トークンが無効・接続できないは、そのサイトを最後に読み込んだ結果（登録、画面、コマンド）で表示し、次に読み込めた時に戻す。

一覧の下の「サイトを追加」で、サイトのURLとトークンを入れて「追加」する。行の「トークンを登録」「トークンを変更」は、その行の下にトークンの欄と「登録」を開く。どちらもEnterでも保存する。追加・登録の時はHostがサイトへ問い合わせ、Forgejo・Giteaとして応答しない、トークンを受け付けない、接続できない時は保存せず、欄のそばに理由を出して入力を残す。権限の不足は、実際に読めなかった時に状態へ出す。トークンの欄の説明に、必要な権限（`read:repository` と `read:issue`。アカウント名を表示する時と[AutomationsのIssue](automations.md#issue)を使う時は `read:user` も、`iori pr create` を使う時は `write:repository` も）を書く。

トークンは入れた後に画面へ出さず、欄を空に戻す。保管は `gh` と同じく、HostのOSの資格情報マネージャー（Windows）・キーリング（Linux）を使い、無い時はHostのデータフォルダーの本人だけが読めるファイルに置く（[技術設計](../architecture.md#filesとgit)）。ファイルに置くHostと、URLがhttpのサイトでは、トークンの欄の下にそのこと（httpではトークンが暗号化されずに送られること）を1行で表示する。トークンは画面・記録・会話・AIエージェントへ出さない。

「削除」は確認を1回出し、「このHostから〈サイト〉のトークンを削除します。非公開のリポジトリとIssueは表示できなくなります。トークン自体は、サイトで無効にするまで使用できます。」と表示する。

## CIの詳細

サイドバーのworktreeの行の[CIの印](git-view.md#画面の構成)を押すと、ブラウザーではなく、親のworktreeの配置の中に「CI」のタブを開く。既にあればそこへ移り、表示対象を押した行のworktreeへ替える。スマホではドロワーの同じ印から全画面で開く。

上端の行に、Gitのタブと同じworktreeの切替、対象のcommit（短いhashと件名）、再読み込み、「ブラウザーで開く」を置く。「ブラウザーで開く」は、失敗している実行、無ければ実行中の実行、全て通過ならそのcommitのCIの画面を開く。十分な幅では左に一覧、右に選んだジョブの詳細を並べ、狭い幅とスマホでは一覧と詳細を一画面ずつ出す（[Git View](git-view.md#画面の構成)と同じ）。一覧は名前・event・時間を1行に並べるので、初期の幅はGit Viewの4分の1より広い本体の38%（320px未満にはしない）とし、Issuesの一覧も同じにする。

- **一覧**: そのcommitのCIを実行（workflow）ごとにまとめ、その下にジョブを並べる。各行に名前、状態（Failed・Running・PassedなどForgeの状態）、かかった時間を表示する。幅が足りない時は、event名（`pull_request_target` など）や結果の説明を名前より先に縮め、入らなければ出さない。Forgejoはジョブの時間を返さないので、Forgejoのジョブには時間を出さない。状態の印はサイドバーの[CIの印](git-view.md#画面の構成)と同じアイコンと色にする。ioriの知らない状態の語は、その語のまま灰の印で表示し、失敗・実行中・通過のどれにも数えない（サイドバーの印も同じ）。実行は失敗、実行中、通過の順に、同じ状態の中はworkflowの名前の順に並べ、ジョブはForgeが返す順にする。やり直した実行は最新の回を表示する。ジョブを持たない結果（外部のサービスのcommit statusやcheck run）は、名前・状態・説明と「ブラウザーで開く」だけの行にする。
- **開いた時の選択**: 失敗したジョブ、無ければ実行中のジョブ、無ければ最初のジョブを選ぶ。
- **ジョブの詳細**: ジョブ名、状態、かかった時間、そのジョブをブラウザーで開くボタン、ログを表示する。ログはジョブ全体を1本で表示し、stepの一覧を返すForge（GitHub）では、ログの上にstepを並べて失敗したstepを表示する。ログは開いた時に失敗したstepの終わり（分からない時はログの末尾）を見せ、上へスクロールすると前の行も読める。行頭の時刻は出さず、色の指定はTerminalと同じ色で表示する。長い行はログの中で横に読め、スマホでは折返しを切り替えられる。終わっていないジョブは、Forgeが返す所までのログを表示する。GitHubはジョブが終わるまでログを返さないので、stepの一覧と、ログの所に「ジョブが完了するまで、ログは表示されません。」と「ブラウザーで開く」を表示し、ジョブが終わった後の[再読み込み](#再読み込み)でログを表示する。
- **ログを読み込めないForge**: 実行・ジョブ・ログを読み込む口を持たないForge（v16より前のForgejoなど）では、一覧をcommit statusから作り、詳細のログの所に「ブラウザーで開く」だけを置く。どの口を使えるかはForgeに問い合わせて決め、使えない操作は出さない。
- **CIが無い時**: 対象のcommitにCIが無い時は「このcommitのCIはありません。」とだけ表示する。ブランチにpush先が無い時は「このブランチにはpush先がありません。CIを表示するには、ブランチをpushしてください。」とだけ表示する。

## Issues

サイドバーの各リポジトリの行に、worktreeを作る「＋」の左へ、Issuesを開くアイコンのボタン（名前は「Issues」）を置く。アイコンは `CircleDot`（[UIの定義](ui.md#画面の骨組み)の表）で、すぐ下のworktreeの行のCIの実行中の印とは別のアイコンにする（[Git View](git-view.md#画面の構成)）。対象のリポジトリのForgeが分かった時だけ出し、Gitでないフォルダーには出さない。開いているIssueの数は出さない（数のために定期的に読み込まない）。スマホのドロワーも同じ行に置く。

Issueはリポジトリのもので、Forgeを読み込むのもworktreeを作るのも、そのHostのcloneで行う。同じリポジトリを複数のHostにcloneしている時は、それぞれのHostのリポジトリの行から開き、そのHostの認証で読み、そこから始めたworktreeはそのHostに作る。

ボタンを押すと、本体が表示している配置がそのリポジトリのworktreeのものならその配置に、違えばそのリポジトリのmain worktreeを選んでその配置に、「Issues」のタブを開く。既にその配置にIssuesのタブがあればそこへ移る。焦点の移し方はサイドバーからFilesなどを開く時と同じにする（[タブと分割](workspace-layout.md#タブと分割)）。

十分な幅では左に一覧、右に選んだIssueの詳細を並べ、狭い幅とスマホでは一覧と詳細を一画面ずつ出す。詳細から戻ると、同じ一覧・絞り込み・選択・スクロール位置へ戻る。

- **一覧**: 上端に、リポジトリ（`owner/repo`）とForgeの種類、状態の切替（Open・Closed）、ラベルの絞り込み、再読み込み、「ブラウザーで開く」を置く。既定はOpen。ラベルはそのリポジトリのラベルから複数選べ、選んだラベルを全て持つIssueに絞る（GitHub・Forgejoの絞り込みと同じ）。各行に状態の印（OpenはPRの印のOpenと同じ緑、Closedは灰）、題名、番号、ラベル（Forgeのラベルの色の小さな丸と名前）、作成者、最後の更新からの時間、コメントの数を表示する。作成の新しい順に並べ、Pull requestは含めない。スクロールに合わせて続きを読み、「さらに読み込む」は置かない。
- **詳細**: 上端に3行を置く。1行目は題名と番号で、幅いっぱいに折り返して表示する。2行目は状態、作成者と作成日時。3行目は「このIssueで開始」と「ブラウザーで開く」を左寄せで並べる。どの幅でも同じ並びにする。その下にラベルと担当者、本文、コメントを古い順に並べる。本文とコメントは[FilesのMarkdown](files-view.md#markdown)と同じ決まりで描画する。画像は、画像の説明の文字のリンクとして表示し、押すとブラウザーで開く。リポジトリは読めるのにIssueが削除された・移された時は「このIssueは見つかりません。」とだけ表示する。
- **空**: 該当するIssueが無い時は「OpenのIssueはありません。」のように表示し、ラベルで絞っている時は「絞り込みを解除」を置く。リポジトリがIssueを使っていない時は「このリポジトリではIssueを使っていません。」とだけ表示する。

## Issueから始める

Issueの詳細の「このIssueで開始」は、そのリポジトリの[worktreeを作る](worktrees.md#worktreeを作る)画面（PCはダイアログ、スマホは全画面）を、次の値を入れた状態で開く。ユーザーは値を直してから「作成」または「この場所で（worktreeを作成しない）」で始める。自動では始めない。

- **名前**: 題名がASCIIの文字（英数字・空白・記号）だけの時は、[`delegate --worktree new` の名前](worktrees.md#作成後に実行するコマンド)と同じく題名をASCIIの英数字とハイフンへ整え（英数字以外の並びをハイフン1つにし、小文字にして前後のハイフンを除く）、24文字以内で単語の途中で切らない所までにして（24文字以内に単語の切れ目が無い時は24文字で切る）、`〈番号〉-〈整えた題名〉` にする（例 「Keep the scroll position after reconnecting」は `134-keep-the-scroll-position`、「Keep the token out of the logs」は `2-keep-the-token-out-of`）。それ以外の文字（日本語など）を含む時と、整えた題名が空になる時は `issue-〈番号〉`（例 `issue-142`）。
- **最初の指示**: 「Issue #123 を進めてください。本文とコメントは `iori issue show 123` で読めます。」（英語の表示では英語の文）。
- **ベースブランチ、CLI・Team、作成後に実行するコマンド**: ふだんの既定値のまま。

始めたCLIは、`iori` のコマンドで最新の本文とコメントを読む。ioriはIssueの本文を指示へ埋め込まず、トークンをCLIへ渡さない。

## AIエージェント向けのコマンド

ioriが起動する全てのCLI（チームの親・子、チームでない会話、Automationの会話）で、Forgeを読み込む `iori` のコマンドを使える。ユーザー自身のCLIの設定が書き込みを許さないsandbox（Codexのread-onlyなど）の会話では、実行にCLIの承認が要る（[子の起動と作業場所](linked-agents.md#子の起動と作業場所)）。チームのコマンド（`iori delegate` など）はチームの会話だけで使える。呼び方、`--json`、`--help` は[Linked Agentのコマンド](linked-agents.md#親と子のコマンド)と同じ決まりにする。

```sh
iori issue list [--state open|closed|all] [--label NAME]... [--limit N]
iori issue show N
iori ci list
iori ci log [JOB_ID]
iori pr create --title TITLE [--body TEXT | --body - | --file PATH] [--issue N]
```

| コマンド          | 返すもの                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `iori issue list` | Issueの番号・状態・題名・ラベル・更新日時。既定はOpenの30件（`gh issue list` と同じ）で、`--limit` で件数を変える。続きがある時は最後にそのことを1行で表示する。`--label` は複数付けられ、全てを持つIssueに絞る                                                                                                                                                                                                                                                                                                                                                                   |
| `iori issue show` | Issueの題名・状態・作成者・ラベル・本文と、全てのコメント（作成者・日時・本文）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `iori ci list`    | 呼んだCLIのworktreeのブランチのpush先の最新のcommitのCI（実行、ジョブ、状態、ジョブのID）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `iori ci log`     | 指定したジョブのログ。ジョブのIDを省くと、`iori ci list` と同じcommitの失敗したジョブのログ                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `iori pr create`  | 呼んだCLIのworktreeの今のブランチを、Hostが自分の認証でpush先へpushし（force-pushはしない）、そのリポジトリの既定のブランチへのdraftのPull request（Forgejo・Giteaは題名の先頭に `WIP:`）を作って、そのURLを返す。本文の渡し方（`--body -` は標準入力、`--file` は作業ディレクトリの中のファイル）は `iori delegate` と同じ。`--issue N` を付けると本文の末尾に `Closes #N` を足す。同じブランチのPull requestが既にあれば、作らずにそのURLを返す。既定のブランチからは作らない。Forgejo・Giteaのトークンに書き込みの権限（`write:repository`）が無い時は「権限が足りない」を返す |

対象のリポジトリとブランチは、呼んだCLIのworktreeから[画面と同じ規則](#対象のリポジトリ)で決める。毎回Forgeから読み込み（そのサイトがどのForgeかの判定も、画面の再読み込みと同じくやり直す）、本文とログはForgeが返すまま出す。読み込めない時は[画面と同じ理由](#失敗の表示方法)と回復の操作（例: 設定の「連携」でトークンを登録する）を英語の短い文で返す。認証はHostが持ち、トークンをCLIの環境・引数・答えに出さない。

## 再読み込み

CIとIssuesの画面は、開いた時（隠れていたタブを再び表示した時を含む）と、ユーザーの再読み込みで読み込む。Issueの詳細は選んだ時に読み込む。CIの画面は、サイドバーのCIの印が変わった時（pushや状態の変化）にも再読み込みする。読み込めない理由を表示しているCI・Issuesの画面は、[連携](#連携の設定)でトークンを登録・替える・削除した時にも再読み込みする。CIの画面の再読み込みと再試行では、そのサイトがどのForgeかの判定もやり直す。再読み込みの間と、再読み込みに失敗した時は、最後に読み込めた内容を保つ。サイドバーの印の再読み込みは[Git View](git-view.md#画面の構成)に従う。

## 失敗の表示方法

Forgeを読み込めない時は、理由を区別して、その対象（CI・Issuesの画面、連携の行、コマンドの答え）のそば一か所に、起きたことと回復の操作を表示する（[表示と失敗の案内](../product.md#表示と失敗の案内)）。

| 理由           | 表示すること                                                                                                          | 回復の操作                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| トークンが無い | 〈サイト〉のトークンが登録されていないこと。GitHubは `gh` にログインしていないこと（`gh` が無い時は見つからないこと） | 「連携を開く」。GitHubは `gh auth login` の案内       |
| トークンが無効 | 〈サイト〉がトークンを受け付けないこと                                                                                | 「連携を開く」                                        |
| 権限が足りない | トークンに足りない権限。GitHubは読めるアカウントが無いこと                                                            | 「連携を開く」                                        |
| 見つからない   | リポジトリ（`owner/repo`）が見つからないこと                                                                          | 「ワークスペースの設定を開く」（リモートとWebサイト） |
| 接続できない   | 〈サイト〉に接続できないこと                                                                                          | 「再試行」                                            |
| 回数の上限     | APIの回数の上限に達したことと、読めるようになる時刻                                                                   | 「再試行」                                            |

GitHubは、アカウントが読めない非公開のリポジトリにも「見つからない」と答える。そのため、HostのどのGitHubのアカウントでも読めない時は「権限が足りない」として表示する。アカウントを順に試すのはリポジトリを読めるかを決める時だけで、読めるアカウントで中の1件（Issue、ジョブのログ）が見つからない時は、リポジトリの理由を出さずにその物が無いとして表示する（始まる前に終わったGitHubのジョブは「このジョブは実行されませんでした。」）。

## スマホ

CIはドロワーのworktreeの行のCIの印から、ジョブの一覧を失敗したジョブを選んだ状態で全画面に開く。Issuesはドロワーのリポジトリの行のボタンから全画面で開く。一覧と詳細は一画面ずつ行き来し、Androidの戻る操作は詳細から一覧へ戻る。「このIssueで開始」は全画面のworktreeの作成画面を開く。設定の「連携」は、ほかの設定の項目と同じく一覧から全画面で開く。
