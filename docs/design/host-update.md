# ClientからのHostの更新

> Status: 採用済みの製品仕様。

読むのは、ClientからHostを更新する操作、その知らせ・確認・進行・失敗の扱い、Hostが自分を入れ替える処理を変える時である。Hostの再起動の画面は[Hostの再起動](host-restart.md)、Terminalが続く仕組みは[Hostの再起動・更新をまたいでTerminalを続ける](terminal-daemon.md)、Clientの更新は[Clientの自己更新](client-update.md)に従う。

## 目的

ユーザーは、Hostのマシンにログインせず、普段のClient（PCでもスマホでも）からHostを新しいバージョンにする。作業中のエージェントとTerminalは止めない。

## 更新先と知らせ

- 更新先は、操作しているClientと同じバージョンとする。Clientを先に更新し、その後でHostをClientにそろえる（VS Code ServerがClientと同じバージョンを使うのと同じ考え方）。安定バージョン・開発バージョンはClientが選ぶため、Hostには別の切替を設けない。
- HostはClientへ自分のバージョンを知らせる。HostがClientより古い時は、全体の設定を開く入口、そのHostの行の「Hostの設定」の歯車と、Host設定の「バージョン」に小さな印を付ける。自動で更新せず、設定を開かず、Attentionにも加えず、OSの通知も出さない（[Clientの自己更新](client-update.md#確認と知らせ)と同じ）。
- 設定画面の中にも同じ印を付け、入口の印に気付かずに設定を開いた人も、更新の場所をすぐ見つけられるようにする。
  - Hostの選択部品には、更新が要るHostが1台でもあれば印を付ける。選んでいないHostが古い時も、ここで気付ける。
  - 選択部品を開いた一覧では、更新が要るHostの名前の横に印を付ける。
  - 「バージョン」の項目には、選んでいるHostの更新が要る時に印を付ける。
  - Hostのバージョンは、接続して知らされたものを使う。まだ知らされていないHostには印を付けない。
- HostがClientより新しい時は、Hostを古いバージョンへ戻さない。代わりに「バージョン」でClientの更新欄を案内する。
- 「バージョン」には、Hostの今のバージョン、更新先のバージョン、変更内容へのリンク、「iori Hostを更新」を並べる。同じ画面に「iori Hostを再起動」も置く。

## 確認

押すと確認画面を開き、今のバージョンから更新先のバージョンへ変わることを表示する。

- Terminalを持つ係を続けられる時: 「〈Host名〉 を 〈今のバージョン〉 から 〈更新先〉 に更新します。」だけを表示し、「更新する」で進める。CLIとTerminalは止まらない。
- 係を入れ替える更新（係のバージョンが変わる時）と、係が動いていない時: 同じ1行の下に、[Hostの再起動](host-restart.md#確認)と同じく「開いているCLIとTerminalはすべて停止します。CLIの会話は後で再開できます。」と「中断される作業」を該当する時だけ表示し、中断される作業がある時は「停止して更新する」、ない時は「更新する」で進める。押せなくはしない。

## Clientの更新と一緒に更新する

[Clientの更新欄](client-update.md#hostとの関係)で「接続中の iori Host も更新する」を選んだまま更新すると、開き直したClientは、更新を押した時に接続していたClientより古いHostを、もう一度は確かめずに続けて更新する（更新欄の選択を確認とみなす。VS Code ServerがClientの更新の後に同じバージョンへそろうのと同じ考え方）。

- 開き直した直後に確認の画面「iori Hostを更新」を開き、対象のHostを全部、最初から行で並べる。行の見出しはHost名で、行の間を区切り線で分ける。ボタンは「閉じる」だけで、閉じても更新は続く。
- 行ごとに状態を表示する: 確認中（回る印）→ 更新中（進み具合は下の[進行と結果](#進行と結果)）→「iori Hostを更新しました」。既に最新なら「最新のバージョンです」。更新に失敗したら理由と「iori Hostを更新できませんでした」。
- 接続できないHostは、接続の層が失敗を返した時（固定の時間切れは置かない。通信の層の既定で約30秒）に「Hostに接続できませんでした。」と「Hostが起動していることを確認してください。」を表示する。画面を開いている間にそのHostへ接続できたら、続けて更新する。閉じた後は、そのHostの「バージョン」から更新する。
- 止まる作業があるHost（動いている作業がある時と、Terminalの係を入れ替える更新で開いているCLI・Terminalがある時）だけは自動で進めず、その行に上の[確認](#確認)と同じ説明と「中断される作業」を表示し、行の最後に「停止して更新する」を置く。押されるまで、そのHostは更新しない。画面を閉じたら、そのHostはそれぞれの「バージョン」から後で更新する。
- 1台の失敗・待ちでほかのHostを止めない。失敗したHostは、そのHostの「バージョン」から再試行する。自動で送り直さない。
- 更新を始めた後にあるHostで新しく止まるものが出た時は、そのHostだけ更新を始めず、その行で確認を出し直す。

## 進行と結果

- Hostが配布元から、更新先のバージョンの配布物を自分で取得する。署名付きの `release.json` をHostに埋め込んだ公開鍵で検証し、配布物のSHA-256と大きさを照合してから使う。取得先は配布物の `release-source.txt` に固定したGitHubのHTTPS配布元にする。転送は同じoriginと、Clientと共通の `release-redirect-hosts.json` に列挙したGitHubの配布物のhostへのHTTPSだけを許す。
- 入れ替えは、Host本体とは別の短い更新の処理が行う（Syncthing・Tailscaleと同じく、動いているHostが自分のファイルを直接上書きしない）。Hostを止め、今のバージョンと保存データを控えてから新しいバージョンを置き、起動する。
- 更新・再起動のボタンを押せなくするのは、今の接続で自分が送った操作の進行中だけにする。Hostが更新処理の終了を検知し、結果が無ければ理由を表示して再試行できるようにする。
- Clientは「iori Hostを更新中」を表示し、切断を失敗として扱わない。再接続したHostが更新先のバージョンを知らせた時に「iori Hostを更新しました」を表示する。
- 新しいバージョンが起動できなかった時は、更新の処理が控えた前のバージョンと保存データに戻して起動し直す。Clientには「iori Hostを更新できませんでした」と、前のバージョンで動いていること、失敗の理由を表示する。前のバージョンでも起動できない時は、Hostのマシンで状態を確かめる手順を表示する。
- 停止を確かめられず保存データの復元を見送った場合も、前のバージョンを置く処理と起動要求は試す。Clientには保存データを戻せなかったことと、再試行前にHostとバックアップを確認する案内を表示する。
- Hostが配布元に届かない時は、更新を始めず、配布元に届かないことと、Hostのマシンで導入スクリプトを使って更新する手順を表示する。

## 範囲

- WindowsとAndroidのClientの両方から更新できる。登録済みのデバイスはどれも更新できる。
- 最初のバージョンに入れないもの:
  - Clientが取得してHostへ渡す経路
  - SSHでの更新
  - 自動の更新
  - 任意のバージョンの選択

  Hostが配布元に届かないユーザーが出た時に、Clientが取得して渡す経路を足す（VS Code Remote SSHと同じ考え方）。

- 導入スクリプト（`install.sh`・`install.ps1`）での手作業の更新は残す。

## 確かめること

- Linux Host・Windows Hostそれぞれで、旧バージョンから新バージョンへ、Clientの画面から更新し、実行中のCLIとTerminalが続き、Clientが新しいバージョンに再接続する。
- 新しいバージョンが起動しない配布物で、前のバージョンと保存データに戻って動き続ける。
- 印・確認・進行の表示は画面のE2Eで確かめる。
