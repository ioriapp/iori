# Hostの再起動

> Status: 採用済みの製品仕様。この文書は登録済みClientからHostを再起動する画面と操作を定める。

読むのは、ClientからのHost再起動、その確認と進行の表示、Host側の再起動の受付と起動し直しを変える時である。
停止の判定と安全境界は[技術設計](../architecture.md)、Hostの導入・更新は別に定める。

## ユーザーの目的

Codex / ClaudeのCLI更新を反映する時や、Hostの状態を立て直したい時に、Hostのマシンへ別途ログインせず、普段使っているClientから再起動する。止まる作業と影響を読んでから進めるかを自分で決める。中断された会話は、起動し直した後にそのまま続けられる。

## 入口

Host設定画面に「iori Hostを再起動」を置く。Windows / Androidとも同じ位置にする。Terminalを持つ係を続けられる時の入口と確認の表示は[Hostの再起動・更新をまたいでTerminalを続ける](terminal-daemon.md#利用者から見えること)に従い、この文書の止める作業の表示は係を続けられない時だけに使う。その時、入口には危険を示す色で「実行中のTerminalは停止し、途中の処理は失われます。」を常に示す。

Hostがserviceとして動いていないなど、Hostが起動し直せないと報告した時は、押せない表示にして理由（例:「このiori Hostはserviceとして動いていないため、ここから再起動できません」）を並べて示す。

## 確認

押すと確認画面を開き、確認画面を開いた時点のHostの状態を読んで、再起動するかの判断に要るものだけを示す。上に「〈Host名〉 を再起動します。」と書き、次の1行と節を、該当する時だけ置く。

- 開いているCLIかTerminalがある時: 「開いているCLIとTerminalはすべて止まります。CLIの会話は後で再開できます。」
- 「中断される作業」（警告。見出しに危険色の印）: 応答中・承認待ち・質問のCLI（状態はサイドバーの子・会話と同じ判定）と、コマンドが動いているTerminal（シェルが入力を待っているだけのものは除く。Terminalを閉じる時の確認と同じ判定）。行ごとに名前と状態を示し、押すとそのタブを開く。

作業場所のパス、待機中のCLI、入力待ちのTerminal、接続が一度切れること（押した後の進行の画面が示す）は確認画面に書かない。中断される作業がある時は「止めて再起動する」、ない時は「再起動する」で進める。どの対象があっても、押せなくはしない。確認画面を開いたまま、確認に無かった中断される作業が新しく増えた時だけ、再起動せずに最新の状態で確認画面を出し直す。確認した作業が終わって減っただけなら、そのまま進める。worktree作成後に実行するコマンドが動いているTerminalも、中断される作業に入れる。

## 進行と結果

再起動を押すと、Hostが新しい作業の受付を止め、確認した対象のTerminalとAgentの応答を止めて停止する。止めた応答は中断として記録し、起動し直した後に同じ会話へそのまま送れる。

停止を受け付けた後、Clientは「iori Hostを再起動しています」を示し、切断を失敗として扱わない。Hostが起動し直して再接続できた時、起動し直したHostであることを確かめてから「iori Hostを再起動しました」を示す。経過時間では失敗にせず、つながり直すまで待ち続ける。通常の自動再接続より長く戻らない時は、待ち続けたまま「iori Hostの再起動をまだ確認できていません。このまま待つか、Hostのマシンでサービスの状態を確認してください。」を添え、同じ画面から再接続できるようにする。Hostが起動に失敗したと確定した時（更新の処理が失敗を記録した時など）だけ、失敗として示す。

結果が分からない時に、再起動をもう一度自動で送らない。同じ操作の再送は同じ結果の照会になる。

## 権限と範囲

登録済みの端末はどれも再起動できる。端末ごとの役割は設けない。

Clientから行うのは再起動だけである。停止したまま残す操作、保守の途中段階（受付停止だけ、保存だけ）、Hostのバージョンの入れ替えはこの画面に置かない。

## Hostの扱い

- 再起動は、Hostが所有する処理（Agentの応答・子作業・Terminal）を止めてから行う。実行中や結果不明の作業があっても、Clientからの明示要求で進める。止めた応答は中断として閉じ、会話の再開を妨げない。
- 起動し直しはOSのservice管理に任せる。Linuxのsystemd user unitではHostが停止を確かめた後にunitの再起動を依頼する。WindowsのserviceはHostが再起動用の終了コードで終わった時に起動し直す設定を持つ。
- 起動し直せる条件を満たさないHost（serviceでない、Linuxでunit名が分からない等）は、再起動を受け付けず、その旨をClientへ報告する。
