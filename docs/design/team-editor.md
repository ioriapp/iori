# チームの編集画面

[チーム](teams.md)を作成・編集する画面。画面の構成・操作・保存と履歴を変える時に読む。チームが持つ項目と割り当ての規則は[チーム](teams.md)、入口とAIエージェントの画面は[AI Agents/Teams](agents-and-teams.md)が扱う。

## 構成

[AI Agents/Teams](agents-and-teams.md)の画面の左の木で、チームを開くと「Team全体」「親」と役割の行（右に同時実行の上限の数）、末尾に「＋ 役割を追加」を並べる。未保存の変更があるチームは名前の横に小さなインジケーターを付ける。チーム名は省略せず、長ければ折り返して全部見せる（複製して末尾だけ変えた名前を見分けるため）。既定のチームの選択欄も、選んだ名前と一覧の名前を省略しない。行を選ぶと右に詳細を出す。Mobileは木を全画面の一覧にし、選ぶと詳細へ全画面で進み、上端に戻るボタンと現在地（チーム名 › 役割名）を置く。

チームの中を選んでいる間は、右の上部にチーム名、「バージョン3 · 保存済み」または「未保存の変更」、「履歴」「元に戻す」「保存」と、チームの一覧の行と同じ…メニュー（複製・別のHostへコピー・削除）を固定する。保存と取り消しはチーム全体で1つで、未保存の変更が無い時は押せない。

設定の行は「左に名前と説明、右に操作」に揃え、操作は中身の右端に置き、行の間に区切り線を引く。長い文章（名前、説明、使う場面、指示、依頼と報告の項目）は、ラベルの下に横幅いっぱいの入力欄で書く。

## チームの一覧

「Team」の見出しを選ぶと、チーム機能のスイッチ、既定のチームと、チームの一覧（名前、説明、既定の表示、そのチームを使う会話の数、バージョンと更新日時）を出す。行を押すとそのチームを開き、…メニューに複製・別のHostへコピー・削除を置く。左の木のチーム名の行を右クリック（スマホは長押し）すると、開く・複製・別のHostへコピー・削除のメニューを開く（サイドバーのworktreeの行と同じ）。「＋」で新しいチームを、テンプレートか既存のチームから作る。チーム機能・既定のチームは、その場で保存する（チームのバージョンに含めない）。

## チーム全体・親・役割

- チーム全体: 名前、説明。
- 親: 実行設定の1行（候補の行と同じ部品で、順番・取っ手・残量の下限が無い形）、親への指示、親に渡る文章。
- 役割: 「基本・候補・指示・依頼と報告・子に渡る文章」の節を1つのページに縦に並べる。基本は名前、使う場面、同時実行の上限、子のセッションを再利用する。役割の…メニューに名前の変更・複製・削除を置く。

親のCLIが未設定の行は「未設定」と表示し、押すとCLIとモデルを選べる。役割の候補が空なら「候補が設定されていません。」と表示し、候補を追加できる。始める画面では親のCLIが未設定のチームに「親のCLIを選択してください」と出し、押すとそのチームの編集を開く。

「親に送る文章」「子に送る文章」は、ioriが渡す固定部分とチームの入力を組み立てた形を折り畳みで表示する。

## 候補

「難易度で分ける」がオンなら、高・中・低を件数付きの切り替えで選び、選んだ難易度の一覧を出す。オフなら中の一覧だけを出し、高・低の入力は保持する。

候補の一覧は列を揃え、見出しを一度だけ置く。1行は、取っ手と順番、「CLI › モデル」の選択、Effort、許可、残量の下限、…メニュー（別の難易度・別の役割へコピー、削除）。ドラッグで優先順を変える。Mobileは2段にする（1段目に取っ手・順番・CLI › モデル・…、2段目にEffort・許可・残量の下限）。

- 許可は、押すとそのCLIの項目をポップオーバーで編集し、ボタンには今の値の要約を出す。項目はCLIが公開する名前のまま（Claude Code は permission mode、Codex は `approval_policy` と `sandbox_mode`、Pi は「確認なしで実行」の一文とツールの選択、OpenCode は「Auto-approve permissions」（オン/指定しない）、他のCLIは「指定なし」だけ）。
- 残量の下限（%）は残量を取得できるCLI（[AIエージェント](agents-and-teams.md#aiエージェント)）の候補だけに出す。空の時は「なし」を表示する。他のCLIの欄は空のままにし、親の行には出さない。その候補のモデルに適用される利用枠のどれかが下限を下回る場合に、割り当てを飛ばす。モデルやグループを名指しした枠は、そのモデルの候補にだけ適用される。
- 行の下に、その候補に適用されるHost全体の上限を小さく表示し、押すとAIエージェントの該当のCLIへ移る。残量が下限を下回っている候補は注意の色で「今は残量が下限を下回るため使われません。」、Hostに無いCLIの候補は行を薄くして「このHostで見つかりません」と表示する。

起動時のEffort指定に対応しないCLI（CLIの定義に `launch.effort` が無く、コードでも付けない。OpenCode V1・Cursor CLIなど）は、モデル一覧の状態（取得中・失敗・一覧に無いモデル）によらず、候補にEffortの操作を出さず、保存済みの値も起動引数へ渡さない。OpenCode V2はモデルごとのvariantをEffortとして選べる。Effortに対応しないCLIでは、そのCLI自身の画面で変更する。CLIの一覧に無い（未インストール・旧Host）CLIは対応が分からないので、今までどおり表示する。

同じCLIでモデルを選び直す時も、新しいモデルのEffort一覧に保存値が無ければEffortを削除する。

Effortと許可の「指定なし」は値を保存しない。CLI自身が返す `none` などの値とは区別する。モデルはCLIが受け付ける値で保存し、一覧に表示名があれば画面には表示名を出す。保存済みの値が一覧に無い場合はその値を表示し、削除したり保存を拒んだりしない。

「CLI › モデル」の選択と「＋ 候補を追加」は、同じ検索つきの一覧を使う。検索が空の時は、先頭に「このTeamで使っているモデル」（親と全役割の候補。重複は1つ）、その下にCLIごとの群を置く。プロバイダが複数あるCLIは、プロバイダの行（モデルの数つき）を閉じて並べ、開くとそのモデルをプロバイダ名を省いて出す。文字を入れると全CLI・全モデルから絞り込み、「CLI › プロバイダ」の見出しの下に出す。一覧は高さを画面に収めて中だけスクロールし、↑↓・Enter・→（開く）・←（閉じる）・Escで操作できる。PiやOpenCodeのように数百のモデルを持つCLIでも、件数で打ち切らない。

## 数の入力

同時実行の上限（役割とHost全体）は、空なら「上限なし」と表示する。入力欄の右端の内側に増減のボタンを置き、↑↓キーでも同じに動く。空で増やすと1、1で減らすと空（上限なし）に戻る。上の値は置かない。ブラウザー自身の増減のボタンは出さない。

## 保存と履歴

保存すると新しいバージョンになり、親の次の委譲から使う（[チーム](teams.md#チームが持つもの)）。保存結果は保存ボタンの横に「保存済み」または理由付きの「保存できませんでした」と表示し、失敗や切断でも入力を保持する。保存だけでは会話へメッセージを送らず、応答を始めない。未保存の変更があるチームから離れる時だけ、「変更を保存しますか？」の確認（「キャンセル」「保存しない」「保存」。[ダイアログ](dialogs.md)）を出す。AIエージェントの設定など節ごとに保存する所の未保存の変更だけの時は、[破棄の確認](dialogs.md)のままにする。

「履歴」は右からのシートで、バージョンの一覧（番号、日時、変わった所）を新しい順に出す。変わった所は、保存の時に前のバージョンと比べて自動で書く（「Workerの候補を変更しました・Advisorを追加しました」のように、役割・項目の単位と、役割・候補の追加と削除。多い時は先頭の数件と「ほかN件」）。保存の操作は増やさない。各バージョンには後からメモを書き足せ、メモはバージョンの番号を上げない。バージョンを選ぶとその時の内容を表示し、「このバージョンに戻す」で、その内容を新しいバージョンとして保存する（変わった所は「バージョン2に戻す」）。
