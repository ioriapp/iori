# ダイアログとポップアップ

重ねて表示する画面は共通の閉じる処理を使う。開くと操作対象を中へ移し、モーダルの間は背景を操作できない。Tabで中の操作を巡回し、閉じると開いた操作へ戻す。候補入力の補完では入力欄の操作を維持し、軽いポップアップを外側から閉じた時はクリックした入力先へ移れる。

| 種類                           | 背景のクリック・Esc                                                          | ×・キャンセル                                      |
| ------------------------------ | ---------------------------------------------------------------------------- | -------------------------------------------------- |
| メニュー、候補一覧、モデル検索 | 即座に閉じる                                                                 | 閉じる                                             |
| 削除、停止、更新などの確認     | 実行しない                                                                   | 実行しない                                         |
| 保存・反映する入力             | 変更がなければ閉じる。変更があれば「変更を破棄しますか？」を一つだけ表示する | 明示的に変更を破棄して閉じる。破棄の確認は出さない |
| 処理の進行表示                 | 表示を閉じ、処理を続ける                                                     | 表示を閉じ、処理を続ける                           |

破棄の確認から「編集を続ける」、Esc、背景、×で戻ると入力を保つ。「変更を破棄」で入力画面も閉じる。保存を1つだけ持つまとめて編集する画面（チーム）から離れる時は、破棄の確認の代わりに、OSのアプリと同じ「変更を保存しますか？」と「キャンセル」「保存しない」「保存」を出す。「保存」は保存できてから移動し、保存できなかった時は移動せずに確認を閉じ、いつもの場所に理由を出して入力を保つ。「キャンセル」・Esc・背景・×は「編集を続ける」と同じに戻る。節ごとに保存する画面（設定など）は、何を保存するかが1つに決まらないので破棄の確認のままにする。検索語や候補の絞り込みは保存する編集に含めない。値を元に戻した時は未変更として扱う。チームや記録を切り替える時の保存確認は、画面を閉じる操作とは別に扱う。

実行中の処理を隠した後も、元の画面の状態表示から進行・結果へ戻れる。閉じる操作から停止、再送、削除を実行しない。

取り消しのボタンは、どのダイアログでも「キャンセル」とする（OS の確認ダイアログと同じ）。実行を確定した後や結果だけを表示する時のように取り消すものが無い時は、同じボタンを「閉じる」にする（成功と失敗が混ざっても合う言葉にし、「完了」は使わない）。削除・停止・更新などの確認では、開いた時の焦点を「キャンセル」に置く（Enterで誤って実行・移動しないため）。確認の中で対象を開ける一覧は、名前を文字のリンクにせず、行全体を押せる形にする。ボタンの文字は折り返さず、狭い画面ではボタン群を折り返すか縦に並べる。内容は画面内でスクロールでき、閉じる操作へ到達できる。ウィンドウより高いダイアログは、題名と操作を見せたまま本文だけをスクロールする。

ダイアログの操作は、[UIの定義](ui.md#画面の骨組み)の「主な操作は上端の行の右」の例外として、PCでは下端の右に横に並べ、スマホでは下に縦に並べて主な操作を先頭に置く。スマホで全画面に出すダイアログ（worktreeの作成画面、設定など）は画面そのものとして扱い、枠・角丸・影を持たない。

入力候補をボタンで開いてから文字入力で絞った場合、閉じると入力欄へ焦点を戻す。IMEの変換中のEscは文字変換だけを操作し、候補を閉じない。失敗した操作は理由と回復方法をその対象の横に一つだけ表示する。原因が分からない失敗では原因を作らず、取れる回復方法だけを表示する。応答待ちや結果未確認を失敗に置き換えない。
