# CLIの画面

読むのは、CLI自身の画面（PTY）の起動・状態・再開・参照の入力を変える時である。製品全体の価値と判断基準は[製品仕様](../product.md)、責任境界は[技術設計](../architecture.md)、shellと入力は[Terminal](terminal.md)、子の表示は[Linked Agent](linked-agents.md)が持つ。

## 始める

CLI自身の画面は、タブの「＋」の一覧からCLIを選んで開く。タブにはCLIの画面がそのまま出る。ペインにはCLIの画面だけを出し、帯やボタンを重ねない（スマホで過去の出力を読む間の「最新へ」だけは例外。[スマホでのTerminalとCLIの画面](mobile-terminal.md#過去の出力を読む)）。タブとサイドバーの行には、状態の印、CLIのアイコン、CLIが端末へ出す題名（無ければCLIの名前）、今の状態になってからの経過時間を出す。承認待ち・入力待ち・応答中・完了は、hooks・extensionを持つCLIで出し、承認待ちと入力待ちは[接続](connection.md)の表示時期に従ってAttentionへ届ける（[技術設計](../architecture.md#cli)）。完了の印は、その画面を表示すると消える。Attentionから選ぶとそのCLIの画面へ移り、答えはCLIの画面の中で行う。その他のCLIは、プロセスの生存と終了、CLIが出す題名と注意音（BEL）の範囲で示し、承認待ちは出さない。CLIの画面はCLI自身の既定のモデル・設定で起動し、モデルなどの変更はCLIの中で行う。CLIの画面は、CLIの起動コマンドを実行したTerminalである（Orcaと同じ）。CLIを抜けるとshellに戻り、そのままTerminalとして使える。タブを閉じてもCLIは止めない。Hostの再起動やTerminalの係の停止でCLIが失われた時は、最後の画面を残し、下端の1行にそのことと「再開」「閉じる」を置く。「再開」はCLIの再開機能で同じ会話を開き直し、会話のIDを持たないCLIは同じコマンドで起動し直す。iori の外で始めた会話は、CLIを起動してCLI自身の再開の画面から開く。Files・Gitからの参照は、開いているCLIの画面の入力へそのCLIの参照の書き方（`@path` など）で打ち込み、送信はしない。

単独のCLIは、[AIエージェント](agents-and-teams.md#aiエージェント)で保存した起動時の引数を付けて開く。再開時も現在の保存値を使い、CLIの命令、ユーザーの引数、ioriの再開の引数の順に組み立てる。チームの親・子も保存した起動時の引数を使い、役割の設定から付ける項目と重なる引数はユーザーの側から値ごと外して役割の設定を優先する。チームの再開は、最初に起動した時の引数を使う。

## 利用枠の書式

利用枠の窓は5h・7d・30dなど長さで呼び、weekや週とは呼ばない。CLIが窓をモデルやモデルのグループごとに返す時は、CLIが返した名前を窓の長さの前に付ける（`Fable 7d 100%`、`Gemini Models 7d 100%`）。リセットまでの残りは1日以上なら`3d 4h`、1日未満なら`2h 15m`、1時間未満なら`45m`とする。Boardとチームの候補で同じ書式を使う（`Usage 5h 78% · resets 2h 15m`）。AIエージェントの一覧は、取得の前後で行の高さを変えないため、狭い時は resets を省いて1行にし、収まらない枠は「+N」として落とす。Board とチームの候補は、狭い時は resets を省き、吹き出しで全文を読める。接続先同士は余白または細い縦線で区切る。
