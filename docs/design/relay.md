# Relay

Relayは、LANやVPNで届かない時にClientとHostの通信を中継する機能である。Relayを使うと、外出先からVPN無しでHostへつなげる。この文書は、Relayの設定・接続の経路・表示を作る・変える時に読む。暗号と認可の境界は[技術設計](../architecture.md#relay)が持つ。

## 使い方

Relayは任意で、既定は今のとおり直接だけでつなぐ。LANやVPNだけで使う人には、設定も表示も増えない。

ユーザーは設定のHostの「接続」で、RelayのURLと、Relayが求める時だけアクセスのトークンを入れる。RelayはユーザーやHostの管理者が自分で用意したもの（irohの `iroh-relay`）を使う。iori自身が運営するRelayはまだ無い。

URLとトークンは同じ節に置き、節の「保存」かEnterでまとめて保存する（[保存の仕方](ui.md#保存の仕方)）。保存すると、Hostにつながっている全ての端末が短く切れて自動で再接続する。ClientではほかのHostの接続も同じく短く切れる。TLSの無い `http://` のRelayにもトークンを送る（LAN・VPNの中で自前のRelayをTLS無しで動かす使い方があるため）。

Relayを設定したHostへは、まず直接つなぎ、届かない時だけRelayを通す。Relayを通してつながった後も、直接届くようになれば直接へ移る。どちらの経路でも、端末の登録・鍵の確認・Hostでの認可は同じで、Relayは暗号化された通信を運ぶだけである。

## Clientへの伝わり方

ClientはRelayのURLとトークンをHostから受け取る。ユーザーがClientごとに設定する必要はない。

- 登録済みの端末は、Hostと接続した時に最新のRelayの設定を受け取り、保存する。以後、LANの外にいてもRelay経由でつながる。
- 招待にはRelayのURLを含める。トークンは長く使う秘密なので招待に含めず、登録の後に暗号化された接続で渡す。トークンを求めるRelayだけを設定したHostへは、外出先から初めて登録することはできない。最初の登録はLAN・VPNで行う。

Relayの設定を変えたり外したりしても、登録済みの端末と接続先は変わらない。Relayの設定を外した後は直接だけでつなぐ。

## 表示

接続の経路（直接かRelayか）は、設定のHostの「接続」に示す。他の画面には出さない。Relayへ届かない時でも、直接つながっていれば何も示さない。直接もRelayも届かない時は、ふだんの切断と同じく[Hostとの接続が切れた時の表示](host-recovery.md)に従う。
