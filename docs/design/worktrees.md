# worktreeとフォルダー

フォルダーを開く、worktreeを作る・削除する、CLIの会話を開く操作を変える時に読む。表示の配置は[画面の構成と移動](workspace-layout.md)、子への委譲は[Linked Agent](linked-agents.md)が持つ。

## フォルダーを開く

「フォルダーを追加」はHostのホームフォルダーから始まり、パス入力で候補を絞る。↑↓で選び、Enterまたはタップで次の階層へ進む。Ctrl+Enterまたは「このフォルダーを開く」で入力したパスを開く。絞り込みの語が `.` で始まらない時は、名前が `.` で始まる隠しフォルダーを候補の後ろへ並べる。同じパスでもHostが違えば別の対象にする。

Gitリポジトリはworktreeで扱う。リポジトリを開くと、そのworktreeをサイドバーへ自動で並べる。CLIやGitで作られたworktreeも自動で現れ、削除されたら外れる。Gitでないフォルダーにはworktreeの操作を出さない。開くフォルダーとGitのルート、Agent・Terminalのcwdは区別する。

## worktreeを作る

リポジトリの「＋」（worktreeを作る）を押すと、PCではダイアログ、スマホでは全画面の作成画面が開く。名前（任意）、ベースブランチ（既定 `origin/main`）、CLI・Team、最初の指示（任意）を選び、「作成」でworktreeを作って選び、そのAgentへ進む。名前の欄のEnter、ダイアログのどこからでもCtrl+Enter（macOSはCmd+Enter）でも「作成」と同じにする。`origin/main` がない時は、`origin/HEAD` が指すブランチ、それも無ければmain worktreeの今のブランチを既定にする。起点には子のブランチも選べる。「この場所で（worktreeを作成しない）」ではmain worktreeで始める。最初の指示は、始めたCLI（チームなら親）へ最初の入力として送り、空なら何も送らない。送り方は[Automationsの指示](automations.md#実行)と同じにする。Issueから開いた時の値は[Issueから始める](forge.md#issueから始める)に従う。

CLI・チームはタブ追加と同じ一つの選択にし、CLIの群の下にチームの群を置く。CLIは[AIエージェント](agents-and-teams.md#aiエージェント)の一覧と同じ順に並べ、そのHostで最後に使ったものを初めから選んでおく。チーム機能がオンなら既定のチームを選んでおき、各チームには親CLIを添える。チームを選ぶとその設定の親CLIで始まり、CLIを選ぶとチームなしで始まる。Gitでないフォルダーの「＋」はタブ追加と同じ一覧を開き、そのフォルダーでCLI・チームを始める。

指定した名前は[Orcaの名前の整え方](https://github.com/stablyai/orca/blob/035588e9/src/main/ipc/worktree-logic.ts)に倣い、Unicodeの文字・数字と `._-` を残す。他の連続記号をハイフン、連続ドットを1つにし、先頭末尾のドットとハイフンを除く。絵文字の辞書変換は行わない。整えた名前をprefixなしのブランチ名にし、main worktreeと同じ親フォルダーの `〈リポジトリ名〉-〈名前〉` に作る。空欄なら `worktree-〈8桁の16進の印〉` を作り、ブランチは `iori/worktree-〈印〉`、フォルダーは `〈リポジトリ名〉-worktree-〈印〉` とする。既存のブランチ・フォルダーと重なる場合は上書きせず、名前を直せるよう知らせる。

作成の結果が不明な時は実Gitと照合し、自動で作り直さない。

### 作成後に実行するコマンド

依存の導入や無視設定したファイルの複写など、新しいworktreeに毎回要る準備を、リポジトリごとに1つのコマンドとして設定できる。値は[ワークスペースの設定の「Git」](settings.md#ワークスペースのgit)に保存し、そこで見て変えられる。作成のダイアログにも同じ名前の「worktree作成後に実行するコマンド」の欄を置き、保存した値を出す。ダイアログで変えた値は、worktreeを作る時にワークスペースの設定へ保存する。空なら何も流さない。設定はioriの中に置き、リポジトリへファイルを置かない（類似製品のファイルの形式は製品ごとに違い、共通の決まりが無い。Hostごとの設定なのでOSごとの書き分けも要らない）。ioriはコマンドを足さない。「この場所で」では流さない。

コマンドは、新しいworktreeで始めるCLI・チームの親のタブの中で、そのHostのTerminalの既定のシェルが流す。作業ディレクトリは新しいworktreeで、環境変数 `IORI_ROOT_PATH` にmain worktreeのパスを渡す（例: `pnpm install && cp "$IORI_ROOT_PATH/.env" .`）。出力はそのタブにそのまま見え、成功（終了コード0）したら同じタブでCLI・チームが始まる。失敗したらCLI・チームを始めず、出力を残してタブのそばに失敗と終了コード、「再実行」「このまま開始」を表示する。worktreeは残し、自動で作り直さない。

チームの子の `delegate --worktree new` でioriが作るworktreeにも同じコマンドを流す。子のCLIはコマンドの成功の後に始まる。失敗したら子のCLIを始めず、子の失敗として親へ知らせ、出力を子の画面に残す。`parent` と既存のworktreeでは流さない。

worktreeを削除する時に流すコマンドは持たない。

子の場所は親Agentが `delegate` の `worktree` に `new` / `parent` / 既存のworktree名を指定して決める。役割の設定に場所の欄は置かない。ユーザーはAGENTS.mdやhooksで親の判断を制御できる。

`delegate --worktree new` は親の現在のHEADを起点にする。名前は題名をASCIIの英数字とハイフンへ整え、24文字以内で単語の途中で切らない所（最後のハイフンの前。24文字以内に切れ目が無い時は24文字）までにしたもの（何も残らない時は `worker`）に8桁の16進の識別子を足す。ブランチは `iori/〈題名のASCII名〉-〈印〉`、フォルダーはmain worktreeと同じ親フォルダーの `〈リポジトリ名〉-〈題名のASCII名〉-〈印〉` に置く。既存のブランチ・worktreeのGit一覧とフォルダーに重なる時は、識別子を変えて作る。既存worktreeは、そのリポジトリのGit一覧にあるフォルダー名またはブランチ名で選ぶ。同名が複数ある時は別の一意な名前で選ぶ。

### 別のリポジトリに子を置く

共通ライブラリを作りながら、それを使う別のリポジトリへ適用する時のように、親の会話から別のリポジトリで子を動かせる。親は `delegate` に `--repo PATH` を付ける。PATHは同じHostのGitリポジトリのパスで、絶対パスか、親の会話を始めたフォルダーからの相対パスで書く。シェルで `cd` した後の今のフォルダーは基準にしない。ioriでそのリポジトリを開いている必要はない。リポジトリの中のどのフォルダーを指しても、そのリポジトリとして扱う。Gitリポジトリでない時は委譲せず、理由をコマンドの答えで返す。

`--repo` は `--worktree new` と既存のworktree名と組み合わせる。`new` はリポジトリの「＋」の既定と同じ起点（`origin/main`、無ければ `origin/HEAD` が指すブランチ、それも無ければmain worktreeの今のブランチ）から、上の `delegate --worktree new` と同じ名前の規則で作り、そのリポジトリの[作成後に実行するコマンド](#作成後に実行するコマンド)を流す。既存のworktree名は、そのリポジトリのGit一覧から選ぶ。`--worktree parent` とは組み合わせず、組み合わせた時は委譲しない。

子は親の会話に属し、報告・質問・`send`・`finish`・Board・Recordsは同じリポジトリの子と同じに扱う。`finish` で削除できる条件も[子のworktreeを削除する](#子のworktreeを削除する)と同じで、削除するのはioriがその子のために作ったworktreeだけにする。サイドバー・Files・Gitでの見せ方は[画面の構成と移動](workspace-layout.md)と[Files View](files-view.md#画面の構成)に従う。そのリポジトリをioriで開いていれば、作ったworktreeはそのリポジトリの下にも通常のworktreeとして並ぶ。

子はチームを持てず、孫へ委譲しない。ユーザーも子の下にworktreeを作れない。新しいworktreeはリポジトリの「＋」から作り、起点には子のブランチも選べる。

## 会話を開く

会話の開始・再開は[CLIの画面](cli-screen.md)に従う。

1つのworktreeには、ユーザーが話す主担当の会話を1つ置く。チームの子は同じworktreeでも動き、サイドバーの子として出る。停止したWorkerとレビュー中のReviewerの会話も別のAgentタブで並べられる。

## Gitでないフォルダーにチームを付ける

子は同じフォルダーで動き、worktreeの操作やGit初期化の確認は出さない。編集の衝突は親へ通知する。

## 子のworktreeを削除する

親Agentが `finish` で残すか削除するかを指定する。削除できるのはioriがその子のために `new` で作ったworktreeだけで、既存のworktreeは残す。同じタスクの続きの子がioriの作ったworktreeを引き継ぐ時は、その所有も引き継ぐ。同じworktreeを別の子が使っている間も削除しない。ioriは自動では削除せず、Gitの取り込み判定を削除の条件にしない。未コミット・未追跡の変更がある時は、親が「変更ごと捨てる」を明示した時だけ削除し、子の会話へ残す。そのworktreeで、子以外のTerminalがCLIを実行中か、シェルでコマンドを実行中の時は削除せず、親へ1行（`A Terminal opened in this worktree is still running. Use --worktree keep.`）で返す。プロンプトで待っているだけのTerminalは、サイドバーからの削除と同じく閉じてから削除する。

`.gitignore` で除外されたファイル（依存やbuildの出力）はGitと同じくworktreeと一緒に削除される。Gitで消した後に残ったファイルも消す。消せなかった時は `finish` を失敗として、残ったパスを理由に返す。

## worktreeを削除する

サイドバーのworktreeの行の右クリック（スマホは長押し）のメニューの「worktreeを削除」から削除する。この項目と「Mergedのworktreeを削除…」にはゴミ箱のアイコンを付ける。main worktree（リポジトリ本体）には出さず、「サイドバーから削除」だけを使える。Agentがシェルで削除した場合もサイドバーから外れる。

確認画面には、削除するかどうかの判断に要るものだけを出す。上に「〈worktreeの名前〉を削除します。」と書き、その下に次の節を、該当するものがある時だけこの順に置く（削除されるものを先に、止めるものを後に）。名前はサイドバーと同じ表示方法にする。どれも無ければ、その1行と「キャンセル」「削除」だけになる。

- 「未commitの変更は削除されます」（警告）: 未コミット・未追跡の変更があるworktree（このworktreeと一緒に削除する子のworktree）ごとに、名前とファイル数。
- 「どのブランチにもないcommitは削除されます」（警告）: HEADが分離していて、どのブランチ・タグ・リモートのブランチからも辿れないコミットがあるworktree（一緒に削除する子のworktreeを含む）ごとに、名前とコミットの数。ブランチが無いのでチェックは置かず、削除するとそのコミットはどの参照からも外れる（Gitのreflogに残る間は戻せる）。
- 「mainにないcommitがあるブランチ」: 一緒に削除するworktreeのうち、取り込み済みでなく作ってからのコミットがあるブランチごとに、名前とmainに無いコミットの数と「ブランチも削除する」のチェック（初めはオフ）。チェックした行には、そのコミットが削除されることを表示する。
- 「実行中の作業を停止します」: 作業中・承認待ち・質問待ちのCLIとチームの子ごとに、名前と状態。入力待ちや終わったCLI・Terminal・子は、止めても失うものが無い（会話の原本はCLIの保存場所に残る）ので出さない。

パス、取り込み済みであること、止めても失うものが無いCLI・Terminal・子、一緒に削除する子のworktreeの一覧は出さず、詳細を開く操作も置かない。確認は1回にし、「削除」を押せば削除する。一緒に削除するのはioriがその子のために作ったworktreeだけで、既存・共有のworktreeは残して子のCLIだけ止める。残したい子の変更は、先に親へ取り込ませる。

削除を確定すると、そのworktreeと子のCLI・Terminalを止めてから、子のworktree、そのworktreeの順に削除する。未コミット・未追跡の変更は確認のとおり捨てる。`.gitignore` で除外されたファイルもGitと同じくworktreeと一緒に削除される。Gitで消した後に残ったファイルも消す。Gitがlockで拒否した時は解除せず、理由を表示する。Windowsではファイルを開いているプログラムがあれば何も削除せず、閉じてからやり直すよう知らせる。

「削除」を押すと確認画面を閉じ、削除はHostが背景で進める。完了を待たずに元の画面で作業を続けられる。削除中のworktreeの行（一緒に削除する子のworktreeの行も）は、先頭のアイコンをスピナーに替えて名前を薄くし、押せず、メニューも出さない。その下に並ぶCLI・Terminal・子のAgentの行も薄くして押せなくするが、スピナーは置かない。「削除中」はHostが持ち、再読み込みや別の端末でも同じ表示になる。見ていたworktreeが削除中になった時は、main worktreeへ移る（押した端末は押した時点で）。確認画面を閉じたら、表示中のTerminalへ焦点を移す。取り消しの操作は置かない。

完了すると行を外し、知らせは出さない。失敗すると行を元に戻し、失敗した対象の名前を題に、対処を本文にしたトーストを閉じるまで残す。Hostは削除の前にCLI・Terminalを閉じるので、失敗の後の行の下にそれらは残らない。閉じたものがあった時は、そのことも本文に添える。入力を奪わないよう確認画面は自動で開かず、トーストの「再試行…」から開く。確認画面には前回の失敗の理由を、アイコンを付けて他の節より前に出す。一緒に削除する子だけが消えて親が残る時は、親の行だけを戻す。worktreeは消えてブランチだけ削除できなかった時は、再試行を置かずに知らせる。

Gitがlockで拒否した時は、Gitの原文ではなくlockの理由と解除の方法を出す。それ以外のGitの失敗は原文を畳んで添える。トーストは押した端末にだけ出し、再読み込みや別の端末へは持ち越さない（行はHostの状態で元に戻り、もう一度削除すれば理由が分かる）。削除の要求をHostへ送れなかった時は、行を戻してトーストを出す。送った後に接続が切れた時は、接続が戻ってHostの状態が分かるまでスピナーを続け、失敗と扱わない。

ブランチは、取り込み済み（下の「取り込みの判定」）またはworktreeを作ってからのコミットが無い時は一緒に削除する。それ以外は残し、確認画面で「ブランチも削除する」をチェックした時だけ削除する。

削除したworktreeの会話と子の行はサイドバーから削除し、ioriからは読めなくなる。CLI自身の会話の原本はCLIの保存場所に残る。表示を閉じただけではworktreeを削除しない。

削除の結果は元の実体と照合する。元の実体が削除されていれば完了、同じ実体が残っていれば削除失敗として、ユーザーがもう一度削除できるようにする。同じ削除操作を自動でやり直さない。

## 取り込み済みのworktreeを削除する

リポジトリの行のメニューの「Mergedのworktreeを削除…」で、取り込み済みのworktreeをまとめて削除する。開いた時にリモートを取得（`git fetch`）してから判定する。取得に失敗しても手元の参照で判定し、古い可能性があることを知らせる。

候補は、取り込み済みで、未コミット・未追跡の変更が無く、CLIが作業中・承認待ち・質問待ちでないworktreeとし、チェックを入れて並べる。ユーザーがチェックを解除したもの以外を「削除」で削除する。確認画面は、上にチェックの入った候補の数で「N件のworktreeを削除します。」と書き、各候補はチェックとworktreeの名前の1行にする。候補は失うものも止める作業中の仕事も無いので、注記・詳細は出さない（1つ削除する時の確認と同じ考え方）。入力待ちなど開いたままのCLI・Terminal・チームの子は一緒に止める。作っただけでコミットの無いworktreeと、判定できないworktreeは候補に出さない。削除方法とブランチの扱いは1つ削除する時と同じにする。

一緒に削除する子のworktreeが1つでも候補の条件を満たさない親は、候補に出さず、1つずつの「worktreeを削除」で扱う。親と子がともに候補なら親の1項目にまとめ、子は親と一緒に削除する。親が候補でない時は、条件を満たす子を単独の候補に出す。親が候補なら、ioriがその子のために作り、作成後のコミットと未コミット・未追跡の変更が無い子も一緒に削除してよい。

## 取り込みの判定

worktreeを作ってから1つ以上のコミットがあり、その内容が `origin/main`（作成の既定の起点と同じ決め方）または手元の同名のブランチに全部入っている時を取り込み済みとする。merge commit・squash merge・rebaseのどれで取り込んでも、試しに合わせた結果（`git merge-tree`）が取り込み先と変わらなければ取り込み済みとする。取り込み先がその後に同じ行を変えて試しの合わせ方がぶつかる時のため、作ってからのコミットが全部、中身の同じコミットとして取り込み先にある時（`git cherry` の判定）も取り込み済みとする。チームの子のworktreeは、親が `finish` で受け入れ（accept）、その時のコミットからHEADが進んでおらず、子のコミットが全部、取り込み先のコミットと対になる時（`git range-diff` の判定。ぶつかりを直して中身が変わっていても対になる）も取り込み済みとする。対になるコミットは作者名・メールアドレス・作者日時が一致するものに限る。受け入れただけでまだ取り込んでいない子は取り込み済みにしない。作成時の起点は、ioriが作ったworktreeでは作成時に記録し、それ以外はブランチの作成の記録（reflog）から読み取る。起点が分からない時は判定できないものとする。

作ってからのコミットにmerge commitがある時は、各mergeが2つの親を持ち、再度自動で合わせた結果との差（`git show --remerge-diff`）が空の場合だけ、git cherry と git range-diff の判定を使う。mergeで足した内容がある時や確認できない時は使わない（どちらもmerge commitを見ないので、mergeで足した内容を見落とす）。

取り込み済みのworktreeは、サイドバーの行に「Merged」の表示を出す。
