# 設定

設定はどの画面にも重ねられるモーダルで開く。項目を指さずに開いた時（サイドバーの左下の歯車など）は一番上の「一般」を開き、Hostの行の歯車や更新の印のように項目を指して開いた時はその項目を開く。左の一覧には小さく薄い「この PC」「Host」「ワークスペース」の見出しを置く。スマホでは[チームの編集画面](team-editor.md)と同じく、上端に1行の帯を置いて右に閉じる（×）を置き、その下に一覧を全画面で出す。項目を押すと詳細を全画面で開き、帯の左に戻る操作と現在地（「自宅PC › 接続」など）を置く。一覧・詳細ともに帯の下から始め、×と中身を重ねない。端末の戻る操作は詳細から一覧、一覧から設定を閉じる順に戻る。「Host」の下には、まず「iori Hostを追加する」のボタンを1か所だけ置き（[iori Hostを用意する画面の入口](host-setup-screen.md#置き場所と流れ)を開く）、その下にHostを選ぶ選択部品を1つだけ置く。Hostが何台でも一覧の長さを変えない。選択部品のすぐ下に、選んだHostの接続、端末、連携、バージョンを置き、選択部品と項目の間に別の部品を挟まない。「ワークスペース」の下には、選んだHostで開いたワークスペース（サイドバーに並ぶリポジトリとGitでないフォルダー）を選ぶ選択部品を1つだけ置き、その下に「Git」を置く。AIエージェントとチームは設定に置かず、サイドバーの[AI Agents/Teams](agents-and-teams.md)で扱う。「この PC」には一般、表示、通知、キーボードを置く。キーボードはスマホのClientだけに表示し、PCには表示しない。各項目には細いアイコンを付け、通常の前景色で表示する。見出しは押せない行としてアイコンを付けない。選択中の項目は背景と太字、ホバーは背景で示す。Hostを切り替えても選択中の項目を保ち、内容をそのHostへ替える。端末の招待もHostの区画から開く。このPCのWindows Hostの「接続」では[ほかの端末からの接続の許可](host-install-update.md#ほかの端末からの接続を許可するwindows)を扱う。

「一般」の更新欄では、端末ごとの「開発バージョンを受け取る」を切り替える。既定はオフで、保存と更新確認の動きは[Clientの自己更新](client-update.md#確認と知らせ)に従う。

「通知」では判断待ちと完了をそれぞれオン・オフでき、Androidでは「バックグラウンドで接続を保つ」（既定オフ）も同じ画面に置く。詳細な動線は[接続](connection.md)に従う。

「表示」で画面とTerminalの文字サイズを別々に変更し、端末ごとに保存する。既定値は[共通の文字の段](visual-style.md#書体と文字の段)に従い、Terminalの変更は開いているTerminalとCLIの画面にもすぐ反映する。「右クリック」は「メニュー」（既定）と「コピー／貼り付け」から選ぶ。その下の「リンクを開く」は、出力のURLとパスを開く操作を「クリック」（既定）と「Ctrl+クリック」から選ぶ。スマホ（AndroidのClient）では、右クリックが無くリンクはタップで開くので、この2つを出さない。操作は[Terminal](terminal.md#読む続ける)に従う。サイドバーのworktreeの行の[PR・CIの印](git-view.md#画面の構成)を出すかを切り替え、既定は出す。タブのダブルクリックによる最大化は既定でオンとし、PCやスマホの広い配置などDockのタブが出る配置で使える。Hostの既定shellはHost設定で選べる。

設定の保存は[保存の仕方](ui.md#保存の仕方)に従う。スイッチと選択はすぐ保存し、文字の欄（接続先、Relay、worktree作成後に実行するコマンド、remoteのWebサイトなど）は節の末尾の「保存」かEnterで保存する。RelayのURLとアクセストークンのように一緒に変える欄は、同じ節で一度に保存する。

Hostの「連携」（英語の表示はIntegrations）では、GitHubの `gh` のログインの状態と、Forgejo・Giteaのサイトごとのtokenを扱う。中身は[Forgeとの連携](forge.md#連携の設定)に従う。

### ワークスペースの「Git」

ワークスペースごとの設定は、そのHostに保存する。サイドバーのワークスペースの行のメニューの「ワークスペースの設定…」から、そのワークスペースの「Git」を直接開ける。Gitでないワークスペースの「Git」には「このワークスペースはGitリポジトリではないため、Gitの設定はありません。」とだけ示す。Gitリポジトリのワークスペースには次を置く。

- **worktree作成後に実行するコマンド**: [worktreeを作った後に流すコマンド](worktrees.md#作成後に実行するコマンド)。作成のダイアログでも同じ値を見て変えられ、ダイアログで変えた値はworktreeを作る時にここへ保存する。
- **remoteとWebサイト**: そのリポジトリのremoteを、名前・URLと、ioriが使うWebサイトとともに並べる。Webサイトが自動で決まったremoteは「GitHub」「Forgejo（https://…）」のように示す。決まらなかったremote（`~/.ssh/config` の別名など）にはWebサイトのURLの欄を出す。入れたURLはremoteのホスト名ごとに保存し、同じホスト名のremoteを持つ他のワークスペースでも同じURLを使う。欄の下に「`forgejo` を使う他のワークスペース（…）にも同じURLを使います」と示す。URLはhttpかhttpsで、保存するのはoriginだけにする。欄を空にすると登録を消す。[PR・CIの印](git-view.md#画面の構成)と[Forgeの画面](forge.md)のForgeの判定に使う。
- **GitHubのアカウント**: GitHubのremoteを持つワークスペースだけに出す。既定は「自動」で、使うアカウントを次の順で決め、「自動（sskksk1）」のように実際に使っているアカウントを示す。リポジトリの持ち主（`github.com/〈持ち主〉/…`）と同じ名前のアカウントがHostの「連携」のGitHubにあればそれを使う。無ければ `gh` の有効なアカウントで読み、そのアカウントで読めない（権限が無い・見つからない）時は他のアカウントで順に試し、読めたアカウントを覚えて次から使う。どのアカウントでも読めない時は印を出さない。Hostの「連携」のGitHubに並ぶアカウントを自分で選ぶこともでき、選んだ時はそれを使う。tokenは保存せず、画面・記録に出さない。

「接続」には、選んだHostをこのClientの一覧から外す「一覧から外す」を置く。確認と再登録は[接続](connection.md)に従う。

各項目の操作と確認は[接続](connection.md)、[Hostの導入と更新](host-install-update.md)、[Terminal](terminal.md)を参照する。

Windowsでは「この PC」の「一般」に「ウィンドウを閉じたら終了する」を置く。切っている時は、窓を閉じるとClientを通知領域へ隠して動かし続ける。LinuxとAndroidには置かない（Linuxは窓を閉じるとClientを終了する）。Client更新の入口は「この PC」の「一般」に置く。更新を見つけた時の印は、設定を開く入口と「一般」の項目に表示する。Hostの更新の印は[ClientからのHostの更新](host-update.md#更新先と知らせ)に従う。動作は[Clientの自己更新](client-update.md)に従う。

初期化・撤去・保存データ削除などの確認では、削除・停止されるものと残るものを短い文で示し、ファイル名の一覧は出さない。

Hostの更新とClientの自己更新は、それぞれの更新操作から実行する。Clientの更新欄で「接続中の iori Host も更新する」を選んでいると、Clientの更新の後に続けて接続中のHostを更新する（[Clientの自己更新](client-update.md#hostとの関係)）。

## Hostのアンインストール

Hostの「バージョン」で再起動の後に、表示名を使った「「〈名前〉」の iori Host をアンインストールする」を置く。Mobileでは実行操作を出さず、「iori Hostのアンインストールは、PCのioriから操作してください。」と案内する。

確認は一画面にまとめ、題名を「iori Hostをアンインストール」、上の1行を「〈名前〉 のiori Hostをアンインストールします。」とし、その下に「開発ファイル、CLI本体の会話・設定・認証、iori Hostの保存データは残ります。」と示す。「iori Hostの保存データも削除する」は既定で選ばず、選んだ時だけ下の文を「端末の登録・作業記録・tokenなどiori Hostの保存データも削除します。開発ファイルとCLIの会話・設定・認証は残ります。」に変える。

中断される作業は[再起動の確認](host-restart.md#確認)と同じ「中断される作業」の節で、応答中・承認待ち・質問のCLIとコマンドが動いているTerminalだけを名前と状態で並べ、対象を開けるようにする。中断される作業がある時は「止めてアンインストールする」、ない時は「アンインストールする」で進め、「キャンセル」で閉じる。止める対象があることを理由に押せなくしない。

手順ごとに見えるものは次のとおり（[UIの定義](ui.md)の「時間のかかる操作の流れ」）。

- 「バージョン」を開いた時: そのHostにつながっている時だけ「アンインストールする」を押せる。iori が自動でつなぎ直している間は、撤去の行に「接続中」と示して押せない。
- 「アンインストールする」を押した時: 確認の画面をすぐ開く。中断される作業の節は、Hostから読む間「確認中」と示す。
- 確認の画面で進めた時: 同じ画面のまま段階を示し（「作業を停止中」「アンインストール中」）、始まった後は「キャンセル」を出さない。
- 停止後の結果をSSHで読むHostで、OpenSSHがパスワード等を求めた時: 同じ画面に「〈ユーザー〉@〈接続先〉のパスワード」（passphraseの時はその鍵）の欄を出す。送信したら欄を閉じて「確認中」に替える。
- 終わった時: 設定のモーダルを閉じ、右下の知らせ（Hostを追加した時と同じ部品）に「「〈名前〉」のiori Hostをアンインストールしました。」、保存データも消した時は「「〈名前〉」のiori Hostと保存データを削除しました。」と出す。停止後の結果を直接読めないHostでは「「〈名前〉」のiori Hostのアンインストールを開始しました。」と出す。別のHostの画面へ移らない。
- 失敗した時: 確認の画面に残り、失敗した段と理由、「再試行」を示す。撤去後の一覧と保存の扱いは[Hostの撤去](host-install-update.md#撤去)に従う。
