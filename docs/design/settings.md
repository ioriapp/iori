# 設定

設定はどの画面にも重ねられるモーダルで開く。項目を指さずに開いた時（サイドバーの左下の歯車など）は一番上の「一般」を開き、Hostの行の歯車や更新のインジケーターのように項目を指して開いた時はその項目を開く。左の一覧には小さく薄い「この PC」「Host」「ワークスペース」の見出しを置く。スマホでは[チームの編集画面](team-editor.md)と同じく、上端に1行の帯を置いて右に閉じる（×）を置き、その下に一覧を全画面で出す。項目を押すと詳細を全画面で開き、帯の左に戻る操作と現在地（「自宅PC › 接続」など）を置く。一覧・詳細ともに帯の下から始め、×と中身を重ねない。デバイスの戻る操作は詳細から一覧、一覧から設定を閉じる順に戻る。「Host」の下には、まず「iori Hostを追加する」のボタンを1か所だけ置き（[iori Hostを用意する画面の入口](host-setup-screen.md#置き場所と流れ)を開く）、その下にHostを選ぶ選択部品を1つだけ置く。Hostが何台でも一覧の長さを変えない。選択部品のすぐ下に、選んだHostの接続、デバイス、連携、バージョンを置き、選択部品と項目の間に別の部品を挟まない。「ワークスペース」の下には、選んだHostで開いたワークスペース（サイドバーに並ぶリポジトリとGitでないフォルダー）を選ぶ選択部品を1つだけ置き、その下に「Git」を置く。AIエージェントとチームは設定に置かず、サイドバーの[AI Agents/Teams](agents-and-teams.md)で扱う。「この PC」には一般、表示、通知、キーボードを置く。キーボードはスマホのClientだけに表示し、PCには表示しない。各項目には細いアイコンを付け、通常の前景色で表示する。見出しは押せない行としてアイコンを付けない。選択中の項目は背景と太字、ホバーは背景で表示する。Hostを切り替えても選択中の項目を保ち、内容をそのHostへ替える。デバイスの招待もHostの区画から開く。このPCのWindows Hostの「接続」では[ほかのデバイスからの接続の許可](host-install-update.md#ほかのデバイスからの接続を許可するwindows)を扱う。

「一般」の更新欄では、デバイスごとの「開発バージョンを受け取る」を切り替える。既定はオフで、保存と更新確認の動きは[Clientの自己更新](client-update.md#確認と知らせ)に従う。

「通知」では判断待ちと完了をそれぞれオン・オフでき、Androidでは「バックグラウンドで接続を維持」（既定オフ）も同じ画面に置く。詳細な動線は[接続](connection.md)に従う。

「表示」で画面とTerminalの文字サイズを別々に変更し、デバイスごとに保存する。既定値は[共通の文字の段](visual-style.md#書体と文字の段)に従い、Terminalの変更は開いているTerminalとCLIの画面にもすぐ反映する。「右クリック」は「メニュー」（既定）と「コピー／貼り付け」から選ぶ。その下の「リンクを開く」は、出力のURLとパスを開く操作を「クリック」（既定）と「Ctrl+クリック」から選ぶ。スマホ（AndroidのClient）では、右クリックが無くリンクはタップで開くので、この2つを出さない。操作は[Terminal](terminal.md#読む続ける)に従う。サイドバーのworktreeの行の[PR・CIのアイコン](git-view.md#画面の構成)を出すかを切り替え、既定は出す。タブのダブルクリックによる最大化は既定でオンとし、PCやスマホの広い配置などDockのタブが出る配置で使える。Hostの既定シェルはHost設定で選べる。

PCでは「表示」と「Terminalのフォント」の間に「新しいworktreeの配置」を置き、今の配置の保存と既定への復帰を行える（保存する対象は[画面の構成と移動](workspace-layout.md)のとおり）。

「表示」の節の後ろに「Terminalのフォント」の節を置く。「フォントの名前」はラベル、説明、入力の順で節の幅いっぱいに並べ、末尾の右の「保存」か、候補を選んでいない時のEnterで保存する。複数の名前はカンマで区切り、前後の空白を除いてデバイスごとに保存する。既定は空で、placeholderは「JetBrains Mono」。保存した値は開いているTerminalとCLIの画面にすぐ反映する。保存の結果はボタンの左の決まった場所に出し、失敗しても入力を残す。Windows・LinuxのPC Clientでは、欄への焦点でインストール済みのファミリー名の候補を表示する。最後のカンマの後ろの名前で大文字・小文字を区別しない部分一致で絞り、選ぶとその部分だけを置き換える。完全一致・一致なしでは一覧を出さず、選択だけでは保存しない。一覧を開いた時と文字を打った時はどの候補も選ばれておらず、上下の矢印かマウスで選んだ候補だけをEnter・クリックで欄に入れる（WAI-ARIAのcomboboxの手動の選択）。一覧の上にマウスを動かしても一覧は閉じない。Escは一覧だけを閉じる。候補は上下の空間に合わせて開き、約6件を超える時は中でスクロールする。Android・狭い幅・web・候補の取得失敗では入力だけを使える。

設定の保存は[保存の仕方](ui.md#保存の仕方)に従う。スイッチと選択はすぐ保存し、文字の欄（接続先、Relay、worktree作成後に実行するコマンド、リモートのWebサイトなど）は節の末尾の「保存」かEnterで保存する。RelayのURLとアクセストークンのように一緒に変える欄は、同じ節で一度に保存する。

Hostの「連携」（英語の表示はIntegrations）では、GitHubの `gh` のログインの状態と、Forgejo・Giteaのサイトごとのトークンを扱う。中身は[Forgeとの連携](forge.md#連携の設定)に従う。

### ワークスペースの「Git」

ワークスペースごとの設定は、そのHostに保存する。サイドバーのワークスペースの行のメニューの「ワークスペースの設定…」から、そのワークスペースの「Git」を直接開ける。Gitでないワークスペースの「Git」には「このワークスペースはGitリポジトリではないため、Gitの設定はありません。」とだけ表示する。Gitリポジトリのワークスペースには次を置く。

- **worktree作成後に実行するコマンド**: [worktreeを作った後に流すコマンド](worktrees.md#作成後に実行するコマンド)。作成のダイアログでも同じ値を見て変えられ、ダイアログで変えた値はworktreeを作る時にここへ保存する。
- **リモートとWebサイト**: そのリポジトリのリモートを、名前・URLと、ioriが使うWebサイトとともに並べる。Webサイトが自動で決まったリモートは「GitHub」「Forgejo（https://…）」のように表示する。決まらなかったリモート（`~/.ssh/config` の別名など）にはWebサイトのURLの欄を出す。入れたURLはリモートのホスト名ごとに保存し、同じホスト名のリモートを持つ他のワークスペースでも同じURLを使う。欄の下に「`forgejo` を使う他のワークスペース（…）にも同じURLを使います」と表示する。URLはhttpかhttpsで、保存するのはoriginだけにする。欄を空にすると登録を削除する。[PR・CIのアイコン](git-view.md#画面の構成)と[Forgeの画面](forge.md)のForgeの判定に使う。
- **GitHubのアカウント**: GitHubのリモートを持つワークスペースだけに出す。既定は「自動」で、使うアカウントを次の順で決め、「自動（sskksk1）」のように実際に使っているアカウントを表示する。リポジトリの持ち主（`github.com/〈持ち主〉/…`）と同じ名前のアカウントがHostの「連携」のGitHubにあればそれを使う。無ければ `gh` のアクティブなアカウントで読み、そのアカウントで読めない（権限が無い・見つからない）時は他のアカウントで順に試し、読めたアカウントを覚えて次から使う。どのアカウントでも読めない時はアイコンを出さない。Hostの「連携」のGitHubに並ぶアカウントを自分で選ぶこともでき、選んだ時はそれを使う。トークンは保存せず、画面・記録に出さない。

「接続」には、選んだHostをこのClientの一覧から削除する「一覧から削除」を置く。確認と再登録は[接続](connection.md)に従う。

各項目の操作と確認は[接続](connection.md)、[Hostの導入と更新](host-install-update.md)、[Terminal](terminal.md)を参照する。

Windowsでは「この PC」の「一般」に「ウィンドウを閉じたら終了する」を置く。切っている時は、窓を閉じるとClientを通知領域へ隠して動かし続ける。LinuxとAndroidには置かない（Linuxは窓を閉じるとClientを終了する）。Client更新の入口は「この PC」の「一般」に置く。更新を見つけた時のインジケーターは、設定を開く入口と「一般」の項目に表示する。Hostの更新のインジケーターは[ClientからのHostの更新](host-update.md#更新先と知らせ)に従う。動作は[Clientの自己更新](client-update.md)に従う。

初期化・撤去・保存データ削除などの確認では、削除・停止されるものと残るものを短い文で表示し、ファイル名の一覧は出さない。

Hostの更新とClientの自己更新は、それぞれの更新操作から実行する。Clientの更新欄で「接続中の iori Host も更新する」を選んでいると、Clientの更新の後に続けて接続中のHostを更新する（[Clientの自己更新](client-update.md#hostとの関係)）。

## Hostのアンインストール

Hostの「バージョン」で再起動の後に、名前「iori Hostをアンインストール」、説明「〈名前〉からiori Hostのプログラムと自動起動の登録を削除します。」、ボタン「アンインストールする」の行を置く。再起動の行は説明を「〈名前〉のiori Hostを再起動します。」、ボタンを「再起動する」とする。接続の状態は題名の下に「〈名前〉 · 接続中」のように1行で表示し、接続されていない間は再起動とアンインストールのボタンを押せない（行ごとに状態を書かない）。Mobileでは実行操作を出さず、行の名前の下に「PCのioriからアンインストールしてください。」と表示する。

確認・進み具合・結果は一つのダイアログで行い、題名は「iori Hostのアンインストール」で固定する（[UIの定義](ui.md)の「ダイアログの高さ」）。題名の下の1行には、流れの間ずっと〈名前〉を表示する（接続されていない時は「〈名前〉 · 接続中」）。本文の1行目に「〈名前〉のiori Hostをアンインストールしますか？」、その下に「このHostを使っているすべてのデバイスから接続できなくなります。」、補足の色で「iori Hostのプログラムを削除し、自動起動の登録を解除します。CLIの設定からioriが追加した項目を削除します。開発ファイルと、CLIの会話・設定・ログイン情報は残ります。」と表示する。「iori Hostの保存データも削除する」は既定で選ばず、その下に「デバイスの登録・作業記録・Forgejo・Giteaのトークンを削除します。選択しない場合は残ります。」を常に表示する（選んでも上の文は替えない）。

中断される作業は[再起動の確認](host-restart.md#確認)と同じ「中断される作業」の節で、応答中・承認待ち・質問のCLIとコマンドが動いているTerminalだけを[再起動の確認](host-restart.md#確認)と同じ行の部品で名前と状態（Running・Approval・Question）を並べ、行全体を押して対象を開けるようにする。無い時は節を残して「中断される作業はありません。」と表示する。中断される作業がある時は「停止してアンインストールする」、ない時は「アンインストールする」で進め、「キャンセル」で閉じる。止める対象があることを理由に押せなくしない。

手順ごとに見えるものは次のとおり（[UIの定義](ui.md)の「時間のかかる操作の流れ」）。

- 「バージョン」を開いた時: そのHostに接続している時だけ「アンインストールする」を押せる。iori が自動で再接続している間は、題名の下に回るインジケーターと「接続中」を表示して押せない。確認の画面を開いている間に切れた時も、題名の下に同じ形で表示する。
- 「アンインストールする」を押した時: 確認の画面をすぐ開く。中断される作業の節は、Hostから読み込む間「確認中」と表示し、読み込めなかった時は理由と「再試行」を表示する。
- SSHで導入したHostで進めた時: 始める前に保存したSSH接続先へ接続する。OpenSSHがパスワード等を求めた時は、確認の本文を非表示にして、同じ画面に「〈ユーザー〉@〈接続先〉のパスワード」（passphraseの時はその鍵）の欄と「送信」を出す。取り消しは下端の「キャンセル」で、ダイアログを閉じる。送信したら欄を閉じて段の一覧に替える。
- SSHで接続できない時、または認証に失敗した時: 失敗と理由の下に、補足の色で「SSHを使わずにアンインストールした場合、iori Hostの削除が完了したかどうかは表示されません。」と「SSHを使わずにアンインストールする」（「アンインストールする」と同じ危険の見た目）を置く。押すと招待だけで登録したHostと同じく、段の一覧（「ioriの設定を削除」「作業を停止」「iori Hostのプログラムを削除」）を表示してから「〈名前〉のiori Hostのアンインストールを開始しました。」で終える。
- 確認の画面で進めた時: 同じ画面のまま、題名の下に〈名前〉の1行と、段の一覧（「ioriの設定を削除」「作業を停止」「iori Hostのプログラムを削除」「結果を確認」。[撤去](host-install-update.md#撤去)の順）を表示し、今の段に回るインジケーターを付ける。始まった後は主ボタンと「キャンセル」を出さず「閉じる」だけを置き、下端の左に「閉じてもアンインストールは続きます。」と表示する。閉じても処理は続き、結果は右下の知らせに出す。閉じた後に注意のある完了で終わった時は「〈名前〉のiori Hostをアンインストールしました。確認が必要な項目があります。」と「詳細」を、止まる前に失敗した時は「〈名前〉のiori Hostをアンインストールできませんでした。」と「詳細」を出す。「詳細」は結果の画面を開き直す。
- 終わった時: 設定のモーダルを閉じ、右下の知らせ（Hostを追加した時と同じ部品）に「〈名前〉のiori Hostをアンインストールしました。」、保存データも削除した時は「〈名前〉のiori Hostをアンインストールし、保存データを削除しました。」と出す。招待だけで登録したHostでは「〈名前〉のiori Hostのアンインストールを開始しました。」と出す。Hostはこのデバイスの一覧から外れ、一覧に残ったHostの最初のものを選んだ画面になる（最後のHostだった時は、Hostが無い時の最初の画面になる）。削除できなかったトークンがある時は、モーダルを閉じずに結果の画面で、1行目に済んだこと、その下に注意のアイコンとWindowsでは「次のサイトのトークンを削除できませんでした。各サイトでトークンを無効にしてから、資格情報マネージャーから削除してください。」、Linuxでは「次のサイトのトークンを削除できませんでした。各サイトでトークンを無効にしてから、キーリングから削除してください。」とサイトの一覧を表示し、「閉じる」で閉じる。 右下の知らせを×で閉じた失敗と、結果の画面を閉じた結果は、見たものとして記録を消し、Clientを起動し直しても出直さない。
- ファイルの一部が残った時: トークンの時と同じ結果の画面で、1行目に「〈名前〉のiori Hostをアンインストールしました。」、注意のアイコンと「iori Hostのファイルの一部を削除できませんでした。」、「残ったフォルダー:」とコピーできるパス、「〈名前〉を再起動してから、〈名前〉でこのフォルダーを削除してください。」（このPCのHostでは「PCを再起動してから、このフォルダーを削除してください。」）を表示する。「再試行」は出さない。
- 止まる前に失敗した時: 同じ画面に段の一覧を残して失敗した段にアイコンを付け、その下に失敗のアイコンと「iori Hostをアンインストールできませんでした。」、できなかったことと理由（例「CLIの設定からioriの項目を削除できませんでした。設定ファイルを変更する権限がありません。」）、「iori Hostはアンインストール前の状態に戻り、そのまま使えます。」、通常の枠の「再試行」を表示する（赤い見出しは置かない）。自動起動の登録を戻せなかった時は、「そのまま使えます」の代わりに「iori Hostは実行中ですが、〈名前〉の再起動後は自動で起動しません。」を表示する。撤去後の一覧と保存の扱いは[Hostの撤去](host-install-update.md#撤去)に従う。
