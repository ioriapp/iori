# 画面の構成と移動

サイドバー、本体、タブ、分割、最大化、Mobileの移動を変える時に読む。対象の作成・削除は[worktreeとフォルダー](worktrees.md)、共通部品は[UIの定義](ui.md)、面の構成は[画面の見た目と言葉](visual-style.md)に従う。

## サイドバーから開く

PCのサイドバーの一番上に、ioriのアイコンと「iori」の行を置き、その下に検索の欄を置く。押しても何も起きず、WindowsのClientではウィンドウのドラッグの場所を兼ねる。スマホのドロワーには置かない（スマホの最初の画面の上端の行の中央に「iori」を出す）。

Hostの見出しとワークスペース（リポジトリ・Gitでないフォルダー）の行は、PCではドラッグして並べ替える。スマホのドロワーでは長押しで持ち上げ、そのまま指で動かして離す。動かさずに離すと行のメニューを開く。普通の縦スクロールでは並べ替えない。持ち上げた行は浮く操作の表示で区別する。ワークスペースは同じHost内だけで動かせ、親子・ブランチの順は変えない。検索中は並べ替えない。

ワークスペースの順はHostへ保存し、PC・スマホで共有する。Hostの順はデバイスごとに保存する。どちらも再起動後に保ち、新しく開いたワークスペースは末尾へ加える。再度開いたワークスペースの位置は変えない。

サイドバーはHost → リポジトリ → 親のworktreeを並べる。各Hostのグループの先頭には固定の行「[AI Agents/Teams](agents-and-teams.md)」を置き、押すとworktreeと同じく本体をその画面へ切り替える。Gitでない対象はHost → フォルダーとして並べる。親の下はブランチ単位で入れ子にし、親と同じworktreeの子は直下、子のworktreeはブランチ行の下に置く。[別のリポジトリの子](worktrees.md#別のリポジトリに子を置く)のworktreeも親の下に置き、ブランチ行の名前を「〈リポジトリ名〉 › 〈ブランチ名〉」とする。worktreeの行はブランチ名を名前として表示し、すぐ上のリポジトリ名を繰り返さない。ブランチが無い時（detached HEAD）は、フォルダー名から先頭の `〈リポジトリ名〉-` を削除して表示する。フォルダー名はツールチップとスマホの長押しのメニューで読める。長い名前は真ん中を省略して先頭と末尾を残し、ツールチップで全文を読める。右端のアイコン（[PR・CI](git-view.md#画面の構成)、マージ済み、折り畳んだ行の要約）は名前より先に縮めない。行の上下には今の動きと経過時間を読める余白を取り、Hostとワークスペース（リポジトリ・フォルダー）のまとまりの間は、まとまりの中の行の間より大きく空けて見分けられるようにする。

「開始」は、CLI・チーム・Terminalを選んで始めるタブで、上に「〈名前〉で開始」（worktreeはサイドバーの行と同じブランチ名、Gitでないフォルダーはフォルダー名）とHost名、検索、その下にCLI・チーム・Terminalを種類ごとの行に並べる。チームの群は、そのHostにチームが1つも無い時は、その旨と[AI Agents/Teams](agents-and-teams.md)を開く入口を出す。始める画面は、このタブの1種類だけにする。初めて開いたワークスペース、タブを全て閉じた後、右・下の分割で開いたペインには、この「開始」のタブを開き、タブ列（「＋」・分割・最大化）を常に出す。PCでは、初めて開くworktreeの配置に、見ているタブとして「開始」を置き、その横に開いた状態のタブとしてFilesとGit（Gitでないフォルダーは Files だけ）を置く。「開始」で選ぶと、そのタブが選んだCLI・チーム・Terminalに置き換わる。チームで始めた時は、開いた状態のタブとしてBoardも足し、見ているタブは会話のままにする。閉じたFiles・Git・Boardは、タブ列の「＋」の一覧の下から開き直す（Boardはチームを付けた会話がある時だけ出す）。既に開いていればそのタブへ移る。保存した配置がある worktree は、その配置をそのまま戻し、タブを足さない。PCではサイドバーのCLI・Terminal・子の行をドラッグして、好きなペインのタブ列や端（分割）へ落として開ける。既に開いている時はそのタブを落とした場所へ移す。CLI・Terminal・子の行は、選択中かどうかに関係なく各worktreeの下に並べる。子を押すとそのAgentタブを本体へ開く。CLIの画面とTerminalの行は、タブを閉じても残り、押すかドラッグすると再びタブとして開く。行から「閉じる」を選ぶと、[Terminalの閉じる操作](terminal.md#閉じる)と同じくプロセスを終えて一覧から削除する。終了した子は畳んで残す。各Hostの行には「フォルダーを追加」の＋と「Hostの設定」の歯車を置く。リポジトリの行には、worktreeを作る「＋」と[Issues](forge.md#issues)のボタンを置く。歯車を押すと、そのHostを選んで設定の「接続」を開く。更新があるHostでは「バージョン」を開く。左下の歯車から全体の設定を開く。

「フォルダーを追加」の画面のHostの選択は、各行のHost名の前にサイドバーと同じ接続の点（接続済み・未接続）を付ける（長い名前の扱いは[UIの定義](ui.md)の選択の欄のとおり）。選んだHostに接続している間は、フォルダーの一覧の場所に回るインジケーターと「接続中」を表示する。接続できなかった時は「Hostに接続できませんでした。Hostが起動していることを確認して、もう一度お試しください。」と「再試行」を表示する。

PCではCLI・Terminal・子の行があるworktreeにリポジトリと同じ開閉のアイコンを付け、既定で開く。検索中はHost・リポジトリと同じく一致するworktreeを開いて行を見せ、検索を解除すると元の開閉へ戻す。中の行が全てなくなっても、選択中のworktreeのビューの入口を残す。通常の開閉はユーザーがそのアイコンを押した時だけ変え、別のHost・リポジトリ・worktreeを選んでも変えない。畳んだworktreeの名前を押した時はそのworktreeを選んで開く。Host・リポジトリ・worktreeの開閉状態は、閉じた行だけをHostの順と同じくデバイスごとに保存し、再起動でも閉じたままにする（VS Codeのエクスプローラーなどと同じ）。新しく現れた行は開いて出す。削除されたworktreeや一覧から削除したワークスペースの記録は自動で捨てる。Gitの一覧を読めない間は、そのリポジトリのworktreeの記録を捨てない。保存に失敗した時は、同じ片付けを繰り返さない。畳んだ行の右側には、動いているCLI・Terminalの種類ごとのアイコンを並べ、同じ種類が2つ以上なら小さな数を添える。幅に収まる先頭の種類だけを並べ、残りの種類数を `+n` にまとめる。種類と数をまとめた要約には状態のインジケーターを付けず、各Agentの状態は開いた行の共通部品で表示する。名前は上のとおり省略し、要約は折り返さない。

PCの配置では、サイドバーの右端の境界をドラッグして幅を変えられる（VS Codeのサイドバーと同じ操作）。境界をダブルクリックすると既定の幅へ戻す。幅はデバイスごとに保存し、再起動でも保つ。幅は行の名前とアイコンを読み取れ、本体にも作業できる余地がある範囲で変えられる。ウィンドウを狭めた時は表示だけ収めて保存した幅は変えない。ドラッグの間はTerminalとCLIへ寸法を送らず、離した時に1回だけ合わせる（ペインの境界と同じ）。ドラッグの間は開閉の動きを止め、幅を指に追従させる。境界はWindows Clientでウィンドウを動かす上端の行と重ねない。スマホのドロワーは対象にしない（タブレット・横向きでPCと同じ配置の時は対象）。

別Hostの対象も並べて開け、一方が切断しても他方を使える。本体の配置は親のworktree（またはGitでないフォルダー）ごとに1つ持つ。別の行を選ぶとその配置へ切り替え、戻ると離れる前の配置を戻す。初めてのworktreeは、PCで新しいworktree用に保存した配置があればその配置で開き、なければ上の「開始」とFiles・Gitのタブの配置で開く。新しいworktreeの配置はデバイスごと・全リポジトリ共通で1つ保存し、Mobileには保存の入口も適用もない。分割の形と大きさ、Files・Git・Board・Issues・CI、チームの子でない最初のCLI（なければ「開始」）の位置、CLIでないTerminalの全タブの位置と選択中のタブを覚える。チームの子のCLI、「ファイル」のタブ、親以外のCLI、同じタブの2つ目以降のパネルは覚えない。CLIの位置には「開始」を置き、CLIの枠がなければ選択中の群に足す。GitはGitリポジトリだけ、Boardは作成時にチームを始めた場合だけ、Issues・CIはサイドバーにIssuesの入口を出せる場合だけ開く。リポジトリの「＋」で作って始めたworktreeでは、Terminalの枠にそのworktreeの既定シェルを新規に開き、コマンドは実行しない。それ以外の初めてのworktreeではTerminalの枠を除いて配置を適用する。開けないタブと空の分割は除き、配置を復元できない時は既定の配置で開く。タブの右クリックの末尾と設定の「表示」から現在の配置を保存でき、設定から既定に戻せる。子は親の配置の中のタブとして開き、本体の配置を切り替えない。別の親を見ている時に子を選ぶと、その子が属する親の配置を戻してから開く。子のworktreeのブランチ行は親の配置内のGitをその子へ切り替えて開く。本体が表示している親の行は太字と左の細い線で表示し、色の付いた背景は本体で見ているタブの行（CLI・Terminal・子）にだけ付ける。

## Windowsのウィンドウ

Windows ClientではOSのタイトルバーを表示せず、サイドバーと上端のペインのタブバーがウィンドウの上端を兼ねる。右上に最小化・最大化／元に戻す・閉じるを置き、右上のタブバーにはその幅を空ける。ウィンドウボタンの色はioriの明暗設定に従う。上端の行の空き領域をドラッグするとウィンドウが移動し、ダブルクリックすると最大化／元に戻す。タブ・ボタン・入力欄はウィンドウのドラッグ対象にしない。最大化ボタンのホバーでWindows 11のスナップレイアウトを使える。端でのサイズ変更とWindowsのショートカットも使える。Androidとブラウザーの配置は変えない。

## タブと分割

配置は開いたタブ、分割、大きさ、選択中のタブをデバイスごとに保存し、再起動でも復元する。Agent、ボード、Files、Git、Terminal、Linked Agentの子、[ファイル](files-view.md#ファイルのタブ)、[CIとIssues](forge.md)をタブで開く。タブ追加、左右・上下分割、最大化の操作をタブバーに置く。タブ追加は、そのHostで見つかったCLIとTerminalの一覧を検索付きで開き、CLIは[AIエージェント](agents-and-teams.md#aiエージェント)の一覧と同じ順に並べる。チームがあれば、CLIの群の下にチームの群を置き、選ぶとそのチームの親を起動する（[Linked Agent](linked-agents.md#チームの会話を始める)）。一覧の最後から「CLIを追加」へ移れる。各タブは選択中とホバーの時に出る×で1回で閉じる。プロセスの終了でタブが自動で閉じる。ただしチームの親は会話を再開できるようタブを残し、「CLIが終了しました」と「再開」を出す（[Linked Agent](linked-agents.md#停止再開通知)）。自動で閉じたタブがペインの最後のタブだった時は、ペインを削除せずに空のペインとして残し、「＋」の一覧を出す（配置はユーザーの操作でだけ変わる）。空のペインの一覧には「ペインを閉じる」を置き、最後の1つのペインでは出さない。タブを閉じてもCLIとTerminalのプロセスは止めない。Terminalは1本につき1タブにする。PCでタブを新しく作る時と、サイドバー・入口からViewを開く時は、開いたViewへ焦点を移し、打ったキーがそのまま届く（VS Codeと同じ）。Mobileは焦点を移さず、キーボードを自動で開かない。直接入力のTerminalの画面は、指でtapすると焦点が移ってキーボードが開く（スクロールのswipeと文字選択の長押しでは開かない）。まとめて入力の画面は、tapでキーボードを閉じ、入力欄をtapすると開く（[スマホでのTerminalとCLIの画面](mobile-terminal.md)）。

タブには種類のアイコン、状態のインジケーター、短い題名を出す。インジケーターと文字は[共通の見た目](visual-style.md)に従う。タブの幅は題名の長さに合わせ、最大の幅を超える時とタブ列の幅が足りない時だけ題名を省略する。タブ列に入らないタブは、タブ列の右端の一覧から選べる。タブ自体に「…」のボタンは置かない。worktree名・役割・題名の全文はツールチップで読める。Terminalはシェルが報告するコマンド名を使える。

タブをドラッグして並べ替え、別ペインへ移し、左右上下の端へ落として分割する。境界をドラッグして大きさを変える。親と子のAgentを左右へ並べられる。移動や分割で下書き・読み位置・実行対象を変えず、配置を保存する。タブ直下に重複する帯は置かない。右・下の分割ボタンは、タブの数にかかわらず、その向きに「開始」のタブを持つペインを開く。今のタブは元のペインに残す。タブを端へドラッグして分割する時は、そのタブを新しいペインへ動かす。

CLIの画面とTerminalは、境界や最大化したペインの端をドラッグしている間、Terminalの寸法を保つ。ドラッグを終えると最終の寸法を一度だけ適用し、そのまま入力を続けられる。

ボード、サイドバー、親の会話の子の行から同じAgentを開ける。既に開いていればそのタブへ移る。子はクリックでもドラッグでも開ける。

## 最大化

全タブで、タブのダブルクリック、最大化ボタン、Ctrl+K Ctrl+M（VS Codeのエディターグループの最大化と同じ）から中央の重ね表示へ広げられる。TerminalとCLI自身の画面に焦点がある時は、Ctrl+KとEscをシェル・CLIへそのまま送り、Escで最大化を閉じない。最大化の切替はダブルクリックとボタンで行う。ダブルクリックは設定でオン／オフにできる。背景は半透明にする。再度の最大化操作、Esc、外側のクリックで元のペイン・タブへ戻る。

同じ表示を移し、読み位置、入力、Terminalの内容を保つ。PTYには表示サイズを伝える。ioriのウィンドウの大きさは変えない。

幅の既定は種類（文章・会話・コード、diff、Terminal・CLIの画面）ごとに持ち、Filesと「ファイル」のタブは文書を広く読むため「幅いっぱい」を既定にする。どの種類でも、最大化した幅は最大化する前のペインの幅より狭くしない。端をドラッグして調整し、種類ごとに記憶する。「幅いっぱい」と記憶した幅を切り替えられ、その選択も種類ごとに記憶する。

## Mobileと戻る操作

Mobileのホームには、Attention、Boards、実行中のAgentがいるworktreeの一覧を順に置く。Boardsは接続中の全Hostから、チームの親の会話が開いているworktreeを集める。作業中の親か子がいるworktreeを先に置き、各グループでは最後の状態変化が新しい順に並べる。行にはworktree、Host、ワークスペース、最後に動いた親の会話、経過時間、状態ごとの件数を表示する。押すと該当するBoardが開き、戻るとホームへ移る。0件の場合は共通の[内容の状態](ui.md#内容の状態)に従う。承認と質問の通知先は[製品仕様](../product.md#判断失敗復帰)に従う。

左上のボタンか左端からのスワイプでサイドバーのドロワーを開く。ドロワーでは先頭にホーム、続けてHostとワークスペースを並べる。worktreeの行を押すと、そのworktreeで前回見ていたビューへ1タップで移り、ドロワーを閉じる。前回のビューがなければAgentを開き、開いている会話がなければ「開始」を表示する。行の主操作と副操作は[共通の一覧](ui.md#画面の骨組み)に従い、親子の会話への直接の入口も使える。

worktreeの画面の上端に現在地、ビュー切替（Agent / Board / Files / Git / Terminal）、同じworktree内のセッション切替を置く。Boardはチームの会話がある場合、GitはGitリポジトリの場合に使える。下端はTerminalのキー帯とソフトウェアキーボードに使い、固定タブを置かない。タブレットなど幅の広い表示ではPCと同じ配置を使える。

ポップオーバー・メニュー・ダイアログが開いている時は、Androidの戻る操作は一番上の1つだけをEscと同じ扱いで閉じ、画面を移動しない。画面内の戻る操作とAndroidの戻る操作は、重なった画面、Files内の移動、実際に訪れたタブの順に戻る。閉じた対象は戻る先から削除する。戻る先がないAndroidではOS標準の操作に任せる。ドロワーから本体に移ったビューも訪問として記録する。訪問履歴はClientを開いている間だけ保持する。

設定やフォルダー選択へ移っても、開いているタブの入力・選択を保つ。幅変更や回転で入力先、読み位置、Host導入の段階を混ぜない。招待は永続保存しない。保存対象の入力を変更した画面から離れるときは[未保存の変更の確認](dialogs.md#未保存の変更)を使う。

FilesとGitの一覧幅はペイン幅と保存比率から調整し、幅変更だけで保存比率を書き換えない。ソフトウェアキーボード表示中も入力と操作へ届く。キーボードが開くと本体の高さが縮み、現在地の行は上に残り、キーの帯がキーボードのすぐ上に来る。Terminalは縮んだ高さに合わせて行数を変え、入力中の行を見える位置に保つ。まとめて入力の欄で書く間にこの行数の変更でCLIの描き直しが乱れると分かったら、行数を変えずに表示だけを最新の行へ寄せる形へ見直す。Mobileの最大化は全画面のまま扱う。
