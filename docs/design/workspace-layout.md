# 画面の構成と移動

サイドバー、本体、タブ、分割、最大化、Mobileの移動を変える時に読む。対象の作成・削除は[worktreeとフォルダー](worktrees.md)、部品と見た目は[UIの定義](ui.md)が持つ。

## サイドバーから開く

Hostの見出しとワークスペース（リポジトリ・Gitでないフォルダー）の行は、PCではドラッグして並べ替える。スマホのドロワーでは長押しで持ち上げ、そのまま指で動かして離す。動かさずに離すと行のメニューを開く。普通の縦スクロールでは並べ替えない。持ち上げた行は面と影で区別する。ワークスペースは同じHost内だけで動かせ、親子・ブランチの順は変えない。検索中は並べ替えない。

ワークスペースの順はHostへ保存し、PC・スマホで共有する。Hostの順はデバイスごとに保存する。どちらも再起動後に保ち、新しく開いたワークスペースは末尾へ加える。再度開いたワークスペースの位置は変えない。

サイドバーはHost → リポジトリ → 親のworktreeを並べる。各Hostのグループの先頭には固定の行「[AI Agents/Teams](agents-and-teams.md)」を置き、押すとworktreeと同じく本体をその画面へ切り替える。Gitでない対象はHost → フォルダーとして並べる。親の下はブランチ単位で入れ子にし、親と同じworktreeの子は直下、子のworktreeはブランチ行の下に置く。[別のリポジトリの子](worktrees.md#別のリポジトリに子を置く)のworktreeも親の下に置き、ブランチ行の名前を「〈リポジトリ名〉 › 〈ブランチ名〉」とする。worktreeの行はブランチ名を名前として表示し、すぐ上のリポジトリ名を繰り返さない。ブランチが無い時（detached HEAD）は、フォルダー名から先頭の `〈リポジトリ名〉-` を削除して表示する。フォルダー名は吹き出しとスマホの長押しのメニューで読める。長い名前は真ん中を省略して先頭と末尾を残し、吹き出しで全文を読める。右端の印（[PR・CI](git-view.md#画面の構成)、Merged、畳んだ行の要約）は名前より先に縮めない。行の上下には今の動きと経過時間を読める余白を取り、Hostとワークスペース（リポジトリ・フォルダー）のまとまりの間は、まとまりの中の行の間より大きく空けて見分けられるようにする。

「開始」は、CLI・チーム・Terminalを選んで始めるタブで、上に「〈名前〉で開始」（worktreeはサイドバーの行と同じブランチ名、Gitでないフォルダーはフォルダー名）とHost名、検索、その下にCLI・チーム・Terminalを群ごとに札で並べる（一覧の「＋」とは別の、大きく押しやすい形）。チームの群は、そのHostでチーム機能がオンの時だけ出す。オンでチームが無い時は、その旨と[AI Agents/Teams](agents-and-teams.md)を開く入口を出す。始める画面は、このタブの1種類だけにする。初めて開いたワークスペース、タブを全て閉じた後、右・下の分割で開いたペインには、この「開始」のタブを開き、タブ列（「＋」・分割・最大化）を常に出す。PCでは、初めて開くworktreeの配置に、見ているタブとして「開始」を置き、その横に開いた状態のタブとしてFilesとGit（Gitでないフォルダーは Files だけ）を置く。「開始」で選ぶと、そのタブが選んだCLI・チーム・Terminalに置き換わる。チームで始めた時は、開いた状態のタブとしてBoardも足し、見ているタブは会話のままにする。閉じたFiles・Git・Boardは、タブ列の「＋」の一覧の下から開き直す（Boardはチームを付けた会話がある時だけ出す）。既に開いていればそのタブへ移る。保存した配置がある worktree は、その配置をそのまま戻し、タブを足さない。スマホのドロワーでは選択中のworktreeの行の下にFiles、Git、Terminal、Board（チームを付けた会話がある場合だけ）の固定入口を置き、押すとそのタブを開き、既にあればそこへ移る。Terminalが複数ある時は最後に使ったものへ移る。PCではサイドバーのCLI・Terminal・子の行をドラッグして、好きなペインのタブ列や端（分割）へ落として開ける。既に開いている時はそのタブを落とした場所へ移す。CLI・Terminal・子の行は、選択中かどうかに関係なく各worktreeの下に並べる。子を押すとそのAgentタブを本体へ開く。CLIの画面とTerminalの行は、タブを閉じても残り、押すかドラッグすると再びタブとして開く。行から「閉じる」を選ぶと、[Terminalの閉じる操作](terminal.md#閉じる)と同じくプロセスを終えて一覧から削除する。終了した子は畳んで残す。各Hostの行には「フォルダーを追加」の＋と「Hostの設定」の歯車を置く。リポジトリの行には、worktreeを作る「＋」と[Issues](forge.md#issues)のボタンを置く。歯車を押すと、そのHostを選んで設定の「接続」を開く。更新があるHostでは「バージョン」を開く。左下の歯車から全体の設定を開く。

「フォルダーを追加」の画面のHostの選択は、各行のHost名の前にサイドバーと同じ接続の点（接続済み・未接続）を付ける（長い名前の扱いは[UIの定義](ui.md)の選択の欄のとおり）。選んだHostに接続している間は、フォルダーの一覧の場所に回る印と「接続中」を表示する。接続できなかった時は「Hostに接続できませんでした。Hostが起動していることを確認して、もう一度お試しください。」と「再試行」を表示する。

CLI・Terminal・子の行があるworktreeには、リポジトリと同じ開閉の印を付け、既定で開く。検索中はHost・リポジトリと同じく一致するworktreeを開いて行を見せ、検索を解除すると元の開閉へ戻す。中の行が全てなくなった場合は開閉状態に関係なく選択中の固定入口を見せる。通常の開閉はユーザーがその印を押した時だけ変え、別のHost・リポジトリ・worktreeを選んでも変えない。畳んだworktreeの名前を押した時はそのworktreeを選んで開く。Host・リポジトリ・worktreeの開閉状態は、閉じた行だけをHostの順と同じくデバイスごとに保存し、再起動でも閉じたままにする（VS Codeのエクスプローラーなどと同じ）。新しく現れた行は開いて出す。削除されたworktreeや一覧から削除したワークスペースの記録は自動で捨てる。畳んだ行の右側には、動いているCLI・Terminalの種類ごとのアイコンを並べ、同じ種類が2つ以上なら小さな数を添える。幅に収まる先頭の種類だけを並べ、残りの種類数を `+n` にまとめる。種類と数をまとめた要約には状態の印を付けず、各Agentの状態は開いた行の共通部品で表示する。名前は上のとおり省略し、要約は折り返さない。

PCの配置では、サイドバーの右端の境界をドラッグして幅を変えられる（VS Codeのサイドバーと同じ操作）。境界をダブルクリックすると既定の幅（360px）へ戻す。幅はデバイスごとに保存し、再起動でも保つ。最小の幅は行の名前と印が重ならない幅（240px）、最大の幅は本体に作業の幅を残す所（窓の幅の半分）までとし、窓を狭めた時は表示だけ収めて保存した幅は変えない。ドラッグの間はTerminalとCLIへ寸法を送らず、離した時に1回だけ合わせる（ペインの境界と同じ）。ドラッグの間は開閉の動きを止め、幅を指に追従させる。境界はWindows Clientで窓を動かす上端の行と重ねない。スマホのドロワーは対象にしない（タブレット・横向きでPCと同じ配置の時は対象）。

別Hostの対象も並べて開け、一方が切断しても他方を使える。本体の配置は親のworktree（またはGitでないフォルダー）ごとに1つ持つ。別の行を選ぶとその配置へ切り替え、戻ると離れる前の配置を戻す。初めてのworktreeは、上の「開始」とFiles・Gitのタブの配置で開く。子は親の配置の中のタブとして開き、本体の配置を切り替えない。別の親を見ている時に子を選ぶと、その子が属する親の配置を戻してから開く。子のworktreeのブランチ行は親の配置内のGitをその子へ切り替えて開く。本体が表示している親の行は太字と左の細い線で表示し、色の付いた背景は本体で見ているタブの行（CLI・Terminal・子）にだけ付ける。

## Windowsのウィンドウ

Windows ClientではOSのタイトルバーを表示せず、サイドバーと上端のペインのタブバーがウィンドウの上端を兼ねる。右上に最小化・最大化／元に戻す・閉じるを置き、右上のタブバーにはその幅を空ける。窓ボタンの色はioriの明暗設定に従う。上端の行の空き領域をドラッグすると窓が移動し、ダブルクリックすると最大化／元に戻す。タブ・ボタン・入力欄は窓のドラッグ対象にしない。最大化ボタンのホバーでWindows 11のスナップレイアウトを使える。端でのサイズ変更とWindowsのショートカットも使える。Androidとブラウザーの配置は変えない。

## タブと分割

配置は開いたタブ、分割、大きさ、選択中のタブをデバイスごとに保存し、再起動でも復元する。Agent、ボード、Files、Git、Terminal、Linked Agentの子、[ファイル](files-view.md#ファイルのタブ)、[CIとIssues](forge.md)をタブで開く。タブ追加、左右・上下分割、最大化の操作をタブバーに置く。タブ追加は、そのHostで見つかったCLIとTerminalの一覧を検索付きで開き、CLIは[AIエージェント](agents-and-teams.md#aiエージェント)の一覧と同じ順に並べる。チーム機能がオンなら、CLIの群の下にチームの群を置き、選ぶとそのチームの親を起動する（[Linked Agent](linked-agents.md#チームの会話を始める)）。一覧の最後から「CLIを追加」へ移れる。各タブは選択中とホバーの時に出る×で1回で閉じる。プロセスの終了でタブが自動で閉じる。ただしチームの親は会話を再開できるようタブを残し、「CLIが終了しました」と「再開」を出す（[Linked Agent](linked-agents.md#停止再開通知)）。自動で閉じたタブがペインの最後のタブだった時は、ペインを削除せずに空のペインとして残し、「＋」の一覧を出す（配置はユーザーの操作でだけ変わる）。空のペインの一覧には「ペインを閉じる」を置き、最後の1つのペインでは出さない。タブを閉じてもCLIとTerminalのプロセスは止めない。Terminalは1本につき1タブにする。PCでタブを新しく作る時と、サイドバー・入口からViewを開く時は、開いたViewへ焦点を移し、打ったキーがそのまま届く（VS Codeと同じ）。Mobileは焦点を移さず、キーボードを自動で開かない。直接入力のTerminalの画面は、指でtapすると焦点が移ってキーボードが開く（スクロールのswipeと文字選択の長押しでは開かない）。まとめて入力の画面は、tapでキーボードを閉じ、入力欄をtapすると開く（[スマホでのTerminalとCLIの画面](mobile-terminal.md)）。

タブには種類のアイコン、状態の印、短い題名を出す。印と文字は[共通の見た目](visual-style.md)に従う。題名は先頭の最大12文字程度にする。タブ列に入らないタブは、タブ列の右端の一覧から選べる。タブ自体に「…」のボタンは置かない。worktree名・役割・題名の全文は吹き出しで読める。Terminalはシェルが報告するコマンド名を使える。

タブをドラッグして並べ替え、別ペインへ移し、左右上下の端へ落として分割する。境界をドラッグして大きさを変える。親と子のAgentを左右へ並べられる。移動や分割で下書き・読み位置・実行対象を変えず、配置を保存する。タブ直下に重複する帯は置かない。右・下の分割ボタンは、タブの数にかかわらず、その向きに「開始」のタブを持つペインを開く。今のタブは元のペインに残す。タブを端へドラッグして分割する時は、そのタブを新しいペインへ動かす。

CLIの画面とTerminalは、境界や最大化したペインの端をドラッグしている間、Terminalの寸法を保つ。ドラッグを終えると最終の寸法を一度だけ適用し、そのまま入力を続けられる。

ボード、サイドバー、親の会話の子の行から同じAgentを開ける。既に開いていればそのタブへ移る。子はクリックでもドラッグでも開ける。

## 最大化

全タブで、タブのダブルクリック、最大化ボタン、Ctrl+K Ctrl+M（VS Codeのエディターグループの最大化と同じ）から中央の重ね表示へ広げられる。TerminalとCLI自身の画面に焦点がある時は、Ctrl+KとEscをシェル・CLIへそのまま送り、Escで最大化を閉じない。最大化の切替はダブルクリックとボタンで行う。ダブルクリックは設定でオン／オフにできる。背景は半透明にする。再度の最大化操作、Esc、外側のクリックで元のペイン・タブへ戻る。

同じ表示を移し、読み位置、入力、Terminalの内容を保つ。PTYには表示サイズを伝える。ioriのウィンドウの大きさは変えない。

幅の既定は種類（文章・会話・コード、diff、Terminal・CLIの画面）ごとに持ち、Filesと「ファイル」のタブは文書を広く読むため「幅いっぱい」を既定にする。どの種類でも、最大化した幅は最大化する前のペインの幅より狭くしない。端をドラッグして調整し、種類ごとに記憶する。「幅いっぱい」と記憶した幅を切り替えられ、その選択も種類ごとに記憶する。

## Mobileと戻る操作

Mobileでアプリを開いた最初の画面には、Attention（PCと同じ。子のCLIの権限承認も含む。子の作業上の質問は親へ届くので出ない）、Boards、Agentが動いているworktreeのRunningをこの順に並べる。Boardsは接続中の全Hostから、チームの親の会話が開いているworktreeを1行ずつ集め、CLIが作業中の親または子を持つBoardを先に置き、その中と残りをそれぞれ最後の状態変化が新しい順に並べる。子が全員報告済みでも親の会話が開いていれば残す。行は、1段目にworktree名・最後の活動からの経過時間・右矢印、2段目にHost名・ワークスペース名・ブランチ（長い時は末尾を省略）、3段目に最後に動いた親の会話の題名、4段目にBoardの子の行と同じ印と言葉で状態ごとの人数を表示する。0人の状態と追加の会話数は出さない。押すとそのworktreeのBoardを全画面で開き、最後に動いた親の会話を選ぶ。戻ると最初の画面へ戻る。0件ならBoardsの見出しと「開いているTeamの会話はありません。」を表示する。子の権限承認の経路は[Linked Agent](linked-agents.md#親への知らせ)に従う。worktreeを開くと上端にサイドバーを開くボタン、worktree名、ブランチを表示する薄い現在地の行を置き、選択したViewを全画面で表示する。最初の画面・worktree・AIエージェント/チームなど、スマホの全画面の上端は左端をサイドバーを開くボタンにそろえ、押せる範囲を48dp相当以上にする。上端に戻るボタンは置かない。移動は左上のボタンまたは左端からのスワイプで開くサイドバーのドロワーから行い、下の固定タブは作らない。Androidの戻る操作は前に見ていたViewへ戻る。ドロワーの先頭には「ホーム」（英語ではHome）をHostの群より上に置く。押すと最初の画面へ移り、ドロワーを閉じる。最初の画面を見ている時は選択中の印を付ける。PCの配置には「ホーム」を置かない。ドロワーはPCと同じ入口と親子のAgentを並べ、どの子へも1回で移れる。worktreeの行を押すと、ドロワーを開いたまま対象を選び、その下の固定入口とCLI・Terminal・子の行を見せる。Viewの入口・CLI・子の行を押すとそのViewへ移り、ドロワーを閉じる。ボードは自動では開かない。縦スクロール、入力、文字選択、View内部の横スクロールを優先する。スマホでも全部の操作を使え、幅が広いタブレットや横向きではPCと同じ配置にする。

画面内の戻る操作とAndroidの戻る操作は、重なった画面、Files内の移動、実際に訪れたタブの順に戻る。閉じた対象は戻る先から削除する。戻る先がないAndroidではOS標準の操作に任せる。ドロワー内でworktreeを選んだだけでは履歴に積まず、ドロワーを閉じて本体を見た時にその対象を訪問として記録する。訪問履歴はClientを開いている間だけ保持する。

設定やフォルダー選択へ移っても、開いているタブの入力・選択を保つ。幅変更や回転で入力先、読み位置、Host導入の段階を混ぜない。招待は永続保存せず、変更した入力から離れる時は[破棄確認](dialogs.md)を使う。

FilesとGitの一覧幅はペイン幅と保存比率から調整し、幅変更だけで保存比率を書き換えない。ソフトウェアキーボード表示中も入力と操作へ届く。キーボードが開くと本体の高さが縮み、現在地の行は上に残り、キーの帯がキーボードのすぐ上に来る。Terminalは縮んだ高さに合わせて行数を変え、入力中の行を見える位置に保つ。まとめて入力の欄で書く間にこの行数の変更でCLIの描き直しが乱れると分かったら、行数を変えずに表示だけを最新の行へ寄せる形へ見直す。Mobileの最大化は全画面のまま扱う。
