# HostとClientの資源の使い方

読むのは、CLIの出力の届け方、ClientのCLIの画面の描画、再接続、定期処理を変える時と、性能の受入をする時である。責任の境界は[技術設計](../architecture.md)、切断時の表示は[Hostとの接続が切れた時の表示](host-recovery.md)が定める。

## ユーザーに対する約束

長い会話、複数の子Agent、逐次の応答、Terminalの大量の出力が同時に流れていても、Clientとの接続は切れず、操作への応答と画面の更新は止まらない。

## 原則

| 原則       | 内容                                                                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 遅い受け手 | 受け手ごとの送信待ちに上限を持ち、超えたらその受け手だけ取り直させる。一台が遅くても、他のデバイスへの配信や承認・停止の要求を待たせない |
| 生存確認   | 生存確認は画面の処理と別の層（ClientのRust側）で返し、画面が忙しいことを切断の理由にしない                                               |
| 重い処理   | 一回の処理を小さくすることを先に行う。残る重い処理は測ってから、必要な分だけ別のthreadへ移す                                             |
| 定期処理   | 定期的な再読み込みをせず、変化をHostから知らせる。隠れた画面は受信と再読み込みを止める                                                   |
| 資源の上限 | メモリに置く出力・送信待ち・一時ファイルには上限と回収の規則を持つ。上限は資源の持ち方であり、会話・回答・ファイルの長さの上限ではない   |

## 目標値

次の負荷試験で満たす。

| 項目                         | 目標                                         |
| ---------------------------- | -------------------------------------------- |
| Hostのevent loopの遅れ       | 最大100 ms以下、p99 50 ms以下                |
| Clientから見た生存確認の往復 | p99 200 ms以下                               |
| 切断                         | 試験中に0回                                  |
| Hostのメモリ                 | 試験の後半が前半から増え続けない（10%以内）  |
| Clientの画面の処理           | 長い会話への逐次応答中も1回の処理が50 ms以下 |

## 負荷試験

実際のCLIやモデルを使わず、CLIの出力を予定時刻どおりに出す偽のCLIを、本物のPTYの経路へ接続する。

- 同時に流す負荷: 親のCLIの大量出力、子の会話4本の逐次応答、Terminalの大量出力。
- 試験用のClientはHostと別のプロセスで動き、実際の通信で、普通に使うClientと同じ画面の構成（親・子・ボード・一覧・Terminal）を並行して開く。開く・閉じる・開き直すの後に、余分な受信が残っていないことも確かめる。
- 記録する値: Hostのevent loopの遅れ（最大・p50・p99と時系列）、CPU、メモリ、Clientから見た生存確認の往復、切断の回数と理由。結果はJSONで出し、目標値との比較を表示する。
- 既定の実行は1分とし、性能に関わる変更の時とRelease前に専用のコマンドで流す。性能の受入はこの試験で行い、実機での長時間試験はしない。
