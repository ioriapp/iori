# Terminal

シェルの選択、入力、出力、閉じる操作を変える時に読む。配置は[画面の構成と移動](workspace-layout.md)、CLIとの会話は[CLIの画面](cli-screen.md)が持つ。

Terminalの画面・履歴・VTのモードを持つemulatorはデーモンだけで動かす。Hostはデーモンから出力と解析済みのOSC・CSI、現在のモードを受け取り、作業ディレクトリ・タイトル・CLIの状態と入力を判断する。再接続での状態の受け渡しと問い合わせへの応答は[Terminalデーモン](terminal-daemon.md#状態と通信の責任)に従う。

## 開く

既存のTerminalを選ぶか、新規作成でシェルを選ぶ。作成時の場所を記録したTerminalはそのworktreeまたはフォルダーに所属し、シェル内で別のフォルダーへ移動しても一覧と判断待ちの入口は同じ所属先に残る。作成時の場所の記録が無い既存Terminalは、現在のcwdで結び付ける。Linuxはbash / zsh / fish、WindowsはPowerShell / cmdなど、Hostで利用できるシェルを使う。既定はOSの既定で、Hostの設定から変更できる。WindowsでGit Bashも選べる。

1本につき1タブで開き、Terminal内に縦タブを置かない。表示のフォーカス中はTabを含め通常のキーをシェルへ送る。Mobileは、TerminalとCLIの画面の下にキーの帯を置く。既定はEsc・Ctrl・Alt・Tab・Enter・Shift+Tab・Space・Backspace・Del・矢印・Ctrl+C/D/L/Z/R/A/E/W/Uを横にスクロールする1列で並べ、表示・非表示と並べ替え、修飾キーとの組合せや決まった文字列のキーの追加ができる（Orcaのスマホのアプリと同じ）。帯の先頭には、直接入力とまとめて入力の切替と、画面の幅の切替を置く。入力欄・修飾キー・画像・選択・ピンチ・スクロールの追従などスマホの操作は[スマホでのTerminalとCLIの画面](mobile-terminal.md)に従う。TerminalとCLIの画面では、切断中に打った・押したキーを貯めて後から送らない。

日本語などのIMEで入力した文字は、確定した文字を欠けも重なりもなく一度だけ送り、変換の候補はカーソルの位置に出す。変換を確定するEnterをCLIへ送らない。

スマホで開くと画面はスマホの幅になり、PCでその画面を開くかクリック・入力するとPCの幅に戻る。どちらのデバイスも入力を止めず、取り戻すための操作は要らない。スマホでPCの幅のまま読みたい時は、キーの帯の幅の切替で縮小表示にする。

新しいTerminalは、実行中のTerminalが最後に使ったPCの寸法のうち、最も列数の多いものから始める。実行中のTerminalが無い時は保存済みのTerminalから同じように選び、記録が無い時は80列・24行で始める。行数は選んだTerminalの値を使う。

Androidのアプリが背面へ回るとTerminalの受信を閉じ、前面へ戻るとHostが保持した画面から自動で開き直す。背面・前面や通信の再接続、送信待ちのあふれによる自動の開き直しでは大きさの持ち主を変えず、ユーザーが開くか操作した時だけ移す。保存画面からの正常な開き直しでは警告を出さず、開き直しに失敗した時だけ対象のそばへ案内を出す。

## 読む・続ける

設定の「Terminalのフォント」で指定した名前は、カンマで分けて各名前をCSSの文字列として引用し、その後ろに既定のフォントの並び（末尾のSymbols Nerd Font Monoとmonospaceを含む）を付ける。空の時は既定の並びだけを使う。保存後はフォントの読み込みが終わったら文字の画像を作り直して再描画し、文字の幅に合わせてTerminalの寸法も合わせ直す。

Terminalの16色（ANSI色）は、明るい表示ではVS CodeのLight+、暗い表示ではDark+の既定値を使い、テーマの変更に追従する。[VS CodeのTerminal色の定義](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/terminal/common/terminalColorRegistry.ts)を出典とする。背景・通常の文字・カーソル・選択はioriの共通の色に合わせる。

出力の履歴はHostが保持し、さかのぼって読める。Clientが切れている間の出力も、接続復帰後に続きから表示する。サイズ変更、非表示、デバイスの引き継ぎで入力先・カーソル・プロセスを保つ。

Hostの再起動で前のシェルが終わった時は、前の画面を残し、その下に「Hostの再起動で前のシェルは終了しました」の区切りを出して、同じフォルダーで新しいシェルを始める。新しいシェルは、そのTerminalをどれかのデバイスで表示した時に始め、表示していないTerminalは開くまで始めない。

CLIの画面では、Hostの再起動やTerminalのデーモンの停止で失われたCLIの最後の画面を残し、下端の1行に「CLIが中断されました」と「再開」「閉じる」を表示する。「再開」は、表示時に始めた新しいシェルでCLI自身の再開コマンドを実行して同じ会話を開く。会話IDが無い時は元のコマンドで起動し直す。自動ではCLIを再開しない。「閉じる」はそのTerminalの画面・履歴・一覧項目を閉じる。

保持した出力を検索し、前後の一致へ移動できる。検索はCtrl+Shift+Fと、画面の右クリック（スマホは長押し）のメニューから開く。メニューにはコピー・貼り付け・検索（スマホではさらに「テキストとして選択」）を置き、タブに「…」のボタンは置かない。設定の「右クリック」で「コピー／貼り付け」を選ぶと、選択がある時はコピーして選択を解除し、無い時は既存の貼り付け操作を行う。どちらの設定でもCLIがマウス報告を求めている間は右クリックをCLIへ渡し、Ctrl+右クリックでメニューを開く。Shift+右クリックはCLIのマウス報告を飛ばし、設定どおりにメニューまたはコピー／貼り付けを行う。スマホの長押しは設定にかかわらずメニューを開く。検索を開いていない時のCtrl+Fはシェルへ送る。出力をテキストで選択・コピーできる。CLIは応答を左に余白を付けて描く（Claude Code・Codexは2文字、OpenCodeは5文字、Piは1文字）ので、コピーする時は、選んだ行のうち空でない全行に共通する行頭の空白だけを削除する（Orcaの「Trim Gutter on Copy」と同じ）。字下げの差は残り、行の途中から選んだ時や左端から始まる行を含む時は何も変えない。1行だけ選んだ時は行頭の空白をすべて削除する。コピーのボタン・メニュー・キー（Ctrl+C・Ctrl+Shift+C・Ctrl+Insert・右クリックのコピー）のすべてに同じく当てる。スマホの「テキストとして選択」はOSの選択でコピーするので対象外。選択がある時のCtrl+Cはコピー、無い時はシェルへ送る。Ctrl+Vで貼り付け、Ctrl+Shift+C・Ctrl+Shift+Vも使える（Windows Terminalと同じ）。PCでは、出力のURLを修飾キー無しの左クリックで既定のブラウザーで開く（WezTerm・kittyのURLと同じ）。ioriでは出力のファイルのパスも同じクリックで開く。Ctrl+クリックでも開く。Alt+クリック・Shift+クリックはリンクを開かず、カーソルの移動、選択に使う。誤って開かないよう、右・中クリック、ドラッグで選択した時、押す前か離した時に選択がある時、ダブルクリック・トリプルクリックの2回目以降、Terminalに焦点が無い時のクリック（別のペインやタブのボタンから焦点を移すクリック）では開かない（1回目のクリックは待たずに開く）。別のアプリからioriのリンクを直接クリックした時は開く。CLIがマウス報告を求めている間も、リンクの上のクリックはリンクを開き、そのクリックをCLIへ送らない。リンク以外の場所のクリック・ドラッグ・ホイールはCLIへ送る。設定の「リンクを開く」で「Ctrl+クリック」を選ぶと、Ctrl+クリックだけで開く。リンクの下線と手のカーソルは、その場で開ける時だけ出す（Terminalに焦点が無い時・選択がある時は出さず、Ctrlを押している間は出す。「Ctrl+クリック」の設定の時はCtrlを押している間だけ）。対象は、絶対パス、`~/` で始まるパス、作業ディレクトリ（シェルが知らせた時はそれ、無ければそのTerminalを始めたフォルダー）からの相対パスで、末尾の `:行`・`:行:列` も読む。Hostに実在するファイルだけをリンクにし、フォルダーと見つからないパスはリンクにしない。開く先は[Files View](files-view.md#パスから開く)に従う。スマホではURLとパスのリンクをタップで開く（[スマホでのTerminalとCLIの画面](mobile-terminal.md#リンクを開く)）。

画像の貼り付けと保存は[添付](attachments.md)に従う。

タブを閉じるだけではプロセスを止めない。シェルが正常に終了した（`exit`など）時はTerminalを閉じる。エラーで終了した時は、画面と「終了しました（コード N）」を残し、ユーザーが閉じるまで読むだけで残す（Windows Terminal・VS Codeと同じ）。

## 閉じる

Terminalの操作は「閉じる」とし、画面・履歴・一覧項目を削除する。シェルの中でコマンドが動いている時だけ、プロセスの終了と履歴削除を一度確認する。シェルが入力を待っている時は確認せずに閉じる。状態が分からない時も閉じる操作を使え、状態だけを理由に警告しない。Hostが元のプロセスを操作できる場合は終了してから閉じ、操作できなくなった場合は保存済みの画面・履歴・一覧項目を閉じて、新しいTerminalを作れるようにする。別のプロセスを推測で停止しない。閉じる操作の結果は照合し、同じ操作を自動でやり直さない。実際に失敗した時は対象のそばへ失敗と回復操作を表示する。他のTerminal・会話・開発ファイルは変更しない。
