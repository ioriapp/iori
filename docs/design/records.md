# Records

Recordsは、チームで回した委譲の記録を見返し、役割ごとの候補（CLI・モデル・Effort）を入れ替える・時間と費用を比べる判断に使う画面である。この文書は、Recordsの置き場所・集計・一覧・経緯を作る・変える時に読む。記録する値は[チーム](teams.md#記録)が正本である。

## 置き場所

設定の「AI Agents/Teams」のHostごとのツリーで、AIエージェント・チームと同じ段にRecordsを置く。チームを横断して見て、絞り込みでチームを選ぶ。チームは複製して組み替えるので、チームごとに分けると同じ候補の比較が散らばるためである。削除したチームの記録も残り、絞り込みに出す。

## 集計

上部の1行で、期間（7日・30日・90日・すべて・日付を指定、既定30日）、Team（すべて・各チーム）、Version（Teamを選んだ時だけ。すべて・各バージョン）、Difficulty（すべて・High・Medium・Low）で絞り込む。「日付を指定」では開始日と、任意で終了日を選び、その日の始まりから終わりまで（Clientの地域の日付）を含める。選んだ絞り込みはその端末にHostごとに覚え、次にRecordsを開いた時も同じ絞り込みで開く（Hostへは保存しない）。0件の時、絞り込みがあれば全部を「すべて」にする操作を、無ければチームで委譲すると記録が残ることを示す。

役割ごとの見出しの下に、候補（CLI・モデル・Effort）ごとの行を置く。役割は名前でまとめる。

| 列        | 値                                                              | 数え方                   |
| --------- | --------------------------------------------------------------- | ------------------------ |
| Candidate | CLI、モデル・Effort                                             |                          |
| Tasks     | タスクの件数                                                    | タスクの最初の担当の候補 |
| Agents    | その候補が担当した子の数（途中から引き継いだ子を含む）          | 子ごと                   |
| 初回受入  | 差し戻し0回で受け入れたタスクの件数と率（`7/9 · 78%`）          | タスクの最初の担当の候補 |
| Revisions | その候補の子が担当中に受けた差し戻しの数 ÷ その候補の子の数     | 子ごと                   |
| Rejected  | 不採用のタスクの件数                                            | タスクの最初の担当の候補 |
| Time      | 子ごとの作業時間（[チーム](teams.md#記録)）の中央値             | 子ごと                   |
| Input     | 子ごとの入力トークン（キャッシュの読み・書きを含む）の中央値    | 子ごと                   |
| Output    | 子ごとの出力トークン（CLIが出力として数えた推論を含む）の中央値 | 子ごと                   |
| Cache hit | キャッシュ読みの合計 ÷ 入力の合計（`82%`）                      | 両方が取れた子だけ       |

件数の少ない候補も同じ形で出し、件数から読み手が判断する（注記や警告は足さない）。トークン量が取れた子が一部だけなら `310k（6件）` のように取れた件数を添え、1件も無ければ値を出さない。Cache hitも同じく、取れた子が一部だけなら件数を添える。判定前のタスクは初回受入・Rejectedの分母に入れない。

PCでは本体の幅いっぱいの表にし、列の見出しで並べ替えられる。初回受入の列には率を小さな横棒でも示す。スマホでは表を候補ごとのカードの縦並びにし、列の名前と値を2列で示す。

## 比較の図

役割ごとの見出しの下、表の前に、その役割の候補を比べる散布図を置く。1点が1候補で、縦は初回受入の率、横は時間の中央値、点の大きさはTasksの件数を表す。横の軸は集計の行に置く切替でTime（時間の中央値）とTokens（入力＋出力の中央値）を選べ、全役割の図に効く。点のそばに候補の番号を小さく示し、表の候補の行（スマホはカード）の先頭に同じ番号を付ける。番号は役割ごとに表の既定の並びで振り、並べ替えても変えない。点に触れる・押すと吹き出しで候補の名前と値を読める。点が重なる時は番号を並べ（`3·5`）、吹き出しに全候補を並べる。点を押すと表の行を押した時と同じ一覧を開く。判定済みのタスクが無い候補、横の値が無い・0の候補は図に出さず、表には残す。左上ほど速く・少ないトークンで差し戻されずに受け入れられた候補になる。スマホでは図を幅いっぱいにしてカードの前に置く。番号は作業面の色で縁取って目盛りの線と重ねない。横軸は対数の目盛り（1・2・5の系列。`1m 2m 5m 10m`、`10k 20k 50k`）にし、切りのよい値まで伸ばして点の半径分の余白を取る。図の幅は960pxまで、図に出る候補が1つの時は低くする。目盛りの文字は単位の区切りと10倍を先に出し、余裕がある時だけ2・5を足す。番号の文字だけがぶつかる時は、円はそれぞれの位置に描き、番号をまとめる。吹き出しの各候補の先頭にも番号を付ける。

## 一覧

行を押すと、右（スマホでは次の画面）にその候補が担当したタスクの一覧を出す。各行は日付、題名、チームとVersion、Difficulty、Revisions、判定と理由、時間、変更、トークン量を示し、途中から担当したタスクには Handoff を付ける。時間・変更・トークン量はタスク全体の値を使う。トークン量は取れた子の合計を示し、一部だけならBoardのまとめと同じく人数を添える（`410k（2人分）`）。1人も取れなければ出さない。

## 経緯

タスクを押すと、Delegated（時刻・役割・候補・Difficulty）、Revise（時刻・その時の担当・差し戻しの本文）、Handoff（新しい子と候補）、Accepted・Rejected（時刻・理由）を時系列に並べる。本文が長い時は最初の数行を示して展開できる。下に、子の最後の画面と、残っていれば親の会話を開く操作を置く。子のタブを閉じた後も、Terminalの記録が残る子の最後の画面を開ける。Terminalの記録がない時は、その操作を出さない。[Board](board.md#agents)の経緯と同じ部品を使う。
