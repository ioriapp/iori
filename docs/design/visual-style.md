# 画面の見た目と言葉

配色、面、書体、動き、スタイルの実装基盤を変えるときに読む。共通部品は[UIの定義](ui.md)、配置と移動は[画面の構成と移動](workspace-layout.md)に従う。

## 色と面

ライトとダークは、サイドバーの土台、フラットな作業面、浮くモーダル・ポップオーバーの3層を使う。セクションと一覧行は1pxの罫線（ヘアライン）、余白、文字の強弱で区切る。作業面上のカードと影は廃止し、影は浮く層に使う。暗幕は背景を暗くし、重ねて開いたときは下のモーダルも覆う。

枠や薄い色面を使うのは次の3つに限る。

- 対応が必要なAttention、失敗の詳細、未保存の変更の強調。ごく薄い状態色と1pxの枠、6pxの角丸を使い、影は付けない。
- ボタン、入力欄、コマンド枠、差分チップなどの操作・入力部品。ボタン、入力欄、バッジ、小枠の角丸は4〜6pxにそろえる。
- 浮くモーダル・ポップオーバー。角丸は8pxにそろえる。

本文と補助文字は載る面に合わせた色を使う。アクセント色は主ボタン、選択、フォーカス、スイッチのオンに使い、状態色と区別する。状態や操作は色だけに依存せず、文字・形・下線などでも区別する。

## スタイルの実装基盤

Tailwind CSS v4と自己完結したshadcn/ui部品を使う。色、余白、角丸、影、暗幕、重ね順（`z-index`）の6段階（通常・固定表示・ドロワー・ポップオーバー・モーダル・通知）、`rem`の文字サイズのトークンは`index.css`に集約する。

画面ごとのグローバルCSS、`!important`での上書き、CSS内の固定`px`での`font-size`指定は、Dockviewとxterm.jsの最小の連携部分に限る。UI全体の文字、余白、部品の大きさはルートの文字サイズを基準に`rem`で比例させる。倍率とTerminalの文字サイズの操作は[設定](settings.md#表示サイズ)に従う。

## 書体と文字の段

画面はInterと同梱のNoto Sans JPを使い、他の言語に必要な文字はOSの書体で補う。等幅はコード、コマンド、パス、差分、Terminalなどに使う。TerminalとCLIの画面ではOSの日本語等幅フォントと同梱のSymbols Nerd Font Monoも使う。

見出しは太さで本文から区別し、補足は小さく控えめに表示する。同じ役割の文字は、サイドバーと作業面で同じ段を使う。長いコマンドやパスを表示する枠では、横にスクロールして全文を読めるようにする。

## 状態のインジケーターと動き

サイドバー、タブ、BoardのAgentsでは共通の状態部品を使う。実行中は緑の丸、判断が必要な状態は琥珀、失敗は赤、停止・待機中は灰色、完了はチェックで表示する。状態名は[用語集](wording.md#状態と件数)に従い、インジケーターは読み上げ名を持つ。CLIは公式のアイコンを使う。未読の完了と注意音（BEL）は、行とタブの題名を太字にし、対象を開くと通常の表示に戻す。

動きは実行中や進行中を示すために使う。実行中の丸やPlanの`TextShimmer`、応答待ちのインジケーターは、OSの動きを減らす設定では静止させ、状態は引き続き表示する。

## 画面の言葉

画面のラベル、読み上げ名、状態、件数、説明は、ユーザーが選んだ表示言語にそろえる。固有名詞とCLI・Gitの専門用語は[用語集](wording.md)に従う。ユーザーやAgentが書いた本文・題名・名前はそのまま表示する。
