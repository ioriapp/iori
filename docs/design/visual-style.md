# 画面の見た目と言葉

配色、面の層、書体、文字の段、状態の印、画面の言葉を変える時に読む。部品の選択は[UIの定義](ui.md)、配置と移動は[画面の構成と移動](workspace-layout.md)が持つ。

## 色と面

モーダルの背景は暗くするだけにし、ぼかさない。重ねたモーダルでは下のモーダルも暗幕（`--modal-scrim`）で覆う。

Linear型の、面の明るさの段差で層を分ける低彩度の画面にする。灰色にはアクセントと同じ色相を薄く混ぜる。サイドバーを土台にし、本体は余白を挟んだ角丸の作業面として一段明るくする。モーダルとポップアップはさらに一段明るい面と弱い黒い影で区別し、白い光の影は出さない。ライトでもサイドバーはわずかに灰色、作業面は白とし、同じ層を保つ。サイドバーの面はアプリのサイドバーとタブ列だけに使う。タブの中の一覧・ツリー（Files・Git・Issuesなど）は作業面に置き、境目の線と選択中の行で区切る。スマホで全画面に出す画面（設定・チームの編集など）は、一覧と詳細のどちらも作業面にする。

罫線はタブ列の下や分割の境目など必要な箇所に絞る。枠や帯を重ねて面を細分化しない。ただし設定や編集の画面の節は、まとまりを示すために角丸の薄い面で1段だけ囲む（[画面の骨組み](ui.md#画面の骨組み)）。色は共通のトークン（名前を付けた色の定義）で持ち、部品ごとに直接指定しない。文字の色は置かれた面の組（面と、その面の上の文字）で選び、主ボタンの上のキー表示などは面の文字の色を薄くして使い、別の面の補助文字の色を持ち込まない。

アクセントは落ち着いた青1色で、主ボタン、選択中の印、フォーカスの輪だけに使う。リンク、スイッチのオン、数字、役割には使わない。スイッチのオンは前景色で示す。状態色はアクセントと分け、diffの追加・削除には状態色の緑・赤を薄く使う。Filesの本文のsyntax highlightの色（`--syntax-*`）は内容の色で、アクセントと状態色の決まりの外に置く。検索の一致の強調の上では、syntax highlightの色を使わず前景色にする。

OKLCHは明るさ・彩度・色相で色を指定する形式である。灰色の彩度は0.004〜0.010程度に抑え、面の差と文字の読みやすさを保つ。

状態色を文字・アイコンに使う時は、前景色と混ぜずに文字用のトークン（`--status-running-text` など）を使う。混ぜるとライトでは黒で濁り、ダークでは白で白っぽくなる。状態色は、載る面（作業面・サイドバー・カード・モーダル）に対して、丸などの形で3:1以上、文字で4.5:1以上になる明度にし、くすまないよう彩度を保つ（WCAG 2.2の1.4.11・1.4.3）。

## 書体と文字の段

画面はInter、日本語は同梱のNoto Sans JPを使う。Noto Sans JPで不足する中国語・韓国語の文字はOSの書体で補い、追加の書体は同梱しない。WindowsではMicrosoft YaHei UI・Microsoft JhengHei UI・Malgun Gothic、Androidでは端末のNoto Sans CJKを使う。等幅の日本語は、WindowsではBIZ UDゴシック、Androidでは端末のNoto Sans Mono CJK JPを使い、無い時は同梱のNoto Sans JPで補う。

等幅はコード、コマンド、パス、diff、Terminalだけに使う。題名、ブランチ名、状態語、数字だけを理由に画面全体を等幅にしない。進捗や使用量の数字は桁の幅を揃えられる。

文字サイズは既定16pxで、[設定](settings.md)から端末ごとに変更する。本文を通常の前景色で最も読みやすくし、見出しは太さで区別する。補足と補助情報は本文より小さく薄くする。時刻、使用量、親の判定を本文より強く見せない。Markdownの見出しは本文から見分けられる段を付ける。サイドバーの主な文字と補足はBoardの同じ役割の文字と同じ段を使い、どちらも設定の文字サイズに連動する。TerminalとCLIの画面は既定14px、行の高さは1.25とし、画面の文字とは別に設定する。

## 状態の印と動き

一覧の中のAgent（サイドバー、タブ、BoardのAgents）は共通の状態部品を使う。役割を表す色の四角は置かない。CLIのアイコンは各CLIの公式のアイコンを色付きのまま使う。

| Agentの状態 | 印                   |
| ----------- | -------------------- |
| 実行中      | 緑の丸、ゆっくり点滅 |
| 判断待ち    | 琥珀の丸、静止       |
| 失敗        | 赤の丸、静止         |
| 停止・待機  | 灰の丸、静止         |
| 完了        | 灰の小さな✓          |

CLIの画面は、実行中・判断待ち・完了・停止の印を持つ。応答中は実行中、承認待ちと質問は判断待ち、CLIの終了は停止として示す。まだ見ていない完了と注意音（BEL）は、行とタブの題名を太字にし、開くと戻す。

ForgeのCIの印は、通過を緑、失敗を赤、実行中を灰の点線の丸で示す。琥珀は判断待ちの色なので使わず、点線を太くしてIssuesのボタン（`CircleDot`）と形で見分ける。

点滅するのは実行中のAgentの丸だけである。Hostの接続状態、ボトムバーの接続済み、最新のpushの印は点滅させない。タブの印は固定の枠へ収め、丸と✓などの切替でタブ幅と文字位置を変えない。状態は色だけに頼らず、意味を読み上げられる名前を持つ。

Planのタスクの印は[Board](board.md#plan)に従う。動きを減らすOSの設定では点滅、光、回転を止め、状態の切替は表示する。画面移動のトランジションはサイドバーの開閉、吹き出し、最大化に絞る。画面の中の折り畳み（サイドバーのworktreeと子のFinished、BoardのFinished・Cancelled・Activityの「Show all」、Records、CIのSteps、委譲の履歴など）は、どれも同じ短い動きで高さを開閉する。FilesのフォルダーとGitの節のように、長い一覧の中の開閉は即座に切り替える。開閉で縦のスクロールバーが現れても中の幅が変わらないよう、開閉のある縦スクロールの面はスクロールバーの幅を常に取っておく。更新・再起動など、終わるまで待つ進行中の表示には、静かに回る小さな印を付け、動きを減らす設定では止める。

## 画面の言葉

UIの文字は、ユーザーが選んだ表示言語（英語・日本語）で画面全体を揃える。最初はOSの言語に合わせ、設定の「表示」でOSに合わせる・English・日本語から選ぶ。会話本文、ユーザーやAgentが書いた題名・タスク名、チーム名は内容としてそのまま表示する。CLI・OS・Gitが定義した用語と識別名（許可・権限・sandbox・worktreeなど、ユーザーが英語のまま慣れているもの）は、日本語の画面でも訳さず英語のまま出し、ioriの独自の用語に置き換えない。AIエージェント開発の用語で、日本人にも分かる簡単な英単語で言えるもの（Attention・Board・Files・Git・Terminal・Plan・Agent・Team・Automation・Running・Accepted・Tokensなど）も、日本語の画面で英語のまま出す。文の中でも同じで、「エージェント」「チーム」「ターミナル」「自動化」と書かない（例:「Teamを削除しますか？」）。Gitの語（commit・remote・fetch・upstream）と認証の token も英語のままにする。半端なカタカナや和訳にしない。一般の操作（開く・保存・編集など）と説明の文は日本語にし、簡単な英単語が無いもの（初回受入など）は日本語にする。日本語は普通の日本人が使う言葉にする（「版」でなく「バージョン」、「利用者」でなく「ユーザー」、「確かめる」でなく「確認する」）。操作できない表示に「読むだけ」のような断り書きを付けない。

日本語の文の書き方は次にそろえる。

- 失敗の文は「〜できませんでした。〜してください。」にする。促しは「再試行してください」を基本にし、操作を言える時は「もう一度保存してください」のようにする。「お試しください」「やり直してください」は使わない。今の状態の説明は「〜できません」。
- 操作の中止は「キャンセル」、編集を戻すのは「元に戻す」、登録や権限を無効にするのは「取り消す」。
- 操作の進み具合の表示（取得・展開・インストールなど）は「〜しています」にし、「〜中」にしない。状態を説明する文の「実行中」「確認中」などはこれに当たらない。
- 文は「。」で終える。ラベル・見出し・ボタン・短い状態には付けない。確認の題は「〜しますか？」。
- 日本語と英字・数字の間に空白を入れない（Windowsの正式な名前「この PC」と、等幅で示すコマンド・パスを除く）。数は算用数字（1回・1件）、通知や項目の助数詞は「件」。カタカナ語は語尾の長音を付ける（フォルダー・プロバイダー）。
- OS・Android・ブラウザー・VS Codeに同じ操作の標準の文言がある時はそれに合わせる（アプリの使用中だけ許可、再読み込み、元に戻す、ベースブランチ、現在の変更・入力側の変更）。「接続する」「インストール」を使い、「つながる」「導入」は使わない（操作の名前の「iori Hostを用意する」は除く）。
- 状態の語（Running・Done・Failed・Stopped・Idle・Exited・Question・Approval・Reported）は、ラベル・読み上げ名・行の補足を英語にする。文の中で状態を説明する時は日本語でよい（「実行中のAgentはありません。」）。OSの通知の題は、ほかのアプリの通知と並ぶので日本語にする（失敗・完了・入力待ち・承認待ち）。

英語のUIも[製品仕様の表示と失敗の案内](../product.md#表示と失敗の案内)に従う。値がない項目を`Unknown`、`Unavailable`、`Not confirmed`、`N/A`などの文字で埋めない。
