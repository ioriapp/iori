# Board

Boardは、チームを付けた会話の状況を1つのタブで一目で知る画面である。この文書は、Boardの区画・行の項目・開き方と、親が計画を登録する `iori plan` を作る・変える時に読む。委譲・報告・判定と子の表示は[Linked Agent](linked-agents.md)、チームが持つ項目と記録は[チーム](teams.md)、記録を見返す画面は[Records](records.md)が正本で、食い違う時はそちらに従う。

## 開き方と配置

選択中のworktreeの行の下に Files・Git・Terminal・Board の入口を並べ、Boardはそのworktreeにチームを付けた会話がある時だけ出す（[画面の構成](workspace-layout.md)）。押すとその配置にBoardのタブ（タブ名 Board）を開き、既にあればそこへ移る。自動では開かない。同じworktreeにチームを付けた会話が複数ある時は、Boardの上端で会話を切り替える。切替にはサイドバーに親の会話の行が残っている会話だけを新しい順に並べ、既定は親のCLIが最後に動いた会話（無ければ最も新しい会話）にする。同じ名前を見分けられるよう、各会話に開始の日時を添える。Boardの上端の会話切替と同じ並びに「会話を開く」（Open conversation）と、選択中の会話のチーム名を置く。「会話を開く」は、サイドバーの親の会話の行と同じ経路で、選択中の親のCLIのタブを開く。既に開いていればそこへ移る。スマホではBoardの全画面から親の会話の全画面へ移り、Androidの戻る操作でBoardへ戻る。チーム名を押すとそのチームの編集画面の「Team全体」へ移る。PC・スマホで同じ入口を使う。

上にAttention、その下にPlanとAgentsを置く。タブの幅が960px以上ならPlan約3/5・Agents約2/5の2列、狭ければAttention・Plan・Agentsの1列、スマホではAttention・Plan/Agentsのタブの行・選択中の中身を1つの縦スクロールにする。Attentionはスクロールで画面の外へ送り、タブの行だけをスクロールの上端に固定する。固定中もタブで切り替えられ、中身はタブの行に透けて重ならない。停止ボタン、メモ、評価は置かない。

## Attention

その会話で、ユーザーが動かないと進まないYouの行だけを1行ずつ並べる。何も無い時は区画ごと出さない。

| 担当 | 種類         | 行に出すもの                                                        | 押した時                             |
| ---- | ------------ | ------------------------------------------------------------------- | ------------------------------------ |
| You  | Approval     | 役割・題名・CLIが求めている内容（`Bash: pnpm test` など）・待ち時間 | その子のタブを開く                   |
| You  | Question     | 役割・題名・CLI自身が求めている質問・待ち時間                       | その子のタブを開く                   |
| You  | No candidate | 役割・題名・候補が使えない理由・「Teamを編集」                      | 「Teamを編集」でその役割の編集へ移る |

1段目は種類・役割・題名、2段目は内容や理由を小さく薄い文字で表示する。上限の空き待ちだけの委譲は、待てば進むので出さない。報告済み・質問中で親の判断を待つ子はAttentionに出さず、Agentsの状態と `Parent: Pending` で表示する。全Hostを横断するサイドバーとスマホの最初の画面のAttentionは、[製品仕様](../product.md)に従う。

## Plan

親が `iori plan` で登録した目標と計画を表示する。CLIのToDoから計画を作らない。

- Goal: 1〜2文と「12分前に更新」のような最後の更新からの時間。「最後の更新」は目標とタスクを含む計画全体の最後の更新とする。古くなっていることが分かるようにする。ユーザーの追加の依頼で組み直した時は「追加の依頼で目標を更新 · 14:02」を出し、押すと前の目標を読める。
- 進み具合: `3 of 7 done`のような件数と細い進捗バー。
- タスク: 計画の順の縦の一覧で、状態で並べ替えない。状態のインジケーター、タスク名、担当（役割・難易度・CLI・モデル。難易度は役割が難易度別に候補を分ける場合だけ `Worker · High` のようにHigh・Medium・Lowで表示する。親自身ならParent）と `Task n`、経過時間を表示し、`Task n` はAgentsの行と同じ番号・書式で担当の並びに表示する。その下に親が最後に書いたチェックポイントの一言を薄い文字で置く。差し戻しがあれば `Revisions 2`、担当の子への親の判定があれば Accepted・Rejected を小さく添える。追加されたタスクは名前の右に Added を付ける。取り消したタスクは末尾に件数（`1 Cancelled`）で畳む。行を押すと担当の子のタブへ、親担当なら親の会話へ移る。
- インジケーター: 未着手は破線の丸、作業中は光る丸と題名のTextShimmer、完了は✓、担当の子がApprovalかNo candidateで止まっている時は琥珀、担当の子が失敗した時は✕。インジケーターの枠は固定する。完了・取り消しは親が書いた状態に従い、子の報告への親の判定待ちとは別の状態として表示する。
- Activity: 計画の変更を新しい順に5件表示し、「すべて表示」で全部を読める。ユーザーの追加の依頼による組み直しと、親の判断による更新を区別する。

## Agents

その会話のLinked Agentの子を表示する。

- まとめ: この会話の合計として `Agents 6 · +412 −88 · 12 files · Tokens 1.2M` を表示する。トークン量は取れた子だけを合計し、取れない子がいる時は対象の人数を添える（`1.2M（5人分）`）。トークン量の定義（入力＋出力）はここで1回だけ表示する。
- その下に、役割ごとの使用数/上限と上限で待つ子の数（`Worker 1/2 · 2 Waiting`）、会話の子が使うCLIの利用枠を[利用枠の書式](usage-display.md#書式)で一度ずつ表示する。値が取れない枠は出さない。
- 行: 状態のインジケーター、役割と難易度（Planと同じ条件・書式）、題名、CLIとモデル・Task番号、今の状態（Starting・Running・Waiting・Approval・Reported・Question・Failed・Stopped・Finished と、待機の理由など補足の文）、変更（`+184 −32 · 4 files`）、トークン量（`412k tokens`）、親の判定（`Parent: Pending`・Accepted・Rejected と Revisions）、経過時間。差分の数字からその子のworktreeのGitへ、行からその子のタブへ移る。同じworktreeで動く子は同じ変更を表示し、トークン量は各子の値を使う。
- 状態: 報告済み・質問中でもCLIが作業中の間はRunning（実行中）のインジケーターと文字を表示し、親の判定待ち・回答待ちは補足の文に残す。CLIの作業が止まったらReported・Questionへ戻す。承認待ちの扱いは変えない。
- 今の操作: Runningの文字は、CLIの通知が取れる時だけ、ツールの実行中にはCLI自身のツール名と対象の要約（`Bash pnpm test`・`Edit src/x.ts`・`exec_command pnpm test`など）、それ以外の作業中には `Thinking` に替える。コマンドは1行目、ファイルは子のworktreeからの相対パス（外なら絶対パス）、検索は検索語を表示し、その他はツール名だけにする。開始から500ms以上続くツールだけを表示し、一度表示したツールは最短200ms保ってから最新の状態へ移る。短いツールや、切替先のツールが開始から500ms経っていない間は、それまでの表示を保つ。Boardを開いた時に既に実行中のツールと、承認・質問の後に続く同じツールは待たずに表示する。承認・質問などツール以外の状態（Thinkingへの復帰を除く）は遅らせず表示する。並列に動く時は最後に開始した実行中のツールを表示し、終了しても他が残っていればその中の最新を表示する。すべて終了したらThinkingに戻す。CLIから操作のIDが取れない時は、終了の通知でThinkingに戻す。1行で折り返さず、長い時は末尾を省略し、ツールチップで全文を読める。状態のインジケーターと補足の文は保ち、Approval・Question・Reported・Failed・Stopped・Finished・Starting・Waitingは上書きしない。通知が取れない時・まだ届いていない時は元の状態を表示する。秘密の伏せ方は承認待ちの要約と同じとし、ツールの入力全文やファイル本文は出さない。
- 並び: Reportedで親が未判定・Questionで親の回答待ち・Failed、StartingとRunning、Waiting（理由付き）、Finished・Stopped の順。同じまとまりの中は委譲した順。Finished・Stoppedは `14 Finished` のように件数で畳み、件数にはStoppedの子も含む。Failedは畳まず、理由は長い語も面の内側で折り返して全文を表示する。
- 経緯: Finishedの行を押すと、その場でタスクの経緯を時系列で開く（Delegated・Revise・Handoff・Accepted・Rejected と時刻、担当、理由の本文）。経緯の下に「最後の画面を開く」を置く。経緯の形は[Records](records.md#経緯)と同じ部品を使う。

値の無い項目（取れないトークン量、計測できない変更など）は項目ごと出さず、0で代用しない。

## 親の計画

Hostはチームの会話の親に `iori plan` を用意し、チームの回し方の固定の指示に、開始時にGoalとタスクを書く、区切りのチェックポイントごとに更新する、追加の依頼では先に計画を組み直す、再開時や迷った時は `iori plan show` で再度確認する、を足す。チームのない会話には足さない。

```sh
iori plan show
iori plan goal --body TEXT [--request]
iori plan add --title TITLE [--after N] [--request]
iori plan update N [--state pending|in_progress|done] [--checkpoint TEXT] [--title TITLE]
iori plan cancel N --reason TEXT
iori delegate ... [--plan N]
```

- `--request` はユーザーの追加の依頼による組み直しを表示し、Activityで親の判断による更新と区別する。
- `delegate --plan N` は委譲を計画のタスクNへ結び、Boardではそのタスクの担当として子を表示する。1つのタスクに複数の子を結べる。
- 本文の渡し方と返答の書式は[Linked Agent](linked-agents.md#親と子のコマンド)の他のコマンドと同じにする。
