# Board

Boardは、チームを付けた会話の進捗と、次に対応することを確認する画面。委譲・報告・判定は[Linked Agent](linked-agents.md)、集計する値は[チーム](teams.md)、過去の記録は[Records](records.md)に従う。

## 開き方と配置

Boardは、チームを付けた会話があるworktreeから開く。入口とタブの扱いは[画面の構成と移動](workspace-layout.md)に従う。同じworktreeの対象会話は上端で切り替える。サイドバーに残っている親の会話を新しい順に開始日時付きで並べ、最後に親が動いた会話を最初に表示し、動作の記録がなければ最も新しい会話を表示する。上端から親の会話とそのTeamの編集を開ける。

上端の下に、上下を1pxの罫線で区切った全幅のサマリーと、対応が必要な場合のAttentionを置く。サマリーはPlanの進捗、Agentsの状態別件数、変更とトークン量を表示する。状態別件数はAgentsの行と同じ状態から集計し、表示と一致させる。

広い表示ではPlanとAgentsを左右のペインに置き、中央の1pxの縦罫線で分ける。幅の狭いPCでは1列に並べる。MobileではAttentionの下でPlanとAgentsを切り替え、タスクがなければAgentsを先に表示する。PlanとAgentsの空・読み込み・失敗は[共通の内容表示](ui.md#内容の状態)に従う。

## Attention

その会話でユーザー自身の回答・承認・設定変更が必要なときだけ、[対応が必要な強調](visual-style.md#色と面)を使って表示する。行には状態、役割、題名、待ち時間、CLIが求める内容または候補を使えない理由を置く。承認や質問の行から対象の会話を、使える候補がない行から役割の編集を開ける。

空きができれば進む委譲やOrchestratorの判定・回答を待つ子はAgentsで確認する。全Hostを横断するAttentionは[製品仕様](../product.md#判断失敗復帰)に従う。

## Plan

親が `iori plan` で登録した目標、前回の更新からの時間、タスクの進捗を表示する。ユーザーの追加依頼で目標を変えた場合は前の目標も開ける。

- タスクは完了・作業中・未着手の順、同じ状態では計画の順に並べる。状態、題名、担当、`Task N`、経過時間と、該当するチェックポイント、差し戻し、親の判定を表示する。難易度は役割が難易度別に候補を持つ場合だけ表示する。取り消したタスクは件数でまとめて末尾で開ける。行から担当の会話を開ける。
- 未着手、作業中、完了、承認や設定変更待ち、担当の失敗を形や色で区別する。作業中の題名に`TextShimmer`を使い、[動きを減らす設定](visual-style.md#状態のインジケーターと動き)に従う。タスクの完了や取り消しは親が登録した状態で表示する。
- 計画の変更は新しい順に表示し、全件を開けるようにする。ユーザーの追加依頼と親の判断による変更を区別する。

## Agents

子Agentを委譲順に並べ、横の1pxの罫線で区切る。行から子の会話を開き、差分から該当するworktreeのGitを開ける。

- 1段目に役割、題名、状態、経過時間を置く。2段目にCLIとモデル、`Task N`、難易度、差分、トークン量、Orchestratorの判定と差し戻しを補足として並べる。日本語では `難易度: 高`、`トークン 412k` のように[用語集](wording.md#状態と件数)に従う。
- CLIが作業中なら実行中として表示し、Orchestratorの判定や回答を待つ場合は補足に残す。CLIから作業の通知が取れるときは、実行中の表示位置にツール名と対象の要約を表示し、ツールの実行がなければ考え中の状態を表示する。短い操作による表示のちらつきを抑え、承認・質問など実行中以外の状態はすぐ反映する。操作名は1行に収め、全文をツールチップで読めるようにする。対象の要約には承認待ちと同じ秘密情報の扱いを適用し、ツール入力全文やファイル本文は表示しない。
- 失敗した行は一覧に残し、ioriの案内を1行で表示する。CLIの出力は等幅で折り返し、折り畳みを開くと全文を読める。
- 完了・停止の行は件数でまとめる。完了の行から委譲と判定の経緯および最後の画面を開ける。経緯は[Records](records.md#経緯)と同じ部品を使う。

役割ごとの利用数・上限・待機数と、CLIの[利用枠](usage-display.md#書式)はまとめて表示する。トークン量は取得できた子の入力と出力を合計し、一部の子の値が取れない場合は合計の対象人数を添える。個別の項目も値が取れたものを表示する。

## 親の計画

Hostはチームの会話の親に `iori plan` を用意し、チームの回し方の固定の指示に、開始時にGoalとタスクを書く、区切りのチェックポイントごとに更新する、追加の依頼では先に計画を組み直す、再開時や迷った時は `iori plan show` で再度確認する、を足す。チームのない会話には足さない。

```sh
iori plan show
iori plan goal --body TEXT [--request]
iori plan add --title TITLE [--first | --after N] [--request]
iori plan move N (--first | --after M)
iori plan update N [--state pending|in_progress|done] [--checkpoint TEXT] [--title TITLE]
iori plan cancel N --reason TEXT
iori delegate ... [--plan N]
```

- `--request` はユーザーの追加の依頼による組み直しを表示し、Activityで親の判断による更新と区別する。
- タスクの番号は変えない識別であり、`iori plan add --first`・`--after N` と `iori plan move N` で変わるのは表示の順だけである。`add` と `move` は変更後の順を返し、`move` はActivityに出さない。
- `delegate --plan N` は委譲を計画のタスクNへ結び、Boardではそのタスクの担当として子を表示する。1つのタスクに複数の子を結べる。タスクNが未着手なら、Hostが作業中にする（ActivityにはHostが変えたことが分かる形で出す）。完了と取り消しはHostが変えず、親が書く。子の受け入れは、統合や確認が残ることがあり、タスクの完了と同じではないからである。
- 計画が古いままの時の促し: Hostが親へ子の知らせ（報告・質問・失敗・未報告の入力待ち・止まり・作業中の子の確認）を送る時、前の子の知らせを送った後に親が `iori plan` で計画を変えていなければ、その知らせの末尾に、計画の最後の更新からの時間と、タスクの状態・順・チェックポイントが変わったなら `iori plan` で更新するよう促す一文を足す。計画がまだ無ければ、目標とタスクを書くよう促す。Hostが自分で変えた状態（上の作業中）は、親の更新に数えない。
- 本文の渡し方と返答の書式は[Linked Agent](linked-agents.md#親と子のコマンド)の他のコマンドと同じにする。
