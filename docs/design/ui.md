# UIの定義

共通部品、内容の状態、保存方式を変えるときに読む。見た目と実装基盤は[画面の見た目と言葉](visual-style.md)、配置と移動は[画面の構成と移動](workspace-layout.md)に従う。

## 画面の骨組み

- 上端の行では左に見出しと必要な説明、右に画面の主操作を置く。[ダイアログ](dialogs.md)と[Issueの詳細](forge.md#issues)はそれぞれの配置に従う。
- 本文は見出し、余白、罫線で節を区切る。一覧の行と設定欄に共通部品を使う。短い入力は左に名称と説明、右に操作を置き、狭い幅では操作を次の行へ移す。文字入力はラベルの下に置く。長い説明やエラーは領域の内側で折り返す。
- タブの選択は下線で表示する。一覧と詳細を別画面で開く場合、一覧に戻ったときは直前に開いた行の選択表示を解除する。ホバーの表示はポインター操作に限る。状態と選択は色に加えて形や読み上げ名で区別し、キーボード操作ではフォーカスを表示する。
- 一覧の順は定義順、名前順、時系列、状態など、ユーザーが把握できる基準で決める。到着順や絞り込みによる並べ替えは行わない。長い名前は省略しても全文を確認できるようにし、読むことが目的の題名は折り返す。
- 行の追加操作はメニューから開ける。右クリックや長押しでは対応するioriのメニューを開く。入力欄と選択中の文字ではコピーと貼り付けのために標準のメニューを使う。危険な操作はメニューの末尾に区切って置く。
- ボタンは操作できる形で表示する。リンクは下線などで識別できるようにし、スイッチのオンは視認性の高いアクセント色で表示する。
- Mobileでは当たり判定を見た目と分ける。独立したボタン、アイコン、メニュー、Terminalのキー帯の操作は40〜44px、確認ダイアログの主ボタンは44pxを確保する。一覧行は36〜40pxとし、行全体で主操作を実行する。副操作は右端の「…」ボタン1つ（当たり判定44px）か長押しメニューにまとめる。ボタンの当たり判定を行の主操作や隣の行と分けられない場合は、長押しメニューを使う。

| Teams       | `Users`            |
| Automations | `CalendarClock`    |

## 内容の状態

[製品仕様](../product.md#表示と失敗の案内)の4状態を共通部品で表示する。

| 状態       | 表示                                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| 読み込み中 | 短い遅延の後、内容の場所に控えめなスケルトン（内容の形を示す仮表示）か進行インジケーターを置く。再試行は表示しない。 |
| 0件        | 空であることを説明し、その場所で取れる次の操作があれば表示する。                                                     |
| 失敗       | 失敗が確定した対象のそば一か所に、判明した理由と回復操作を表示する。                                                 |
| 内容あり   | 読み込んだ内容を表示する。追加取得や再読み込みの間も、表示済みの内容は読めるようにする。                             |

初回の失敗は内容領域に表示する。再読み込みの失敗は最後に読めた内容を保ち、回復操作をそのそばに表示する。比較の片側だけを読み込めなければ、その側に案内を置く。読み込めた未対応形式については、対応していないことを表示する。

送信・保存・作成などの応答を待つ間は、操作したボタンに進行状況を表示し、同じ操作を二重に送らない。

## 時間のかかる操作の流れ

導入・更新・アンインストールの進行と結果は同じ流れで表示する。ダイアログの高さは[ダイアログ](dialogs.md)に従う。表示を閉じても処理が続く場合は、元の画面か通知から結果を開けるようにする。対処が必要な結果は結果画面に残し、通知から開き直せるようにする。背景で進める操作の確定した失敗は、対象と回復操作を通知から確認できるようにする。

## 保存の仕方

- 即時保存。安全に即時反映できるスイッチ、選択、表示サイズなどに使う。変更直後だけ控えめに「保存済み」と表示する。失敗した場合は元の値に戻し、その欄のそばに理由を表示する。
- 明示的な保存。文字入力、複数欄の整合が必要な設定、TeamやAutomationの定義に使う。設定は対象の節に、定義の編集は画面上端に共通の「保存」を置き、変更があるときに有効にする。編集欄から離れただけでは保存しない。設定の入力欄はEnter（複数行ではCtrl+Enter）でも保存できる。結果は保存操作のそばに表示し、空の結果欄は設けない。失敗した場合は理由を表示し、入力を保持する。

未保存の変更がある状態で閉じたり対象を切り替えたりするときは、[変更を保存するかの確認](dialogs.md#未保存の変更)を使う。

## 文言

操作を求める文は操作を先に書き、ユーザーが確認できる結果を添える。理由は判明したことのうち対処に必要な情報に絞る。語と文の形は[用語集](wording.md)に従う。
