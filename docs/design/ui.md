# UIの定義

部品を選ぶ時に読む。配色、書体、文字の段、状態の印、動き、画面の言葉は[画面の見た目と言葉](visual-style.md)、配置と操作は[画面の構成と移動](workspace-layout.md)が持つ。

部品はshadcn/uiとAgent Elements、分割はdockviewを使う。shadcnプリセット `bLsFFpw1Y` とBlocksを土台にし、見た目は共通の定義へ揃える。Planの縦の一覧はAgent ElementsのTodo Toolを土台にする。

右クリック（スマホは長押し）では、ioriのメニューがある行・画面はそのメニューを開き、無い所ではWebViewの標準のメニュー（再読み込み・印刷など）を出さない。入力欄と選択中の文字ではコピー・貼り付けのメニューを残す。

一つの画面は一つの部品の系統で揃える。shadcn/uiとAgent Elementsに無い部品（ファイルツリー、差分表示、ボードなど）だけを他から採り、採る前に、色をテーマの変数で指定していること、動きが控えめなこと、アイコンが同じ系統（lucide）であることを確かめる。合わない所は取り込んだ後に直す。

行の下の補足・失敗の詳細は、長い語でも面の内側で折り返す。

## 画面の骨組み

画面を作る・変える時は、部品を並べる前にこの骨組みに当てはめる。骨組み・節・欄の行・保存の知らせは共通の部品で作り、画面ごとに書き直さない。

- 上端の行: 左に題名と短い説明（戻る操作がある時は題名の上の左）、右に主な操作（保存・作成・実行など）を置く。主な操作はこの行の右だけに置き、本文の途中や左に置かない（ダイアログの例外は[ダイアログ](dialogs.md)）。例外として、Issueの詳細は題名を幅いっぱいに取るため、操作を状態の行の下に左寄せで置く（[Forge](forge.md#issues)）。設定のモーダルのように主な操作が無い画面には置かない。
- 本文: 1列に節を縦に並べる。最大幅は画面の種類で揃える: 設定のモーダルは680px、本体の編集画面（AIエージェント、チーム、Automation）は960px、表や一覧で比べる画面（Records）は本体の幅いっぱい。Files・「ファイル」のタブで描画したMarkdownはペインの幅いっぱい、Issuesの詳細（本文とコメント）は960px。節の中を別の切替（タブ・節へ移るリンク）で分けない。
- 節: 見出し（と短い説明）の下に、中身を角丸の薄い面で囲んでまとめる。面の中の行は細い線で区切り、最後の行の下には線を引かない。見出しは自分の面のすぐ上に置き、上の節からは離す。
- まとまりを近さで示す: 同じまとまりの中の間隔は、まとまりどうしの間隔より必ず狭くする（行の中8px、見出しと面8px、行どうしは線で区切り、節どうし32px）。間隔は4pxを単位にし、隣り合うボタン・選択・入力の枠を重ねない。その操作が属するもの（保存なら自分の節の欄、「追加」なら追加先の一覧）のすぐ下・横に置く。
- 欄の形: スイッチ、選択、短い数・値は1行に置き、左に名前と説明、右に操作を置く。狭い幅で右の操作が入らない時は、名前を縮めず、操作を名前・説明のすぐ下の行へ回して右に寄せ、行の高さを中身より伸ばさない。狭い幅では、説明のある行は操作を下の行へ回す。文字の入力（名前、URL、コマンド、指示など）は名前の下に置き、複数行の欄は面の幅いっぱいに取る。
- スマホのダイアログの操作ボタンは高さを44px以上にする。
- 指・ポインターで開いたメニュー・ドロワー・選択の一覧は、容器にも先頭の項目にも焦点の輪を出さない。
- 押せるものは押せる見た目にする: 文字だけ・ホバーでだけ背景が出る形は、アイコンだけのボタン、一覧の行、外部のページを開くリンク（「変更内容」など）に限る。「追加」「確認」「再試行」などは枠のあるボタンにする。
- 並び順: 一覧・表・行の中の項目は、利用者から法則の分かる順に並べる。定義の順（設定やチームで並べた順、CLIの一覧の順）、名前の順、作成の順、新しい順、状態ごとのまとまり（動いているものが先など）のどれかにし、データが届く順や絞り込みで順を変えない。同じ順の項目どうし（同じ状態・同じ時刻）も、作成の順などで決まった順にする。同じものは画面をまたいでも同じ順に並べる。利用者が並べ替えた時はその順に従う。
- 行の右側の印と操作: 一覧の行の右側に並ぶ札・印・ボタン（OS名と接続の印、歯車と＋など）は一つの組として右端へ寄せ、行の幅が変わっても組の中の間隔を変えない。開閉できる行（リポジトリ・フォルダー・worktree）の開閉の印（⌄・›）は名前の左でなく行の右端に置き、＋などの操作はその左に並べる（見出し・アコーディオンの型）。開閉の印と＋の位置は、この3種類の行で同じ横の位置に揃える。境界のドラッグで幅を変える所は、ホバー中とドラッグ中だけ既存の罫線と同じトークンの線を2pxにして示す。
- 一覧の末尾の畳み（非表示にした項目 など）は常時の塗りを付けず、面の中では前後の行と同じ線で区切る。
- 行の「…」メニューは、危険な操作を区切りの下の最後に置き、項目のアイコンは全部に付けるか全部に付けないかのどちらかにする。
- 空と長い名前: 一覧が0件の時は列の見出しだけを残さず、空であることと次の操作を短く示す。長い名前を戻る操作・上端の行・選択部品に出す時は1行で末尾を省略し、全文は吹き出しで読める。worktreeの名前は中ほどを省略する。例外として、Issueの題名は読むための中身なので、上端の行でも折り返して全文を示す。
- dockのタブは、キーボードで焦点を移した時にタブ全体の内側を輪で囲む。
- タブの選択の印は、dockのタブもペインの中のタブ（Filesのファイルのタブ、Gitの変更・履歴など）も、タブの下端に、アクセントの色の2pxの線で置く。Board のスマホの Plan・Agents のような、面の中で選んだものを白い箱で示す切り替えの部品は、タブではないのでこの決まりの対象にしない。
- メニュー・選択の一覧の幅: 一覧の幅は並ぶ項目の長さで決め、押したボタンの幅に合わせない。画面の幅を超える時は画面の端から10px内側で止め、入りきらない項目を上の決まりで省略する。高さが画面を超える時は一覧の中でスクロールする。共通の部品（`DropdownMenuContent`）の既定にしてあり、画面ごとに幅を決め直さない。
- 取得中の見た目: 画面を開いた後に届く値（モデルの一覧、残量、Gitの状態など）を待つ間、行の下に「取得中」の段や再試行を足さず、届く値の場所を先に空けて、届く前と後で行の高さと位置を変えない。取得に失敗した時だけ、理由と再試行を出して行を伸ばしてよい。
- 読めなかった時の見た目: 見せる内容が無い時（初めて読めなかった）は、内容の場所の中央に、起きたこと・理由・回復の操作を空の時と同じ部品で示す。最後に読めた内容を保っている時（読み直しの失敗）は、上端の行の下に1行で示す。どちらも赤は見出しか印だけにし、理由は前景色、回復の操作は通常の枠のボタンにする。
- 押した操作の完了を待つ見た目: 削除・保存・作成・開始など、押してからHostの応答を待つボタンは、待つ間、押したボタンの文字の場所を残したまま中央に回る印を出し、ボタンの幅と位置を変えず、同じ操作を二重に送れないようにする。読み上げの名前は元の文字のままにし、ボタンの共通の部品（`Button` の `pending`）で作る。
- 選択中の印: 一覧・ツリーで選んでいる行、選んでいる曜日などは、アクセントの色（薄い背景と、アイコン・下線などの印）で示し、非選択と一目で区別できる差を付ける。一覧と詳細を別の画面で行き来する時（スマホの設定・AIエージェント/チーム、狭い幅のFiles・Git・Issues・CI）は、一覧の行に選択中の印を出さない。ホバーの背景はマウスなどのポインターがある時だけ出し、指で押した行に残さない。一覧に戻った時に、さっき開いた項目が選ばれたままに見えないようにする（iOS・Androidの設定アプリと同じ）。
- OSが描く部品（時刻・日付の選択など）は、画面のテーマ（ライト・ダーク）に合わせて描かせる。スクロールバーはどの面でもサイドバーと同じ見た目（テーマの灰色）にそろえる。
- 画面のアイコン: 画面の入口のアイコンは下の表に従い、同じアイコンを別の画面に使わない。画面を足す時は表に足す。

| 画面           | アイコン（lucide） |
| -------------- | ------------------ |
| AIエージェント | `Bot`              |
| チーム         | `Users`            |
| Automations    | `CalendarClock`    |
| Records        | `History`          |
| CI             | `Workflow`         |
| Issues         | `CircleDot`        |

## 保存の仕方

保存の仕方は節（まとめて編集する画面では画面）ごとに一つに決め、同じ節の中で混ぜない。

- スイッチと選択だけの節: 操作したらすぐ保存する。成功の知らせは出さず、操作した部品の状態で示す。失敗した時だけ、その行に理由を出して元の状態へ戻す。
- 文字の欄がある節: 節の末尾の右に「保存」を置き、欄の中のEnterでも保存する（複数行の欄はCtrl+Enter）。欄から離れただけでは保存しない。保存ボタンは変更が無くても押せる。結果（「保存しました」・理由つきの「保存できませんでした」）は保存ボタンの左の決まった場所に出し、出る時も消える時も他の部品の位置を変えない。失敗しても入力を残す。保存していない変更があるまま閉じる・離れる時は[破棄の確認](dialogs.md)を出す。
- まとめて編集する画面（チーム、Automationの1件）: 上端の行の右に「保存」を1つ置く。保存すると新しいバージョン・新しい定義を作るので、未保存の変更が無い間は押せない（節の保存とは違う）。結果は上端の行の題名の下の行に出す。有効・無効の切替のようにすぐ効かせたい操作は、編集の外（一覧の行か上端の行）に置き、すぐ保存する。
- 見るだけの画面（Records）には保存を置かない。
