# Hostの導入と更新

読むのは、最初のiori Hostの用意、Hostの導入・更新・撤去の画面と操作、SSHの扱いを変える時である。
導入画面の並び・欄の名前は[iori Hostを用意する画面](host-setup-screen.md)、接続状態は[接続](connection.md)、設定項目は[設定](settings.md)、Hostの再起動は[Hostの再起動](host-restart.md)、デバイスの招待と登録は[製品仕様](../product.md#初回利用とデバイス追加)が持つ。
Clientの自己更新と、Client・Hostのバージョンの照合および更新順序は[Clientの自己更新](client-update.md)に従う。

## ユーザーの目的

Hostのマシンへ別途ログインしてコマンドを打たずに、普段使うiori Clientからiori Hostを用意し、そのバージョンを最新に保つ。iori Hostとiori Clientが同じマシンのユーザーも、別のマシンのユーザーも、同じ入口から始められる。

## コマンドでの導入と更新

Clientからの導入より先に、Hostのマシンでコマンドを1行実行して導入・更新できる。配布物は[Releaseと公開](release.md#配布物)に従う。

- Linuxは `curl -fsSL https://github.com/ioriapp/iori/releases/latest/download/install.sh | sh`、WindowsはPowerShellで `irm https://github.com/ioriapp/iori/releases/latest/download/install.ps1 | iex` を実行する。管理者権限とパスワードを求めない。
- 本人のユーザーで常駐させる。Linuxはsystemdのuser serviceにし、lingerが無効なら本人の権限で有効にしてその旨を表示する。有効にできない時は管理者が実行するコマンドを表示し、導入は続ける。Windowsはログオン時に本人のユーザーで起動し、画面にwindowを出さない。コマンドでの導入はWindowsファイアウォールの許可を加えない。他のデバイスから接続するための許可は、Clientから加える（[ほかのデバイスからの接続を許可する](#ほかのデバイスからの接続を許可するwindows)）。
- バージョンを指定しない導入スクリプトは、GitHubの最新の安定バージョンを取得する。`IORI_VERSION` を指定した時は、そのバージョンの `/download/v〈版〉/〈名前〉` から取得する。
- 同じコマンドで更新する。Hostを新しいプログラムへ入れ替えて起動し直す。LinuxではioriのTerminalから実行しても、そのTerminalが閉じた後にHostは新しいバージョンで戻る。実行中のTerminalとCLIの画面のプロセスが止まり、LinuxでioriのTerminalから実行した場合はそのTerminalも閉じること、会話はCLIの保存に残り再開できることを、止める前に表示する。確認は求めない。
- WindowsのioriのTerminalからの更新は、ClientからHostを更新する機能で扱う。
- 環境変数 `IORI_VERSION` でバージョンを指定すると、そのバージョンを入れる。前のバージョンへ戻す時にも使う。
- 初めての導入の終わりに、デバイスを登録する招待（QRと文字列）を表示する。後から出す時は `iori-host invite` を実行する。
- 更新でデバイスの登録・鍵などのHostの保存データを削除しない。撤去はClientから行う（下の[撤去](#撤去)）。

## 入口

Hostが一台も無いDesktop Clientの最初の画面に、「iori Hostをセットアップする」と「招待で接続する」を並べる。Hostがある時は、設定のHostの区画の「iori Hostを追加する」から同じ入口を開く。

| 選択                | 対象                    | 動線                                                            |
| ------------------- | ----------------------- | --------------------------------------------------------------- |
| iori Hostを用意する | Desktop Client          | モーダル内でこのPCかSSHの接続先を選び、導入とデバイス登録を行う |
| 招待で接続する      | Desktop / Mobile Client | 既存Hostまたは登録済みデバイスから受け取った招待で登録する      |

このPCへの導入はWindowsとLinuxを対象とする。SSHの接続先はLinuxとWindowsを対象とし、WindowsとLinuxのClientから使える。欄と文言は[画面の並び](host-setup-screen.md#画面の並び)に従う。

SSHによる導入の対象にmacOS Hostを含めない。

MobileのClientには導入の選択肢を出さない。既存の招待（Hostまたは登録済みClientが発行したもの）をQRの読取または貼り付けで受け取って登録する。

## 導入で選ばせないもの

導入先のOSとCPU、待受のアドレスとポート、使えるCLI、ワークスペースのフォルダーは、導入の画面で選ばせない。

- 待受先: Hostは全てのネットワークで待ち受け、接続に使えるアドレスを自分で調べて知らせる。接続できない時だけ、[接続](connection.md)の設定で直す。
- CLI: Hostが起動後に見つけ、CLIの一覧と設定で扱う。
- フォルダー: 導入後に[worktreeとフォルダー](worktrees.md#フォルダーを開く)の経路でHost上のフォルダーを直接開く。

## このPCにiori Hostを導入する（Windows）

- 本人のユーザーで、ログオン時に画面にwindowを出さずに起動するように導入する。アカウントのパスワードは求めない。
- 配布物はClientが取得し、署名を確かめてから導入する（[Releaseと公開](release.md)の署名済みRelease情報）。取得・展開・起動・登録の段階と、失敗した時の理由と再試行を同じ画面に表示する。段階の経過時間だけで失敗にしない。
- 導入の画面の「ほかのデバイスからの接続を許可する」は既定で選んでおく。選んだまま導入すると、ファイルの配置後、Hostの起動前にWindowsの管理者の確認（UAC）を1回だけ出し、iori Hostのプログラムだけに受信を許す規則を加える。確認の前に、出る確認とその理由を画面に一行で表示する。選択を解除した時、または確認を断った・失敗した時も導入は続け、このPCからは使えることと、後から設定で許可できることを表示する。この場合はHost起動時にWindows自身の接続許可の確認が出ることがある。
- Windowsの管理者確認が終わったら、ioriを前面に戻して導入の結果を確認できるようにする。
- このPCに既にiori Hostがある時は導入せず、名前とバージョンを表示して「このiori Hostに登録する」を置く。規則が無い既存Hostの登録完了時にも、ほかのデバイスからはまだ接続できないことと、設定で許可できることを表示する。

## このPCにiori Hostを導入する（Linux）

- Clientが署名済みRelease情報を確かめ、そのSHA-256を同梱の `install.sh` へ渡して、本人のユーザーで実行する（SSHの導入と同じ確かめ方）。[コマンドでの導入](#コマンドでの導入と更新)と同じく、systemdのuser serviceにしてlingerを試し、有効にできない時はログアウトするとHostが止まることと管理者が実行するコマンドを表示して導入を続ける。アカウントのパスワードは求めない。
- 取得・展開・起動・登録の段階と、失敗した時の理由と再試行を同じ画面に表示する。
- ファイアウォールには触れない。
- このPCに既にiori Hostがある時はWindowsと同じく導入せず、「このiori Hostに登録する」を置く。

## ほかのデバイスからの接続を許可する（Windows）

このPCのiori Hostを選んだ設定の「接続」に、「ほかのデバイスからの接続を許可する」を置く。押すとWindowsの管理者の確認（UAC）を出し、導入時と同じ規則を加える。既に規則がある時も押せて、同じ規則を加え直す（重ねて作らない）。規則があるかを読み取れた時は、許可済みであることを表示する。読み取れない時は何も表示しない。

規則はiori Host専用の同梱Node（`%LOCALAPPDATA%\Programs\iori-host\runtime\node.exe`）だけにUDPの受信を許す。Hostの更新は同じ場所へ配布物を置き換えるため、規則のプログラムのパスは変わらない。規則の名前は導入先ごとに固定し、再実行では同じ規則を書き換える。

許可を加える時には、同じプログラムのパスに対する受信の遮断規則だけを削除する。Windowsが接続確認の取消や管理者でないユーザーの起動時に作る遮断規則は、許可の規則より優先されるためである（[Windowsの規則と通知](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules)）。他のプログラムの規則には触れない。昇格する処理もPowerShellのwindowを出さずに実行する。

ネットワークの種類はドメイン・プライベート・パブリックの全て（`Profile Any`）を対象にする。LAN・VPNのネットワーク分類によって接続できなくなることを避けるためである。接続元のサブネットは限定しない。VPNの相手は同じサブネットとは限らない。Windowsの[プログラム・プロファイル・接続元の指定](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule)に従い、ポートだけを開く規則にはしない。デバイスの登録と鍵の確認はioriの通常の通信経路で行う。

## 別のマシン（SSH）

- 接続にはユーザーの手元にあるOpenSSHの`ssh`を使う。`~/.ssh/config`、ssh-agent、鍵、known_hosts、踏み台の設定はそのまま効く。
- `~/.ssh/config`のHostを接続先の候補として表示する。Includeもたどり、ワイルドカード・否定のパターンは候補にしない。手で指定する時は、OpenSSHと同じ `[user@]host` または `ssh://[user@]host[:port]` を使う。`-` で始まる値は指定できない。configは書き換えない。
- OpenSSHが無い時は「OpenSSH クライアントが見つかりません」と表示し、WindowsではWindowsの設定の「オプション機能」から追加するよう、LinuxではOpenSSH クライアントをインストールしてから試すよう案内する。ioriは昇格して追加しない。
- 接続先を選ぶとOS・CPU・user・ホームを確認する。Linux x64とWindows x64を対象にし、それ以外のOSやCPUはその事実を表示して導入へ進ませない。Windowsの接続先の既定のシェルはcmdとPowerShellのどちらもありうるので、確認と導入はWindows標準のPowerShellを絶対パスで呼び、命令をエンコードして渡し、シェルの書き方に左右されないようにする。
- Clientはパスワード・鍵・passphraseを保存しない。覚えるのは接続先の指定（候補の名前、または手で指定した内容）だけである。passphrase等の入力と、初めての接続先のhost鍵の確認は、OpenSSHの確認をそのまま表示してユーザーに判断させ、iori側で自動承認しない。
- 接続先の選択から招待の発行までSSHの接続は1本を保つ。取消はSSHが実際に終了するまで待つ。
- 配布物は接続先のマシンが取得する。Client自身と同じバージョンの署名済みRelease情報をClientが確かめ、そこにあるSHA-256で接続先の取得物を展開前に確かめる。導入にはClient同梱の導入スクリプトを使い、接続先にcurlがあればcurl、無ければwgetで取得する。どちらも無い時は必要な道具を表示して止め、自動では追加しない。どちらのマシンが取得しているかと段階を表示し、段階の経過時間だけで失敗にしない。取消と接続・取得処理の実際の終了を区別する。
- Linuxでは本人の権限でlingerの有効化を試す。有効化が失敗した時だけ設定を照会し、無効なら導入を続け、完了の時に結果の画面で、ログアウトするとHostが止まることと、管理者権限で実行するコマンドを表示する（「ログアウト後も動かすには、管理者権限で次のコマンドを実行してください。」。右下の知らせには載せない）。設定の照会に失敗したことや、照会結果の形式が分からないことだけでは、有効化の失敗を表示しない。
- 導入後、Clientから導入したHostへioriの接続（Direct）で実際に接続することを確かめてから完了とする。SSHでは接続するがioriの接続先へ届かない場合は、導入は済んだがこのデバイスから接続できないことと、接続先との間の受信の許可を確かめて再試行するよう表示する。SSHをioriの普段の通信路にはしない。
- Windowsの接続先には、[このPCへの導入（Windows）](#このpcにiori-hostを導入するwindows)と同じく、本人のユーザーでログオンした時に画面にwindowを出さずに起動するように入れる。パスワードと管理者は求めない。SSHのセッションから起動したプロセスはSSHの終了とともに止まるため（[Win32-OpenSSH #2452](https://github.com/PowerShell/Win32-OpenSSH/issues/2452)）、導入の時にそのユーザーがその PC にサインインしていれば、Windowsのタスク スケジューラーに渡してそのサインインの中で起動する。Hostは、ロック中・リモート デスクトップの切断中・ユーザーの切り替え中も動き続け、サインアウトと再起動で止まり、次のサインインで起動する。導入の時にサインインしていなければ、導入を終えて、そのユーザーがサインインするとHostが起動することと、起動した後に同じ接続先を選ぶと登録できることを表示する。ログオンしていない時にも動かす形（S4Uのタスク・サービス）は、管理者とユーザーの鍵・CLIの認証の扱いが要るため採らない。
- Windowsの接続先には、SSHのユーザーがその PC の管理者（昇格した権限で動いている）時だけ入れる。接続先の確認の時に調べ、管理者でなければ導入へ進ませず、その PC で iori Host を入れ（「このPC」の導入か導入のコマンド）、招待でこのデバイスを登録するよう案内する。コマンドでの導入はファイアウォールの許可を加えないため、案内は「この PC」の導入にし（その PC で管理者のパスワードが1回求められること、その後その PC の iori Clientの「デバイス」→「新しいデバイスを招待する」で表示した招待をこのデバイスの「招待で接続する」で読み取ることまで表示する）、「インストールする」の代わりに「招待で接続する」を置く。Windows の Host はデスクトップを持つ PC が多く、その PC で入れればファイアウォールの許可も UAC の確認1回で済むため、管理者でない時に SSH の先で許可を足す仕組みは持たない（Netdata の Windows の導入と同じく、管理者を前提にする）。
- 管理者の接続先では、選択を置かずに必ず[同じ規則](#ほかのデバイスからの接続を許可するwindows)を確認を出さずに加え、導入の途中で加えることを導入の前に一行で表示する。SSHで導入する時は操作しているデバイスそのものが「ほかのデバイス」なので、許可しない選択を置くと導入した本人が接続できなくなる。SSHの先にはUACの確認を出せない。加えられなかった時は、導入後のDirectでの接続の確認が通らない失敗として表示する。
- 導入の時にサインインしていなかったHostに、サインインの後に同じ画面の「このiori Hostに登録する」で登録する時は、Hostが既に動いていれば起動し直さずに登録する。
- 接続先に既にiori Hostがある時は導入せず登録する。実行ファイルがあり、Linuxではuser serviceが有効、Windowsではログオン時の起動が登録されている場合を導入済みとし、途中で取り消された半端な状態は導入し直せる。応答が無く名前・バージョンを取れない場合や、user・ホームを読み取れない場合も登録へ進める。応答の無いHostでは登録の前に、導入と同じlingerの手順とuser serviceの起動を試す。
- 新規・既存とも、Hostの実行userの権限で一度限りの招待を発行させ、その招待で登録する。SSHでの接続だけを登録の根拠にはしない。古いHostで登録できない時は、そのことと更新先のバージョン、[Hostの更新](host-update.md)と同じく止まるCLIとTerminal、「iori Hostを更新して登録する」を表示する。押すと同じSSHの接続で同梱の導入スクリプトを実行して更新し、続けて登録する。押されるまで更新しない。更新と登録の途中で画面を閉じても続け、閉じた後に失敗した時は右下の知らせ「〈接続先〉のiori Hostを更新できなかったため、このデバイスを登録できませんでした。」と「詳細」を出し、「詳細」で失敗の画面を開き直す。

## 導入したデバイスの登録

導入に成功したClientは、そのHostの最初の登録デバイスになる。Clientは、Hostの実行userの権限で一度限りの招待を発行させ（このPCとSSHのどちらも、本人限定の手元接続を使う）、その招待で登録する。ユーザーに招待の受け渡しは求めない。以降のデバイスは、このデバイスから招待（QR）で追加する。

登録の保存、招待の拒否、接続、登録後の一覧取得の失敗は、実際の原因と再試行で行うことを同じ導入画面で表示する。

## 更新

ClientからのHostの更新は[ClientからのHostの更新](host-update.md)に従う。導入スクリプト（`install.sh`・`install.ps1`）での手作業の更新は、導入と同じ手順で行う。Terminalを持つ係を続けられる更新は、[Hostの再起動・更新をまたいでTerminalを続ける](terminal-daemon.md)に従い、Terminalとエージェントを止めない。

## 撤去

Desktop Clientの設定のHost → バージョンから、選んだHostをアンインストールできる。確認画面とMobileの案内は[設定](settings.md#hostのアンインストール)に従う。どの導入経路でも、登録済みデバイスから通常のioriの接続でHostへ依頼する。

止まる前に、ioriがCLIの設定へ足したhooksだけを削除し、自動起動の登録を解除する。この段で失敗したら削除した設定を戻し、通常の作業を続けられる状態へ戻す。戻せなかった自動起動の登録は、Hostのマシンを再起動した後にHostが自動で起動しないこととして失敗の結果に表示する。CLIの設定のhooksは、次にCLIをioriから起動した時に足し直されるので表示しない。その後、Terminalとエージェントを止めて画面を保存する。Hostが停止する前に撤去に失敗した場合も設定を戻し、停止済みのTerminal係とチームを起動し直す。起動し直せなかった項目は失敗の結果に表示する。各段の結果は更新と同じ操作の記録・照会で返す。Host本体の外で動く短い処理が停止を確かめ、プログラムを削除する。Windowsのログオン時の起動とPATHのioriの項目、Linuxのuser unitとコマンドへのリンク、Terminalを持つ係とその実行資材も削除する。Windowsのファイアウォールの規則とLinuxのlingerは残す。撤去で管理者の確認は出さない。

「iori Hostの保存データも削除する」を選んだ時だけ、デバイスの登録・Hostの識別情報・ioriの作業記録・Terminalの履歴・Forgejo・Giteaのトークン（[連携](forge.md#連携の設定)）を削除する。更新時の控えの保存データも対象にする。トークンのうち資格情報マネージャー（Windows）・キーリング（Linux）に置いたものは、Hostが止まる前に削除する。削除できなかったサイトは撤去を止めずに、完了の時に結果の画面で表示する（右下の知らせには載せない）。選ばない時は保存データと控えのDBを残す。開発ファイルとCLI本体の会話・設定・認証は削除しない。

Host停止後のプログラム・保存データの削除に失敗した時は、削除できなかったフォルダーの場所（停止できなかったprocessがある場合は名前とPIDも）を表示する。場所はコピーできる形で表示し、PCを再起動してからそのフォルダーを削除するよう表示する。入れ直しと、一覧から削除する操作は案内しない（Hostは止まっており、一覧からは外れている）。Clientから撤去を再試行する案内は出さない。

停止後の結果の受け取り方は次のとおり。

- このPCのHost: Clientが設定画面を閉じていても、結果が出るまで間隔を空けて再読み込みする。
- SSHで導入したHost: アンインストールを始める前に、保存したSSH接続先へ接続する（OpenSSHの鍵の確認と認証は導入時と同じ扱い）。その接続を保ったまま、停止後の結果が出るまで読み続けて表示する。設定画面を閉じても続ける。SSHの接続が切れて結果を読み込めない時は、そのことと再試行を表示する。始める前にSSHで接続できない時や認証に失敗した時は、SSHを使わずに招待だけで登録したHostと同じ経路で進める選択を置く（停止後の削除が済んだかは表示しない）。
- 招待だけで登録した別のPCのHost: 止まる前の段が済み、ファイルの削除へ進む応答を受けたら、「アンインストールを開始しました」と表示する。完了とは表示しない。止まる前に失敗した段は理由とともに表示する。

結果がまだ読み込めないことを失敗にしない。撤去を自動で再送しない。結果の保存と回収は[技術設計](../architecture.md#配布と更新)に従う。保存後に結果票の削除だけが失敗した時は、その事実を知らせ、保存済みの結果と一覧の扱いは変えない。

Hostが停止した後は、成功した時、ファイルの一部が残った時、招待だけで登録したHostで停止後の削除へ進んだ時のどれも、操作したClientの一覧から削除する。Client側の下書き等は削除しない。

設定の「接続」からは撤去の結果に関わらず確認して一覧から削除できる（[接続](connection.md)）。

他のデバイスは通常の切断として扱い、全デバイスへの撤去結果の同期は行わない。入れ直しは既存の「iori Hostをセットアップする」から行う。保存データを残したHostは、入れ直すと同じHost鍵で登録し直される。
