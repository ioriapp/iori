# iori 製品仕様

ioriは、作業先のiori Hostへ手元のiori Clientから接続し、Agentとの会話を中心に開発を続ける製品である。Filesでファイルを読み、Gitで変更を確かめ、Terminalでコマンドを実行する。
技術上の責任は[技術設計](architecture.md)が持つ。

## 製品の目的と対象

同じマシンでも別のマシンでも、ユーザーが開発内容を理解して続けられる。一人がPCとMobileを行き来する使い方を対象とし、ユーザー同士の共同操作は提供しない。

ClientはWindows、Linux、macOS、Android、iOS、iPadOSのnativeアプリ、HostはWindows、Linux、macOSを対象とする。共通UIと共通処理を使い、ブラウザー配信のWebアプリやPWAは提供しない。初期ClientはWindows・Linux・Android、初期HostはWindowsとLinux。初期の5種で問題なく使えるところまで進め、公開前に他のOSを足すかは、その時に決める。AgentはClaude Code・Codex・Pi・OpenCode・Cursor CLI・Antigravity CLIを扱い、他のCLIもHostに入っていれば起動でき、値で書いた定義ファイルで足せる。どのCLIもCLI自身の画面（PTY）で使え、チームを含むioriの主な機能を使える。出せないのは、CLIが外へ出さない値（トークン数の集計など）だけである。接続はLAN / VPN経由で、届かない時はユーザーが用意したRelayを通せる。複数Hostを同時に使える。

既存CLIの認証・契約・設定・Skill・hooks・MCP・sandboxを尊重する。iori専用のCLI環境への移行や、使わないCLIの導入を求めない。CLIが持つモデル・許可モード・ツール・コマンドは、その名前と意味で扱う。

## 製品の判断基準

初めて開いたユーザーが、対象を選び、Agentへ依頼し、結果を読んで次の入力へ進める。iori独自の用語や操作体系を覚えさせない。画面・文書では「ユーザー」に統一し、CLI・OS・Gitの用語は実名を使う。

CLIの機能を二重に持たないため、iori独自の会話の画面は作らず、CLI自身の画面を使う。

Agentとの会話を中心に置く。子Agentも同じ基準で読め、Files・Git・Terminalは会話を助ける。内部ID、生データ、転送単位、実装の都合を画面へ出さない。接続先の能力を一律に削らず、値がある情報を表示する。

一つの機能の不足や一方のHostの切断で、他の利用可能な機能・Hostを止めない。保存しているものの所在と量はユーザーが確認・整理できる。

製品仕様と個別設計が操作の正本である。Prototypeと見本は参考であり、架空の値や初期配置を製品の約束にしない。

## 表示と失敗の案内

値がない、取得できない、まだ確かめていない項目は、その項目ごと表示しない。「未取得」「未確認」「不明」「—」などの代わりの文字で埋めない。確認に時間がかかる時や状態が分からない時も、警告・注記・帯・色・確認画面を出さず、後から応答や証拠が届いたら成功として扱う。

警告・エラーは、失敗が確定し、ユーザーが再送、読み直し、設定変更、再導入などの回復操作をできる時だけ出す。対象のそば一か所に、起きたことと回復操作を表示する。原因が分からない失敗でも、回復操作がある場合は案内できる。ユーザーが何もできない内部事情、接続先の内部制約、確認方法、試験で確かめた条件は表示しない。

## 初回利用とデバイス追加

PCでHostを導入すると、そのPCが最初の登録デバイスになる。別のデバイスは期限付き・一回限りの招待をQRまたは文字列で受け取り、接続先を確認して「登録する」。招待を出した画面で追加されたデバイスを確かめ、取り消せる。

導入・更新・撤去を変える時は[Hostの導入と更新](design/host-install-update.md)、導入画面を変える時は[iori Hostを用意する画面](design/host-setup-screen.md)を読む。
Clientの更新確認・取得・入替を変える時は[Clientの自己更新](design/client-update.md)を読む。ClientからのHostの更新を変える時は[ClientからのHostの更新](design/host-update.md)を読む。
招待・複数Host・接続状態・通知を変える時は[接続](design/connection.md)、切断時の表示や復帰を変える時は[Hostとの接続が切れた時の表示](design/host-recovery.md)を読む。

## 対象と画面

ユーザーはHostのフォルダーをパスの入力で探して開ける。Gitリポジトリはworktreeを使い、Gitでないフォルダーもそのまま扱える。Hostの許可フォルダーは持たず、Agentが触れる範囲はCLI自身の許可に任せる。

サイドバーから親のworktreeを選ぶと、親と子のAgent、ボード、Files、Git、Terminalを一画面で扱える。同じworktreeの複数Agentもタブで見比べられる。
画面構造・配置・最大化・Mobileの移動を変える時は[画面の構成と移動](design/workspace-layout.md)、worktreeの作成・削除を変える時は[worktreeとフォルダー](design/worktrees.md)を読む。

ファイルの一覧・表示・参照を変える時は[Files View](design/files-view.md)、差分・履歴とサイドバーのPR・CIの印を変える時は[Git View](design/git-view.md)、ForgeのCI・Issueを読み込む画面、Hostの設定の「連携」、Issueから始める操作、Agent向けのForgeを読み込むコマンドを変える時は[Forgeとの連携](design/forge.md)、シェル・入力・終了を変える時は[Terminal](design/terminal.md)、スマホでの入力欄・キーの帯・画像・選択・文字の大きさを変える時は[スマホでのTerminalとCLIの画面](design/mobile-terminal.md)を読む。Filesはファイルの中身を編集せず（ファイルのアップロード・ダウンロードだけはできる）、Gitの書き込み操作は作らない。

CLIの一覧・追加・同時実行の上限と、チームの入口を変える時は[AI Agents/Teams](design/agents-and-teams.md)、正式対応でないCLIを定義ファイルで足す仕組みを変える時は[CLIの定義ファイル](design/cli-definitions.md)を読む。

部品を選ぶ時は[UIの定義](design/ui.md)、配色・書体・文字の段・状態の印・動き・画面の言葉を変える時は[画面の見た目と言葉](design/visual-style.md)、画面の文の語を選ぶ時は[画面の文の語と言い回し](design/wording.md)、設定項目を変える時は[設定](design/settings.md)、重ね表示を変える時は[ダイアログとポップアップ](design/dialogs.md)を読む。

## Agentとチーム

CLI自身の画面で依頼を送り、応答を読む。起動・状態・再開・参照の入力を変える時は[CLIの画面](design/cli-screen.md)を読む。

会話にチームを付けると、親Agentが子Agentへ委譲し、ユーザーは各子の会話と変更を確かめられる。チームは回し方の事前定義で、複数のプロジェクトで使い回し、記録を後から見返して改善できる。チームの項目・子の割り当て・同時実行の上限・親の判定と記録を変える時は[チーム](design/teams.md)、委譲・停止・親への知らせ・子の表示を変える時は[Linked Agent](design/linked-agents.md)、会話の状況を一目で知るタブを変える時は[Board](design/board.md)、委譲の記録を見返す画面を変える時は[Records](design/records.md)、チームの選択・編集・保存を変える時は[チームの編集画面](design/team-editor.md)を読む。

添付の操作・保存を変える時は[添付](design/attachments.md)、Pi固有の会話や準備を変える時は[Pi](design/pi.md)を読む。

## 保持とデバイス間の引き継ぎ

同じデバイスでは同じAgentの会話・Terminalを一箇所に開く。別の入口から開いた時は既存の表示へ戻る。対象はHostを含めて識別し、同じ名前・パスから同一性を推測しない。

別デバイスで送信・入力・停止すると操作権がそのデバイスへ移る。閲覧だけでは移さず、引き継ぐためだけの操作を求めない。元デバイスの遅れた操作で新しい作業を巻き戻さない。デバイスを替えただけでAgent・Terminalを作り直さない。

下書き、読み位置、配置はデバイスと入力先ごとに保つ。切替、再起動、切断で削除せず、保存できない時は再試行またはコピーで回収できる。表示を閉じる操作、応答を止める操作、Terminalを閉じる操作、worktree削除は区別する。

## 判断、失敗、復帰

Attentionは全Hostを横断して、ユーザーが回答できる質問と権限承認だけを集める。子の作業上の質問は親へ、子のCLIの権限承認はユーザーへ届ける。完了・失敗は、その会話や画面で表示し、見ていない画面の完了はOSの通知でも知らせる（設定で切れる）。判断待ちの通知と、待ちが続く間の通知の扱いは[接続](design/connection.md)に従う。値がない項目や未確定の状態の扱いは[表示と失敗の案内](#表示と失敗の案内)に従う。

送った内容はすぐ表示し、CLIの応答や確定した失敗をその操作に表示する。結果不明の作用を自動で再実行しない。ユーザーの操作なしに送信・作業開始・中断・削除・再起動を起こすのは、採用仕様で定めた契機に限る。ユーザーの明示操作は、失われるもの・中断されるものを表示して選べるようにする。信頼済みデバイスは操作権を移さず判断要求へ回答でき、古い要求や未知の選択肢を許可へ変換しない。二重実行・対象の取り違え・データ消失を防ぐ操作以外は、閲覧・入力を止めない。

切断中も最後の本文・結果・入力を保ち、戻ったら同じ対象へ追いつく。Host再起動で中断した応答は中断として閉じ、同じ会話を続けられる。再起動の操作を変える時は[Hostの再起動](design/host-restart.md)、再起動・更新をまたいでTerminalを続ける仕組みを変える時は[Hostの再起動・更新をまたいでTerminalを続ける](design/terminal-daemon.md)、Clientの起動・初期化を変える時は[Clientの起動と保存データ](design/client-startup.md)を読む。

## 受入契約

| ID    | ユーザーができること                                                               |
| ----- | ---------------------------------------------------------------------------------- |
| AC-01 | 通常の導入・招待から接続先とフォルダーを確認し、最初の実Agentへ依頼する            |
| AC-02 | 複数Host、Gitの有無、リポジトリとworktreeを取り違えず対象を開く                    |
| AC-03 | 既存・新しい会話で入力、ツール、結果、失敗、停止、次の入力まで続ける               |
| AC-04 | 親のworktreeの木をタブ・分割で管理し、Agent・Files・Git・Terminalを往復する        |
| AC-05 | 実PTYへの入力、サイズ変更、非表示、切断、デバイス引き継ぎでも同じTerminalを使う    |
| AC-06 | 別Hostや子の権限承認をAttentionから開き、一度だけ回答する                          |
| AC-07 | DesktopとMobileを行き来して、確認・判断・操作を続ける                              |
| AC-08 | 下書き・入力先・読み位置・配置を切替・再起動・切断から守る                         |
| AC-09 | Client・Host・CLIの切断を区別し、二重送信なく現在状態へ戻る                        |
| AC-10 | 更新・バックアップ・復元・デバイス失効・撤去で失うものを理解し、開発ファイルを守る |
| AC-11 | 同じ会話・Terminalへの複数入口から既存の表示と下書きへ戻る                         |
| AC-12 | worktreeを作成・利用・削除し、別の対象の変更・会話を混ぜない                       |
| AC-13 | 子の内容・状態・変更を確認し、表示を閉じた後も結果と実行を保つ                     |
| AC-14 | 独自用語を覚えず、接続先と対象を選んで最初の会話へ進む                             |

受入は実際の操作と結果で確認する。Releaseの検査・公開を変える時は[Releaseと公開](design/release.md)を読む。静的検査や文書への記載を、操作結果の確認として扱わない。

## 対象外と未決

ユーザー同士の共同操作、Web/PWA、Filesの編集、Gitの書き込み操作は対象外。動いているCLIプロセスの引き渡し、Files/Gitの永続offline cache、自由なcwd変更の画面は未定。ライセンスと配布の経路は[Releaseと公開](design/release.md#公開の準備)が持つ。
LAN・VPNで届かない時の中継を変える時は[Relay](design/relay.md)、保存した指示を時刻・Webhook・Issueのラベルを契機にAgentへ渡す機能を変える時は[Automations](design/automations.md)を読む。
